LQ-Nets: Learned Low-Bit Quantization

Paper: LQ-Nets: Learned Quantization for Highly Accurate and Compact Deep Neural Networks

LQ-Nets is useful because it asks a basic question: why should the quantization levels be fixed before training? Uniform quantization is easy to implement, but the distribution of weights and activations may not be uniform. LQ-Nets learns the quantizer itself.

Motivation

Binary and ternary networks save a lot of memory, but their codebooks are extremely restrictive. Uniform multi-bit quantization is more expressive, but it still assumes that equally spaced values are a good fit. LQ-Nets keeps the low-bit representation but learns the basis values used to reconstruct quantized tensors.

The figure shows that activation and weight distributions are not always well matched by a naive uniform grid. The learned basis gives the quantized model more freedom at the same bit-width.

The optimization alternates between two coupled tasks:

  1. update the network weights under quantized forward propagation;
  2. update the quantization basis so the low-bit representation better matches the learned tensor distributions.

This is more flexible than LSQ-style step-size learning because the codebook is not forced to be a scaled uniform grid. The cost is deployment complexity: arbitrary learned levels are less friendly to standard integer GEMM kernels.

Results

The paper reports low-bit CNN results on CIFAR and ImageNet. Learned quantization improves over fixed binary/ternary and uniform quantization baselines, especially when bit-width is very small. The benefit comes from using the same number of bits more effectively rather than increasing model capacity.

Takeaway

LQ-Nets is a learned-codebook baseline. It is not the most hardware-friendly endpoint, but it explains why quantization levels matter. Later papers make different tradeoffs:

  • LSQ learns only the step size, keeping a uniform grid.
  • SqueezeLLM uses non-uniform quantization for LLM weights, but with serving cost in mind.
  • NF4 in QLoRA chooses a data type matched to normally distributed pretrained weights.

The common idea is that the quantizer is part of the model design space.

Learned Codebook Versus Learned Scale

LQ-Nets learns more than LSQ. LSQ keeps the levels uniformly spaced and learns the spacing. LQ-Nets learns basis values, so the spacing itself can become non-uniform.

This gives better accuracy at very low bit-width, but it changes the hardware story. A uniform quantizer can often be implemented as integer multiply-accumulate plus scale. A learned codebook may require lookup/decode logic or specialized kernels. That is why learned-codebook papers often look strong in accuracy tables but need a separate deployment analysis.

A useful comparison:

Method Learned quantity Hardware friendliness
PACT activation clipping threshold high
LSQ uniform step size high
LQ-Nets quantization basis/codebook lower, unless kernel supports it

What The Paper Contributes

The paper’s real contribution is showing that the quantizer has trainable capacity. Once the model is forced into 2-bit or 3-bit weights/activations, the choice of levels can matter as much as the choice of architecture. This idea later reappears in NF4 and SqueezeLLM, where the quantization levels are chosen to fit actual weight distributions rather than a generic uniform grid.

Source-Level Notes

LQ-Nets learns the quantization levels instead of fixing them to uniform bins. A quantized value is represented by a small number of binary bases:

The basis vector determines the actual quantization levels. Given assignments, the basis can be solved by least squares; given the basis, the assignments are updated by projection. This alternating structure is the main difference from LSQ, where the quantization grid stays uniform and only the step size is learned.

What The Learned Codebook Buys

Uniform quantization is hardware friendly, but it assumes values are evenly worth representing across the range. Learned quantization can put levels where the layer actually needs them. That helps especially at very low bit widths, where every level matters.

The cost is implementation complexity. A learned non-uniform codebook is not the same as a plain integer GEMM path. If the target is a real accelerator, the codebook must either be converted into an efficient lookup/decode path or restricted enough to map to hardware. This is why LSQ-style learned scale became more widely used in QAT baselines, while LQ-Nets remains useful as a conceptual learned-quantizer reference.

Experiment Reading

The result tables should be read with the hardware question in mind. Learned quantization levels can recover accuracy at 1-2 bits, but they create a less regular numeric format. If the final kernel must decode arbitrary codebook entries before multiplication, the practical speedup may be smaller than the bit width suggests.

The paper is strongest as evidence that quantization levels are model parameters. This contrasts with post-training min/max calibration, where the grid is determined by tensor statistics. In LQ-Nets, the grid itself is optimized for the task.

A reproduction should compare three variants: fixed uniform levels, learned scale with uniform levels, and learned non-uniform levels. That isolates whether the gain comes from learning the range or from learning the shape of the codebook.

RPTQ: Reorder-Based LLM Quantization

Paper: RPTQ: Reorder-Based Post-Training Quantization for Large Language Models

RPTQ is another activation-outlier paper, but it uses a different lever from SmoothQuant. Instead of scaling channels, it reorders them so quantization groups are easier to represent.

Motivation

Group-wise quantization is a compromise: it avoids one scale for the whole tensor but does not require one scale per element. The problem is that if outlier channels are spread across many groups, each group has a large range and poor resolution.

The figure shows how channel reordering changes the grouping structure seen by the quantizer.

Methodology

RPTQ constructs channel permutations that place similar activation channels together. If a permutation can be folded into adjacent linear layers, the model function remains equivalent while the quantizer sees better grouped distributions.

The method is particularly relevant for activations after LayerNorm and other locations where persistent outlier channels appear.

Results

RPTQ reports LLM PTQ results showing better activation quantization than naive grouping. It is not as widely adopted as SmoothQuant or GPTQ, but it is a useful design point: data layout itself can be a quantization parameter.

Takeaway

The main lesson is that group boundaries matter. Once the runtime quantizes by group, channel order affects accuracy even if the mathematical model is unchanged. QuaRot later generalizes this idea: instead of only reordering coordinates, rotate the basis to spread outliers more evenly.

Reordering Is A Layout Transformation

RPTQ is easy to underestimate because channel reordering sounds trivial. But if quantization is group-wise, the grouping layout changes the scale statistics. Moving outlier channels together can prevent them from polluting every group.

The transformation is useful only if it can be folded into adjacent layers or supported cheaply by the runtime. Otherwise the model may save quantization error but pay layout-conversion overhead.

Relation To QuaRot

RPTQ permutes coordinates. QuaRot applies an orthogonal rotation. Both are equivalent transformations before quantization, but rotation has more freedom to spread outlier energy. RPTQ is cheaper; QuaRot is stronger.

Source-Level Notes

RPTQ attacks activation outliers through channel reordering. If outlier channels are scattered, a group-wise quantizer has to use a large scale for many ordinary channels. If channels are reordered so similar ranges fall into the same group, group quantization wastes less resolution.

The challenge is not the algebra; it is carrying compatible permutations through Transformer blocks without breaking residual paths and normalization assumptions.

Reading Detail

RPTQ is useful because it treats layout as part of quantization. Quantization quality is not only about choosing bit width and scale. It can also depend on which channels share a scale group.

QuaRot later takes a more continuous version of this idea: instead of permuting channels, rotate them with an orthogonal transform to spread outliers. RPTQ is therefore a good bridge between SmoothQuant-style scaling and QuaRot-style rotations.

Experiment Reading

The key experiment is whether reordering improves group quantization at the same group size. If group size is one, reordering is irrelevant. If group size is large, reordering can decide whether ordinary channels share a scale with outliers.

I would also check the cost of carrying permutations through the model. A permutation that introduces runtime shuffles can erase benefits. The strongest form is one where permutations are fused into adjacent weights or handled as a static layout transform.

RPTQ is therefore a layout-aware quantization method. It does not invent a new numeric type; it makes an existing group quantizer see friendlier groups.

Reproduction Checklist

For a small reproduction I would start with one Transformer block and record activation ranges before and after reordering. The expected result is that channels inside each quantization group have more similar magnitudes after permutation. Then I would fold the permutation into adjacent linear weights and verify that the floating-point output is unchanged before quantization. That check separates algebraic correctness from quantization benefit.

The final benchmark should report whether any runtime transpose or gather remains. RPTQ is attractive only if reordering becomes a static layout choice. If every token pays a dynamic shuffle cost, the method can lose the simplicity that made it appealing.

Boundary / Failure Mode

The limitation is that permutations are discrete and preserve only reordered axes. If outliers are not just misplaced but genuinely concentrated in a few semantic dimensions, reordering can only group them; it cannot reduce their magnitude. That is where SmoothQuant-style scaling or QuaRot-style rotation becomes stronger. RPTQ is best when group-wise quantization is already required and layout can be changed almost for free.

Paper: RPTQ: Reorder-based Post-training Quantization for Large Language Models
Code: hahnyuan/RPTQ4LLM

RPTQ is a layout-aware post-training quantization paper. Its main claim is more specific than “LLM activations have outliers.” The paper argues that activation quantization fails because different channels have very different value ranges. Some channels have large outliers, but even channels without extreme outliers can occupy incompatible intervals. If those channels are forced to share one quantization scale, the smaller or shifted ranges lose precision.

The method is simple in spirit:

  1. Run calibration data through the model.
  2. Record each activation channel’s minimum and maximum.
  3. Cluster channels whose ranges look similar.
  4. Reorder channels so each quantization group contains similar channels.
  5. Quantize each cluster with its own scale and zero point.
  6. Fold the reorder into layer norm writes and linear weights so inference does not pay an explicit shuffle.

That makes RPTQ a useful bridge between SmoothQuant and later rotation-based methods such as QuaRot. SmoothQuant rescales coordinates. RPTQ permutes coordinates. QuaRot rotates coordinates. All three try to make the tensors seen by low-bit quantizers less hostile.

The Activation Problem

The first figure is the motivation. Each dot is one activation channel, plotted as (channel maximum, channel minimum) on calibration data.

Figure 1 from the paper. Different OPT activation channels occupy very different min/max ranges across layers and projection sites.

Two things show up in this plot:

  • Some channels are outliers with much larger maxima or minima.
  • Many channels have different ranges even when they are not isolated outliers.

The second point is the one RPTQ focuses on. Suppose two channels are both important, but one lives mostly in [-100, -50] and another in [80, 100]. A single asymmetric quantizer covering [-100, 100] wastes resolution for both channels. If the quantizer has only 4 bits, this waste is not a small rounding issue.

This matters because activation quantization is the hard part for LLM PTQ. By the time this paper appeared, weight-only 4-bit methods such as GPTQ were already usable. Turning activations and KV cache into low-bit tensors is harder because runtime tensors vary with data and sequence state.

Where RPTQ Sits

The paper compares four ways to handle activation quantization difficulty.

Figure 2 from the paper. LLM.int8() isolates outliers, SmoothQuant rescales channels, VSQ uses local vector scales, and RPTQ clusters and reorders channels before grouped quantization.

The differences are useful:

  • LLM.int8() keeps outlier features in high precision. This protects accuracy, but it adds a side path.
  • SmoothQuant moves activation difficulty into weights through equivalent per-channel scaling. It can make activation INT8 practical, but the paper argues that scaling alone does not fully solve range differences at lower bit widths.
  • VSQ gives nearby values their own quantization parameters, but that can increase parameter storage and runtime overhead.
  • RPTQ changes which channels share a quantization group. It tries to get most of the benefit of finer granularity without per-channel or per-vector overhead.

The key observation is that group-wise quantization is not permutation-invariant. If a group shares a scale, channel order decides which ranges are forced to share that scale. Reordering is therefore a quantization parameter.

Then it runs K-means over those points. Channels in the same cluster are placed next to each other in memory order, and each cluster gets its own asymmetric quantization parameters.

This is a small algorithmic step but an important systems detail:

  • If g = 1, RPTQ becomes ordinary shared-scale quantization.
  • If g = C, each channel can get its own scale, but metadata and kernels become expensive.
  • With a small number of clusters, RPTQ tries to keep quantization groups homogeneous while keeping overhead moderate.

The paper uses 32 clusters for R1, R4, and R5, and 4 clusters for R2 and R3 in the main experiments. R2 and R3 are per-head self-attention reorder indices, so their overhead grows with head count.

Avoiding Runtime Shuffle

A naive implementation would physically reorder activation channels at runtime. That would add memory movement, temporary buffers, and latency. RPTQ tries to avoid that.

The full transformer-layer flow is shown below.

Figure 3 from the paper. Reorder indices R1 to R5 are inserted around layer norm, attention projections, attention matmul, output projection, and FFN projections.

The paper uses two main tricks.

First, it fuses reordering into layer norm. Layer norm already writes its output back to memory. RPTQ changes the write address according to the reorder index, so the activation is produced in reordered layout without a separate shuffle kernel.

If both sides are permuted consistently, the full-precision function is unchanged. In practice, RPTQ rearranges columns according to the input activation order and rows according to the output activation order. The weight reorder can be done before deployment.

Alignment Constraints

The hard part is not the single linear layer. It is keeping the whole transformer block consistent.

RPTQ has to handle several alignment constraints:

  • Residual additions require matching channel order. The paper therefore avoids reordering the output of the attention output projection and final FFN output in ways that would break residual paths.
  • Query and key channels meet in QK^T. They must use compatible reorder indices, otherwise attention scores become wrong.
  • The paper computes R2 and R3 for each self-attention head, and for query/key it clusters a combined point containing both Q and K min/max statistics.
  • LayerNorm output can be reordered because the following weights are adjusted to accept that order.

This is why the method is more than a sorting heuristic. It is a static layout transformation that must be propagated through the transformer graph.

Experiment Setup

The experiments focus on OPT models from 1.3B to 175B. Since RPTQ focuses on activations, the paper combines it with GPTQ for weight quantization.

The setup details:

  • weights and input activations use static quantization;
  • activation clusters use asymmetric min-max quantization;
  • layer norm output and softmax output are quantized to 8-bit precision;
  • calibration uses 256 samples randomly selected from WikiText2, Penn Treebank, and C4;
  • metrics include perplexity, zero-shot accuracy, memory consumption, and cluster-number ablations;
  • experiments run on a server with 8 NVIDIA A6000 GPUs.

The naming convention is important:

  • W4A16: 4-bit weights, 16-bit activations.
  • W4A8: 4-bit weights, 8-bit activations.
  • W4A4: 4-bit weights, 4-bit activations.
  • W4A4KV: 4-bit weights and 4-bit KV cache, with ordinary activations less aggressively quantized.
  • W3A3KV: 3-bit weights and 3-bit KV cache.

The KV variants exist because KV cache becomes a dominant memory cost at long sequence length and large batch size.

Perplexity Results

Table 1 is the main accuracy table for perplexity on WikiText2, Penn Treebank, and C4.

Table 1 from the paper. RPTQ is evaluated across OPT-1.3B to OPT-175B under W4A16, W4A8, W4A4, and KV-cache-focused settings.

The easiest way to read the table is to compare OPT-175B:

  • FP16: WIKI 8.34, PT 12.01, C4 10.13.
  • W4A16: WIKI 8.37, PT 12.31, C4 10.26.
  • W4A8: WIKI 8.43, PT 12.24, C4 10.49.
  • W4A4: WIKI 10.60, PT 15.59, C4 12.28.
  • W4A4KV: WIKI 8.40, PT 12.38, C4 10.54.
  • W3A3KV: WIKI 10.03, PT 13.82, C4 11.30.

Two lessons stand out.

First, full activation W4A4 is much harder than W4A8. The perplexity increase is still manageable on the largest model, but it is not free.

Second, KV-focused quantization is attractive. W4A4KV stays close to FP16 on OPT-175B while reducing memory pressure in the part of the model that grows with sequence length and batch size.

Zero-Shot Tasks

The zero-shot table checks whether perplexity trends transfer to downstream multiple-choice tasks.

Table 2 from the paper. The evaluated tasks are LAMBADA(OpenAI), PIQA, ARC(Easy), ARC(Challenge), OpenBookQA, and BoolQ.

The table is dense, but the pattern is consistent with Table 1:

  • W4A16 is usually close to FP16.
  • W4A8 loses some accuracy but remains usable.
  • W4A4 is more fragile, especially on smaller models and harder tasks.
  • KV-focused schemes preserve more quality than fully quantizing all activations to the same low bit width.

This is a useful distinction for deployment. If the memory bottleneck is KV cache, then pushing every activation to 4-bit may not be the best first move. A KV-focused design can buy a lot of memory reduction with less quality loss.

Memory Results

The memory table is the practical reason activation and KV quantization matter.

Table 3 from the paper. Memory consumption is reported for OPT-30B, OPT-66B, and OPT-175B across batch sizes and sequence lengths.

The headline result from the paper:

  • W4A8 reduces memory by about 63%.
  • W4A4 reduces memory by about 75%.
  • W4A4KV reduces memory by about 73%.
  • W3A3KV reduces memory by about 80%.

For OPT-175B at batch size 64 and sequence length 8192:

  • W16A16: 2750.1GB.
  • W4A16: 2505.6GB.
  • W4A8: 1311.6GB.
  • W4A4: 714.6GB.
  • W4A4KV: 759.6GB.
  • W3A3KV: 593.7GB.

The W4A16 number is a good sanity check. Weight-only quantization helps, but in this long-context large-batch setting it does not solve the problem because activations and KV cache dominate.

The appendix breaks this down by memory component.

Table 6 from the appendix. As batch size and sequence length grow, KV cache and dynamic activation memory become much larger fractions of total memory.

This table explains why activation quantization is worth the trouble. At small batch and short sequence, weights dominate. At large batch and long sequence, the KV cache and runtime tensors can become the main memory problem.

Cluster Count Ablation

RPTQ has a knob: the number of clusters. More clusters mean channels share scales with more similar channels, but also increase bookkeeping and possibly kernel complexity.

Figure 4 from the paper. Perplexity generally improves as the number of clusters increases, but the curves differ across reorder locations.

The paper reports that:

  • increasing clusters generally decreases perplexity;
  • R2 has fluctuations, which the authors suspect may come from limited calibration data;
  • larger models are more sensitive to too few clusters;
  • using only one cluster can make larger networks fail badly;
  • the main experiments choose 32 clusters for R1/R4/R5 and 4 clusters for R2/R3.

The appendix adds a larger calibration comparison.

Figure 7 from the appendix. Calibration sample count changes the stability of the cluster-number ablation, especially for R2 and R3.

This makes sense: RPTQ depends on channel min/max statistics. If calibration data misses rare activation ranges, the clusters can be poorly placed.

Comparison With SmoothQuant And PEG

The paper also compares against SmoothQuant and PEG under low-bit settings.

Table 4 from the appendix. SmoothQuant degrades badly in several W4A4 cases, while RPTQ remains in a usable perplexity range.

The most dramatic entries are in W4A4 on larger OPT models. For OPT-30B, SmoothQuant has extremely large perplexity values on all three datasets, while RPTQ stays at WIKI 11.15, PT 14.11, and C4 13.48. That supports the paper’s claim that range differences are not fully solved by simple channel scaling.

Table 5 from the appendix. Under W4A4, RPTQ is generally better than PEG on the tested OPT models.

PEG is also a permutation-style idea, but the paper argues that its grouping is less suitable for LLM activation range patterns. The RPTQ advantage is strongest on OPT-30B in this table, where PEG has PT 34.94 and C4 45.43 while RPTQ has PT 14.11 and C4 13.48.

What RPTQ Is Good At

RPTQ is strongest when:

  • activation quantization is required, not only weight-only compression;
  • group-wise quantization is used, so channel order controls scale sharing;
  • the reorder can be folded into existing operations;
  • calibration data is representative enough to estimate channel ranges;
  • the deployment target benefits from lower activation or KV-cache memory.

It is less compelling if the runtime has to execute explicit gather/scatter operations for every token, or if the hardware cannot efficiently run the chosen low-bit integer format. The appendix notes that 3-bit values are not supported on most GPUs and may need to be cast to 4-bit or 8-bit datatypes.

Relation To Later Work

RPTQ permutes channels. QuaRot rotates channels. The conceptual connection is direct: both treat the coordinate basis as part of the quantization problem.

The difference is expressive power:

  • A permutation can only group existing coordinates differently.
  • A scaling transform can shift quantization difficulty between activations and weights.
  • A rotation can spread outlier energy across many coordinates.

RPTQ is cheaper and easier to reason about than rotations, but less flexible. That makes it a good intermediate point in the LLM quantization story. It shows that low-bit activation quantization is not only a numeric-type problem; it is also a data-layout problem.

Takeaway

RPTQ’s main lesson is that channel grouping matters. If a group-wise quantizer uses one scale for a set of channels, then the order of those channels can decide whether the group is easy or impossible to quantize.

The method is not just “sort channels.” It uses calibration statistics, clusters channels by min/max range, propagates compatible reorder indices through transformer layers, and folds the layout change into layer norm and linear weights. That combination lets RPTQ push OPT activation and KV-cache quantization into lower-bit regimes while keeping perplexity and zero-shot accuracy usable in the paper’s experiments.

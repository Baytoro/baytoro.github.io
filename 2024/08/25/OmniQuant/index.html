OmniQuant: Omnidirectionally Calibrated LLM Quantization

H.J. Chen
  2024-08-25 2024-08-25 Created  
  • Paper Reading 
 
  • Quantization 
  • | LLM 
  • | Inference 

Shao W, Chen M, Zhang Z, Xu P, Zhao L, Li Z, Zhang K, Gao P, Qiao Y, Luo P. OmniQuant: Omnidirectionally Calibrated Quantization for Large Language Models. ICLR 2024.

  • Paper: arXiv PDF
  • Code: OpenGVLab/OmniQuant
  • Topic: post-training quantization, learnable clipping, equivalent transformation, low-bit LLM deployment

OmniQuant is a useful paper because it sits between lightweight PTQ and expensive QAT. It does not update the full-precision model weights like quantization-aware training. It also does not rely only on handcrafted calibration rules like plain MinMax, SmoothQuant-style fixed migration strength, or grid-searched scaling. The main idea is narrower and more practical: freeze the original LLM weights, add a small set of learnable quantization parameters, optimize those parameters block by block on calibration samples, then fold the learned parameters away so the exported model has no extra runtime modules.

That design matters most in the hard cases. W4A16 is already reachable by strong weight-only methods such as GPTQ and AWQ. W8A8 is the target of SmoothQuant. OmniQuant tries to cover a wider set of formats, especially W2A16 and W4A4, where ordinary PTQ collapses. The method has two knobs:

  • Learnable Weight Clipping, or LWC, learns relative clipping strengths for weights.
  • Learnable Equivalent Transformation, or LET, learns scale/shift transformations that move activation quantization difficulty into weights while preserving the floating-point function before quantization.

The paper’s name is a little grand, but the technical point is concrete. “Omni” means the same calibration framework is used across weight-only, weight-activation, and attention/KV-related quantization positions.

One-Picture Summary

Figure 1 is the best starting point. The left panel compares three points for LLaMA-7B W4A4:

LLM-QAT 100k samples 90 h 46.43%

The two right panels show why the paper focuses on low bit widths. In the weight-only curve, GPTQ is reasonable at W4A16 and W3A16, then breaks badly at W2A16. In the weight-activation curve, SmoothQuant is fine around W8A8/W6A6 but degrades sharply at W4A4. OmniQuant’s claim is not that every quantization setting becomes lossless. The claim is that optimizing a small number of calibration parameters gives much better low-bit behavior than fixed rules, while staying far cheaper than QAT.

For weight-activation quantization, the goal is broader. If both weights and activations are low-bit, the matrix multiplication itself can move toward low-bit kernels. This is also where outliers are most damaging. LLM activations often have large channel-wise outliers, and naive per-token activation quantization must choose a scale large enough to cover them, wasting resolution on ordinary values.

PTQ, QAT, And Where OmniQuant Fits

Figure cropped from the paper PDF. The paper positions OmniQuant as learning a small set of quantization parameters with 128 calibration samples on a single A100-40G.

The practical tension is:

Approach What is optimized Cost Low-bit behavior
Plain PTQ fixed quantization parameters low often fails at W2A16/W4A4
Heuristic PTQ scales/clips searched by proxies low to medium better, but limited by proxy quality
QAT all model weights under quantization simulation very high strong but expensive
OmniQuant only quantization parameters medium PTQ-like strong in low-bit settings

OmniQuant’s calibration setup in the paper is intentionally small: 128 randomly selected 2048-token segments from WikiText2, batch size 1, AdamW, and block-wise optimization. The original FP weights are frozen. The learned parameters are:

The central implementation question is whether these parameters stay in the runtime graph. OmniQuant’s answer is no: clipping affects the final quantized weights, and equivalent transformations are folded into adjacent normalization or linear layers. If these parameters remained as extra floating-point operations during serving, the method would be much less attractive.

Transformer Block Placement

Figure cropped from the paper PDF. Red modules are learnable during calibration, blue snowflake markers are fixed, and pink modules can be eliminated after quantization.

The placement diagram is dense, but it is the most useful implementation figure in the paper. The learnable pieces appear around:

  • weight clipping before weight quantization;
  • normalization-to-projection transformations;
  • Q/K transformations before attention affinity;
  • value/output projection transformations;
  • MLP transformations around fc1.

The paper explicitly avoids LET on the second FFN linear layer. Its explanation is that the activation after the nonlinear layer is sparse, which can make LET gradients unstable there. That is a good reminder that equivalent transformations are not free to place everywhere. They need numerically stable statistics and a neighboring operation where the transform can be folded.

Calibration Algorithm

Algorithm cropped from the paper PDF. OmniQuant runs a full-precision stream and a quantized stream through blocks, optimizing LWC/LET parameters for each block before moving on.

The algorithm keeps two activation streams:

For each transformer block :

  1. Run the full-precision block to update .
  2. Initialize LWC parameters and LET parameters .
  3. For several epochs, transform the block, quantize it, run it on , and minimize .
  4. Fold the learned LET parameters and quantize the block with LWC.
  5. Run the final quantized block to update for the next block.

A simplified pseudocode view:

This sequential design is important because errors accumulate. If every block were calibrated only against the original full-precision input distribution, later blocks would see a cleaner distribution than they will see at inference time. By updating after each quantized block, the next block calibrates on the actual quantized prefix distribution.

Table 1 is the most important weight-only result. The easy setting is W4A16, where GPTQ/AWQ/RTN are already close to FP16. The interesting setting is W2A16.

Some representative rows:

Setting Model GPTQ PPL AWQ PPL OmniQuant PPL
W2A16 LLaMA-1-13B 5.5e3 - 13.21
W2A16 LLaMA-1-30B 499.75 - 8.71
W2A16 LLaMA-2-70B 77.95 - 7.81
W2A16g128 LLaMA-1-13B 15.60 2.8e5 7.93
W3A16 LLaMA-1-13B 6.76 7.45 5.68

The pattern is:

  • At W4A16, the gap is small because the format is not extremely hard.
  • At W3A16, OmniQuant is consistently strong but the baseline methods remain usable.
  • At W2A16, the learned clipping becomes crucial; GPTQ and AWQ can collapse depending on model and grouping, while OmniQuant keeps perplexity in a usable range.

I would not read this table as “OmniQuant replaces GPTQ everywhere.” For ordinary W4A16 deployment with mature kernels, GPTQ/AWQ may still be simpler. The reason to care about OmniQuant is the lower-bit frontier and the fact that the same calibration machinery also supports weight-activation quantization.

W4A4 is the table I care about most. Once activations are also 4-bit, activation outliers become unavoidable. SmoothQuant helps at W8A8, but W4A4 is much harsher.

For average zero-shot accuracy:

Model SmoothQuant W4A4 OS+ W4A4 OmniQuant W4A4 FP16
LLaMA-1-7B 38.41 48.43 52.65 64.09

LLaMA-1-30B 44.83 52.62 56.63 67.44

The 7B row also includes LLM-QAT:

Method LLaMA-1-7B W4A4 average accuracy
SmoothQuant 38.41
LLM-QAT 41.27
LLM-QAT + SmoothQuant 46.43

This is the headline result: with 128 calibration samples and 1.6 hours for LLaMA-7B, OmniQuant beats the listed QAT baseline in that W4A4 comparison. The reason is not that tiny PTQ optimization is more expressive than full QAT in general. It is that optimizing the right local quantization parameters can be a better use of calibration budget than doing broad weight updates under a limited QAT setup.

W6A6 is less dramatic. It is usually close to FP16 and SmoothQuant/OS+ are already reasonable. Again, OmniQuant is most interesting where handcrafted parameters stop being enough.

Instruction-Tuned Models

Figure cropped from the paper PDF. Vicuna-Bench pairwise comparison for LLaMA-2-chat W3A16g128.

The instruction-tuned experiment is useful because perplexity is not the whole story. On Vicuna-Bench, the authors compare RTN, AWQ, and OmniQuant with GPT-4 judging over both answer orders.

For LLaMA-2-7B-chat:

  • AWQ vs RTN: 69.4% win rate for AWQ.
  • OmniQuant vs RTN: 80.3% win rate for OmniQuant.
  • OmniQuant vs AWQ: 50.0% win rate.

For LLaMA-2-13B-chat:

  • AWQ vs RTN: 46.6% win rate for AWQ.
  • OmniQuant vs RTN: 54.4% win rate for OmniQuant.
  • OmniQuant vs AWQ: 56.2% win rate for OmniQuant.

The result is not an overwhelming sweep, but it supports the claim that the calibration is not only overfitting WikiText2 perplexity. For instruction-tuned models, OmniQuant remains competitive or better in a pairwise chat evaluation.

Deployment Result

Table cropped from the paper PDF. Weight-only quantized LLaMA models deployed through MLC-LLM on an NVIDIA A100-80G.

The deployment table matters because a quantization method can look good in perplexity and still be awkward to serve. OmniQuant’s learned parameters are designed to be folded, so weight-only models can be exported into existing low-bit deployment stacks.

The paper reports memory and generation speed through MLC-LLM. For LLaMA-7B:

Setting Weight memory Running memory token/s
FP 12.6G 14.4G 69.2
W4A16g128 3.8G 5.7G 134.2
W3A16g128 3.2G 5.1G 83.4
W2A16g128 2.2G 4.1G 83.9

For LLaMA-65B, the FP model is OOM under the measured setup, while quantized variants run:

Setting Weight memory Running memory token/s
W4A16g128 33.0G 41.0G 24.3
W3A16g128 27.0G 35.1G 15.2
W2A16g128 18.0G 25.6G 24.8

The speed numbers are not monotonic with bit width because kernel support matters. INT3/INT2 support was weaker in the reported MLC-LLM stack. This is a deployment lesson: lower bits reduce memory, but latency depends on packing, dequantization, kernel quality, and hardware support.

The paper only demonstrates deployment for weight-only quantization. It explicitly notes that W4A4 and W6A6 lacked out-of-the-box hardware support in that study. So OmniQuant’s W4A4 accuracy result should be separated from actual production W4A4 serving speed.

Why LWC And LET Need Each Other

Table cropped from the appendix. LET and LWC work best when optimized together under the same differentiable block-wise framework.

Table A2 is one of the most useful ablations:

LLaMA-7B W4A4 method Average PPL Average accuracy
SmoothQuant 28.78 38.41
LET 16.97 48.83
LET + grid-searched weight clipping 15.82 49.59
SmoothQuant + LWC 15.80 50.15
LET + LWC 12.87 52.65

The point is not simply “clipping helps” and “equivalent transformation helps.” LET changes the activation and equivalent weight distributions. LWC then has to clip the transformed weights, not the original weights. If clipping is found by a separate grid search or if the equivalent transform is fixed, the two knobs are not co-adapted.

This is the most convincing argument for OmniQuant’s differentiable setup. It is not learning many parameters, but it is learning coupled parameters.

Component Ablation

Table cropped from the appendix. Removing LET is catastrophic for W4A4; removing LWC is also harmful.

The component ablation is blunt:

Model / setting LWC+LET without LWC without LET without both
LLaMA-13B W4A4 10.87 20.75 5.4e3 1.8e3
LLaMA-13B W3A16 5.65 7.65 5.68 10.68
OPT-13B W4A4 11.65 15.23 7.8e3 7.8e5
OPT-13B W3A16 10.87 12.98 11.29 4.6e3

For W4A4, removing LET causes a collapse because activation quantization remains unsolved. For W3A16 weight-only quantization, LET is less important for LLaMA, which is why the paper often uses only LWC for LLaMA weight-only settings to save time. OPT is more sensitive to LET even in weight-only W3A16.

This is a good practical rule:

  • If activations are quantized, LET is not optional.
  • If only weights are quantized, LWC is the core component, and LET may or may not pay for itself depending on the model family.

LET Design Choices

Tables cropped from the appendix. Channel-wise shifting, attention transformation, and LET placement each affect W4A4 quality.

Table A4 compares the two additions beyond a basic scale-only linear transformation:

Method LLaMA-13B W4A4 PPL OPT-13B W4A4 PPL
LWC + LET 10.87 11.65
without shifting 11.47 13.64
without attention LET 11.34 11.79

Channel-wise shifting helps, especially on OPT-13B W4A4. Attention LET helps too, though less dramatically in this table. That matches the paper’s explanation that the largest outliers often appear after normalization layers, so linear-layer LET carries most of the gain.

Table A5 removes LET at different positions in LLaMA-7B W4A4:

Removed LET position Average PPL Average accuracy
none 12.87 52.65
[ln1, (q_proj, k_proj, v_proj)] 19.87 46.79

[Q,K] 13.34 51.47
[ln2, fc1] 14.47 51.04

The most sensitive placement is the transform after the first LayerNorm and before Q/K/V projections. This is consistent with the activation-outlier story: if a normalization output has severe channel outliers, every downstream projection inherits the quantization problem.

The fast convergence is important. W4A4 drops from 33.93 to 12.04 in 10 epochs, then only improves modestly. W2A16 is harder and keeps benefiting from longer calibration. This is exactly what I would expect: 2-bit weight quantization leaves so little representational room that the clipping parameters need more optimization.

The main paper uses 20 epochs for most settings and a longer schedule for W2A16. The deployment implication is that calibration cost is not zero, but it is still in the PTQ family rather than QAT.

What LWC Learns

Figure cropped from the appendix. Learned clipping strengths differ by bit width and grouping.

The learned clipping-scale visualization is a useful sanity check. LWC is not always clipping aggressively. In grouped quantization, many groups have clipping strengths close to 1, meaning little clipping. At lower bit widths, the distribution shifts toward more clipping because the quantizer has fewer representable values.

This fits the role of LWC. The method is not trying to erase all outliers. It is deciding where the quantization range should stop so that the block output is preserved on calibration data.

The appendix also reports that LWC reduces both weight distance and final activation distance. That second part matters more than the first. A small weight reconstruction error is not enough if it produces a large downstream activation error. OmniQuant’s block-wise loss directly sees that downstream effect.

What LET Changes

Figure cropped from the appendix. LET makes activation channels more homogeneous than the original distribution and the SmoothQuant-transformed distribution.

Figure A2 shows the activation-outlier story visually. Original activations have a few channels with much larger magnitude. SmoothQuant reduces the largest outliers, but the transformed distribution still has visible channel imbalance. LET reduces the disparity further because it is optimized under the block reconstruction objective rather than chosen by a fixed migration rule.

This is the activation-side reason W4A4 improves. If the activation quantizer must cover a few huge channels, ordinary channels lose resolution. LET reshapes the distribution before quantization, and LWC absorbs the corresponding weight-side difficulty.

Block-Wise Error

Figure cropped from the appendix. Gradient-based calibration produces lower block-wise error than grid-search-based methods in the reported settings.

Figure A3 compares block-wise quantization error against AWQ-style or OS+-style grid-search baselines. The curves make the main optimization argument concrete: a handcrafted proxy can find a useful scale, but directly optimizing block reconstruction can reduce the error more consistently across blocks.

This does not mean gradient-based PTQ is automatically better for every model. It means the optimization target is better aligned with what we care about: preserving the block’s actual output on representative activations.

Bit-Level Scaling Law

Figure cropped from the appendix. With stronger PTQ, 3-bit quantization can approach the tradeoff usually associated with 4-bit quantization.

The bit-level scaling plot is a more speculative but interesting result. Earlier empirical work often argues that 4-bit quantization is a good universal balance between total model bits and accuracy. OmniQuant’s appendix suggests that, with better calibration, 3-bit models can approach a similar tradeoff for perplexity.

I would read this cautiously. It depends on the quantizer, metadata, kernels, and model family. A 3-bit checkpoint with poor kernel support may be slower than a 4-bit checkpoint. Still, the result is important because it says the “4-bit is the natural floor” intuition is partly a method limitation, not only a model property.

PACT and LSQ were originally designed in a QAT context. They can help weight-only quantization, but W4A4 is different because LET changes the equivalent weight distribution during calibration. LWC’s relative clipping parameterization adapts better to that changing distribution.

Figure cropped from the appendix. LWC tracks changing weight ranges during training more stably than absolute-threshold clipping methods.

Figure A5 reinforces the same point. If the effective weight range changes during LET optimization, an absolute clipping threshold can become stale. Relative clipping strengths are a better parameterization when the scale of the transformed weights is moving.

Relation To Other LLM Quantization Methods

Table cropped from the appendix. OmniQuant differs from SmoothQuant/AWQ/OS+ by learning scale-and-shift transformations and applying them to both linear layers and attention.

Method Main target Calibration signal Runtime shape
LLM.int8() INT8 matmul with outlier rescue activation outlier detection INT8 path plus FP16 outlier path
SmoothQuant W8A8 activation/weight maxima, fixed smoothing strength dense INT8-friendly path
GPTQ W3A16/W4A16 second-order layer reconstruction weight-only low-bit kernels
AWQ W4A16 activation-aware salient weight protection weight-only low-bit kernels
OmniQuant W2A16/W3A16/W4A16/W6A6/W4A4 gradient-optimized block reconstruction over LWC/LET parameters folded quantized model

The closest conceptual relatives are SmoothQuant and AWQ:

  • Like SmoothQuant, OmniQuant uses equivalent transformations to migrate activation difficulty into weights.
  • Like AWQ, OmniQuant cares about activation-aware weight quantization and avoids updating the full original model.
  • Unlike both, OmniQuant directly optimizes the calibration parameters with gradients under a block-wise reconstruction loss.

Compared with GPTQ, OmniQuant is less about Hessian-based rounding compensation and more about making the quantization range and transformed distributions easier before quantization. They attack different parts of the PTQ problem.

Practical Reproduction Notes

If I were reproducing OmniQuant, I would not start with all settings at once. I would stage it like this:

  1. Implement LWC only for one linear layer and verify the LWC formula against MinMax when .
  2. Calibrate one transformer block in W4A16 or W3A16 and confirm the block reconstruction loss decreases.
  3. Add LET for a linear layer and verify exact floating-point equivalence before quantization:

  1. Check that folding removes the runtime transformation. The exported graph should not contain extra LET modules.
  2. Move from W4A16 to W3A16, then W2A16. Do not debug W2A16 first.
  3. Add activation quantization and test W6A6 before W4A4.
  4. Track both layer/block reconstruction and end metrics. A lower local loss is useful only if perplexity and task accuracy follow.

The calibration data also deserves attention. The paper uses 128 2048-token WikiText2 segments. That is enough for the reported setting, but deployment prompts may have different activation statistics. For a production model, I would calibrate on representative prompts and hold out a similar set to detect overfitting of the learned quantization parameters.

Takeaway

OmniQuant is best read as differentiable PTQ for LLMs. It keeps the original weights frozen, learns only a small set of quantization parameters, and calibrates them block by block. LWC learns how much weight range to clip. LET learns how to reshape activation distributions through equivalent transformations. Together, they make difficult formats such as W2A16 and W4A4 much more stable than fixed PTQ rules.

The caveat is systems support. Weight-only OmniQuant can be deployed through existing low-bit stacks after folding. W4A4 accuracy is promising, but real W4A4 serving also needs mature kernels and hardware support. In that sense, the paper is both a quantization-method paper and a reminder that quantization quality and quantized inference are related but separate engineering problems.

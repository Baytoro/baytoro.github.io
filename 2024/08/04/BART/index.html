BART: Denoising Sequence-to-Sequence Pre-training

Paper : BART: Denoising Sequence-to-Sequence Pre-training for Natural Language Generation, Translation, and Comprehension

BART is easiest to place as a denoising sequence-to-sequence model. It puts a BERT-style bidirectional encoder and a GPT-style autoregressive decoder into a standard Transformer encoder-decoder, then pre-trains the model by corrupting a document and reconstructing the original one.

This objective gives BART a useful middle ground. If the downstream output is a label, the model still has a bidirectional encoder for understanding. If the output is text, the decoder is already trained to generate a sequence left-to-right. The paper’s experiments are mostly a stress test of that design choice.

Motivation

Figure 1 is the most useful mental model for the paper.

BERT encodes the whole context bidirectionally, but masked tokens are predicted independently, which makes full-sequence generation awkward. GPT is naturally generative, but every position only conditions on the left context. BART encodes a corrupted document bidirectionally and reconstructs the clean document with an autoregressive decoder.

The key detail is that encoder input and decoder output do not have to align. That makes it possible to delete tokens, replace variable-length spans, shuffle sentences, or rotate a document. The decoder only needs to recover the original sequence.

Noising Functions

The paper compares several input corruptions:

  • Token Masking: randomly replace tokens with [MASK], close to BERT’s MLM setup.
  • Token Deletion: remove tokens entirely, so the model must infer where content is missing.
  • Text Infilling: sample spans and replace each span with a single [MASK]; span lengths are drawn from a Poisson distribution with .
  • Sentence Permutation: split a document into sentences and shuffle their order.
  • Document Rotation: choose a random token as the new beginning of the document.

Text infilling is more generative than ordinary token masking. The model has to recover both the missing content and the missing span length. Based on the ablation results, the large model uses text infilling + sentence permutation, masking 30% of tokens and permuting all sentences.

Fine-tuning

BART’s fine-tuning recipes mostly follow from the encoder-decoder shape.

For sequence classification, the same input is fed to both the encoder and decoder. The hidden state of the final decoder token is used for classification, roughly playing the role that [CLS] plays in BERT, except that it comes from the decoder and can attend to the complete input.

For generation tasks, the setup is direct: summarization, abstractive QA, and dialogue response generation are all standard sequence-to-sequence fine-tuning problems.

Machine translation is a special case in the paper. To translate into English, the authors add a randomly initialized source encoder that maps the foreign-language input into a space that the pretrained BART model can denoise into English. Training first freezes most BART parameters and updates the new encoder plus a small set of related parameters, then briefly fine-tunes the full model.

Objective Ablation

Table 1 is the most informative result in the paper. The models are kept at comparable size, trained for 1M steps on books and Wikipedia, and then evaluated across both understanding and generation tasks.

The important readings:

  • Text Infilling is the most consistently strong single corruption: SQuAD 1.1 F1 reaches 90.8, XSum PPL is 6.61, and ConvAI2 PPL is 11.05.
  • Text Infilling + Sentence Shuffling is best on CNN/DailyMail, with PPL 5.41.
  • Document Rotation and Sentence Shuffling perform poorly in isolation. Shuffling structure alone is not a strong enough signal.
  • A pure Language Model is best on ELI5 PPL, but it is weak on SQuAD. That fits the task shape: ELI5 has long, loosely constrained answers, while SQuAD needs bidirectional context.

The point is not that one noising function is universally optimal. The point is that BART’s architecture makes these noising schemes comparable under one framework, and text infilling turns out to be the most robust choice.

Large-scale Results

The large model uses a 12-layer encoder, a 12-layer decoder, and hidden size 1024. It is trained at a similar scale to RoBERTa for 500k steps. Table 2 answers a practical question: does adding an autoregressive decoder hurt discriminative tasks?

The answer is mostly no. On SQuAD 1.1, BART reports 88.8/94.6 while RoBERTa reports 88.9/94.6. MNLI, QQP, QNLI, and RTE are also in the same range. BART keeps generation ability without obviously giving up language-understanding performance.

Summarization is where BART looks most natural. CNN/DailyMail is relatively extractive and the Lead-3 baseline is already strong, but BART still reaches 44.16 / 21.28 / 40.90. XSum is more abstractive, and extractive systems are much weaker there; BART reaches 45.14 / 22.27 / 37.25, roughly six ROUGE points above the previous BERTSUM-style results.

This is the cleanest use case for encoder-decoder pre-training: the input is a document, and the output is a new piece of text rather than a label or a copied span.

Generation And Translation

ELI5 is long-form abstractive QA, and the output is less tightly constrained by the input than in summarization. BART still reports the best ROUGE in Table 5: 30.6 / 6.2 / 24.3. This does not contradict Table 1, where the pure language model had the best ELI5 PPL. PPL and ROUGE measure different things, and the large-scale setup is also different from the base-model ablation.

The translation experiment is more of a probe for BART’s English generation prior. On WMT16 RO-EN with back-translation data, the baseline is 36.80 BLEU. Fixed BART is slightly worse at 36.29, while tuned BART reaches 37.96. The gain is modest, but it shows that the pretrained English denoising model can be attached to a translation system in a useful way.

Reading Notes

BART is often discussed next to T5 because both models push NLP tasks toward a text-to-text or sequence-to-sequence interface. The emphasis is different, though. BART is mainly about what kind of corruption works well for encoder-decoder denoising.

Text infilling is the core design for me. It forces the model to infer content and length, so it is closer to downstream generation than single-token masking. Sentence permutation then adds a document-level ordering signal, which is why the large model keeps it as an auxiliary corruption.

BART’s contribution is not a complicated new block. It is a clean composition of ideas that already had evidence behind them:

  • the encoder handles bidirectional understanding of corrupted input;
  • the decoder handles left-to-right reconstruction;
  • the noising function can be more flexible than MLM;
  • the same model can be fine-tuned for classification, summarization, QA, dialogue, and translation.

The limitations are also visible. If the task is only classification, an encoder-only model such as RoBERTa is cheaper. If the output is only loosely grounded in the input, a pure language model can be competitive. BART is strongest when the input provides real constraints and the output is still natural language.

Takeaway

BART is not just “BERT + GPT”. The important move is to put a denoising objective inside a sequence-to-sequence architecture. Pre-training teaches the model to recover full documents from damaged ones, and fine-tuning can reuse the same interface for text-in, text-out tasks.

My summary after reading the paper:

  • text infilling is the most important noising function;
  • the bidirectional encoder keeps understanding tasks strong;
  • the autoregressive decoder makes summarization and generation natural;
  • BART is not the lightest classifier, but it is a strong default when the output is text.

The broader lesson is still useful: if the downstream workload is generative, pre-training should look generative too. Recovering damaged text is a better match than predicting isolated masked tokens.

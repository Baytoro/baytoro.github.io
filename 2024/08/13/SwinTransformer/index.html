Swin Transformer: Hierarchical Vision Transformer using Shifted Windows

H.J. Chen
  2024-08-13 2024-08-13 Created

Paper

Swin Transformer is one of the papers that made vision Transformers feel practical as a backbone instead of only as an image classification model. The design is not mysterious: it keeps the Transformer block, but changes the token layout and the attention pattern so that the network looks more like a CNN pyramid.

The two core ideas are:

  • build hierarchical feature maps by progressively merging neighboring patches;
  • compute self-attention inside local windows, then shift the window partition between adjacent blocks so information can cross window boundaries.

This sounds small, but it fixes two major problems of the original ViT: the feature map is no longer stuck at one low resolution, and attention is no longer quadratic in the full image size.

Motivation

Plain ViT treats an image as a sequence of non-overlapping patches. For image classification this is acceptable: a class token or pooled feature is enough. For object detection and semantic segmentation, however, the model needs dense feature maps at multiple scales. A detector usually wants something like a feature pyramid, where early stages preserve spatial details and later stages carry high-level semantics.

The figure compares the two feature layouts. ViT keeps a single-scale token grid after patch embedding. Swin starts from small patches and repeatedly merges them, so the network naturally produces feature maps at resolutions similar to C2, C3, C4, and C5 in a CNN backbone.

This is why Swin became useful outside ImageNet classification. The paper evaluates it as a drop-in backbone for ImageNet classification, COCO detection, and ADE20K segmentation, instead of only reporting a classification number.

Shifted Windows

Local windows alone create a new problem: tokens in different windows cannot communicate. If every layer uses exactly the same window partition, the model becomes a set of isolated local Transformers.

Swin solves this by alternating between regular window partitioning and shifted window partitioning.

The left side is regular window attention. The right side shifts the partition by half a window size, so each shifted window contains tokens that came from several previous windows. After two consecutive blocks, information can move across the original window boundary.

This is a nice compromise:

  • within one block, attention is still local and cheap;
  • across two blocks, neighboring windows exchange information;
  • the model does not need global attention at every layer.

Efficient Shifted Window Implementation

A naive implementation of shifted windows would create more windows near the feature boundary. The paper gives an example where a window layout becomes a layout after shifting, which means more attention windows and more padding.

The efficient implementation uses cyclic shift:

  1. Cyclically shift the whole feature map toward the top-left.
  2. Partition the shifted feature map into the same number of windows as before.
  3. Apply an attention mask so tokens from non-adjacent wrapped regions cannot attend to each other.
  4. Reverse the cyclic shift after attention.

The mask is not a minor engineering trick. Without it, tokens wrapped from the opposite side of the feature map would be treated as if they were spatial neighbors. With the mask, cyclic shift becomes a batching trick: the implementation keeps the same number of windows while preserving the intended shifted-window attention pattern.

This is also why Swin is fast in practice. The theory says window attention is cheaper, but the cyclic-shift implementation makes the shifted case close to the non-shifted case in actual latency.

Swin-T is the small practical backbone, roughly comparable to ResNet-50 scale in downstream usage. Swin-B and Swin-L are larger models where ImageNet-22K pre-training becomes important.

One useful detail: the deeper stage is Stage 3, not Stage 4. That matches CNN backbone design as well. Stage 3 usually has enough spatial resolution to matter for dense prediction, so spending more blocks there gives a better compute-accuracy tradeoff.

ImageNet Results

On ImageNet-1K, Swin-T reaches 81.3 top-1 accuracy with 4.5G FLOPs and 755.2 images/s throughput. Swin-S reaches 83.0, and Swin-B reaches 83.5 at input.

The comparison with DeiT is the most relevant Transformer baseline:

  • At input, DeiT-S gets 79.8 top-1 with 4.6G FLOPs, while Swin-T gets 81.3 with 4.5G FLOPs.
  • At input, DeiT-B gets 81.8 top-1 with 17.5G FLOPs, while Swin-B gets 83.5 with 15.4G FLOPs.
  • At input, DeiT-B gets 83.1 top-1 with 55.4G FLOPs, while Swin-B gets 84.5 with 47.0G FLOPs.

Swin is not always faster in throughput than DeiT at the small scale, but it gives better accuracy at similar FLOPs. After ImageNet-22K pre-training, Swin-L reaches 87.3 top-1 at input. That was a strong result for a general-purpose backbone.

Again, this is where the backbone design matters. Semantic segmentation needs detailed spatial output. The hierarchical structure gives the segmentation head multi-scale features, while shifted windows allow local regions to communicate without paying global attention cost.

Ablation: Shift, Position Bias, and Speed

The shifted-window ablation is very direct. Removing the shift drops Swin-T from 81.3 to 80.2 on ImageNet, from 50.5 to 47.7 box AP on COCO, and from 46.1 to 43.3 mIoU on ADE20K.

My reading: the shift is more important for dense prediction than for classification. Classification can tolerate some locality because the final representation only needs a global category. Detection and segmentation need object boundaries, context, and cross-window consistency, so the lack of communication hurts more.

The position encoding ablation is also useful:

  • no position embedding: 80.1 ImageNet, 49.2 box AP, 43.8 mIoU;
  • absolute position embedding: 80.5 ImageNet, 49.0 box AP, 43.2 mIoU;
  • relative position bias: 81.3 ImageNet, 50.5 box AP, 46.1 mIoU.

Relative position bias works better because it is local and window-compatible. Absolute position embeddings are more tied to a specific image grid, which is less convenient when image sizes vary across detection and segmentation pipelines.

The speed table compares different attention implementations. The important row is shifted window with cyclic implementation. It is much faster than naive shifted-window padding and close to normal window attention.

For Swin-T, the paper reports:

Attention implementation Throughput
Sliding window, naive MSA 183 images/s
Performer 638 images/s
Window, no shift 770 images/s
Shifted window, padding 670 images/s
Shifted window, cyclic 755 images/s

This explains why the cyclic shift and mask trick matters. The shifted-window idea would be less attractive if it created many extra windows or padding overhead. With cyclic shift, the implementation keeps the number of windows stable.

Takeaway

Swin Transformer is important because it adapts the Transformer to the normal shape of vision backbones:

  • patch merging creates a feature pyramid;
  • window attention makes high-resolution features affordable;
  • shifted windows allow cross-window communication;
  • relative position bias gives local spatial inductive bias;
  • cyclic shift and masking make the design efficient enough to use in real detection and segmentation systems.

The paper is not just proposing another attention variant. It is packaging several architectural and implementation choices into a backbone that fits existing vision pipelines. That is why Swin had such a large downstream impact: it could be plugged into the same places where people were already using ResNet, ResNeXt, and ConvNeXt-style backbones.

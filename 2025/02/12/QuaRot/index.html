QuaRot: Rotated 4-Bit LLM Inference

H.J. Chen
  2025-02-12 2025-02-12 Created  
  • Paper Reading 
 
  • Quantization 
  • | LLM 
  • | KV-Cache 
  • | Inference 

Ashkboos et al. “QuaRot: Outlier-Free 4-Bit Inference in Rotated LLMs.” NeurIPS 2024.

Paper: arXiv:2404.00456
Code: spcl/QuaRot

QuaRot is a rotation-based answer to the LLM activation-outlier problem. SmoothQuant rescales channels. LLM.int8() routes outlier dimensions through a high-precision side path. QuaRot changes the coordinate basis with orthogonal Hadamard rotations so the same hidden state becomes less axis-aligned and easier to quantize.

The target setting is hard: A4W4KV4. That means activations, weights, and KV cache are all stored or moved through 4-bit paths where possible. This is different from W4A16 methods such as GPTQ or AWQ, which keep activations high precision, and different from W8A8 methods that only need INT8-level robustness.

The key reading of the paper is:

  • rotations preserve the model function before quantization;
  • Hadamard structure makes those rotations cheap enough;
  • the rotated tensors have fewer coordinate outliers;
  • after that transformation, ordinary low-bit quantizers become much less fragile.

The Outlier Problem

The first figure is the whole motivation.

The left panel shows the input activation distribution of a Llama-2-7B FFN block before QuaRot. Some hidden dimensions have much larger ranges than the rest. If a per-token INT4 activation quantizer has to cover those spikes, most ordinary dimensions lose resolution.

The right panel shows the same kind of tensor after QuaRot processing. The total vector energy is not removed, but it is spread across coordinates. That is exactly what a uniform quantizer wants: a smaller coordinate-wise maximum for the same semantic signal.

The nontrivial part is that transformer blocks have RMSNorm, residual streams, attention, RoPE, and multi-head structure. QuaRot relies on a computational invariance property: if the residual stream is transformed by an orthogonal matrix and adjacent weights are updated consistently, the full-precision model output stays the same.

The RMSNorm interaction is important. Ignoring the learned scaling term for a moment, RMSNorm divides each row by its norm. Since orthogonal rotation preserves the row norm:

In practice, QuaRot absorbs the RMSNorm scale parameters into adjacent weights first, then uses rotations around the remaining norm-only operation.

This is the main conceptual move: make the network compute in a rotated hidden basis without changing the FP16 function, then quantize the easier tensors.

The point is not that Hadamard is the only possible orthogonal matrix. The point is that it is fast. A dense orthogonal rotation would be too expensive on the inference path. A Hadamard transform can be implemented with structured add/subtract operations, and many rotations can be folded into weights offline.

It is targeting the expensive matrix multiplications and the cache/memory path.

Quantization Setup

QuaRot has two stages:

  1. Rotate and modify the model in high precision. Fold rotations into weights where possible and insert the small number of online Hadamard transforms that remain.
  2. Quantize weights, activations, and cache. The paper uses GPTQ by default for weights, round-to-nearest for online activations, and group-wise asymmetric quantization for KV cache.

The experiment details are worth keeping:

  • activation quantization: symmetric per-token INT4;
  • activation clipping ratio: 0.9;
  • activation scale: row maximum divided by 7 for INT4;
  • KV cache quantization: asymmetric, group size 128;
  • KV clipping ratio: 0.95;
  • weight quantization: GPTQ by default, RTN in ablations;
  • GPTQ calibration: 128 WikiText-2 samples with sequence length 2048;
  • implementation: PyTorch/Hugging Face, CUTLASS INT4 GEMM, FlashInfer for KV cache;
  • performance hardware: NVIDIA RTX 3090.

For Llama-2-70B, the paper reports about 5 minutes for the QuaRot model modification and about 2 more hours for GPTQ quantization on a single A100. So this is still PTQ-style work, not QAT, but it is not a zero-cost conversion.

Main Accuracy Results

Table 1 is the most important result because it compares end-to-end 4-bit quantization on WikiText-2.

QuaRot with GPTQ has no high-precision outlier features and keeps Llama-2 perplexity close to FP16:

Model FP16 QuaRot GPTQ A4W4KV4 PPL increase
Llama-2-7B 5.47 6.10 +0.63
Llama-2-13B 4.88 5.40 +0.52
Llama-2-70B 3.32 3.79 +0.47

That is the headline: the 70B model, which is usually more forgiving under quantization, loses only 0.47 WikiText-2 perplexity while weights, activations, and cache are all in the 4-bit target regime.

The comparison against SmoothQuant and OmniQuant is also revealing. Those methods were not designed around this exact 4-bit activation/cache setting, and their table entries degrade badly. QUIK-4B keeps 256 outlier features, while QuaRot keeps zero. This supports the paper’s claim that rotation can remove the need for a high-precision outlier side path.

Group-wise quantization narrows the gap further. With 128-group quantization, QuaRot reaches 5.93 on 7B, 5.26 on 13B, and 3.61 on 70B.

Zero-Shot Accuracy

The zero-shot table checks whether the perplexity story transfers to common LM-eval tasks.

The average drops are:

Model FP16 avg QuaRot avg Drop
Llama-2-7B 69.82 65.64 -4.18
Llama-2-13B 72.59 69.79 -2.80
Llama-2-70B 77.07 75.98 -1.09

This is a useful pattern: 4-bit end-to-end quantization is more painful for smaller models, and the 70B model retains most of its average zero-shot score. The paper summarizes this as preserving about 99% of zero-shot performance for the largest Llama-2 case.

Kernel And Memory Results

QuaRot is not only a mathematical transform. Its deployment value depends on whether the remaining online Hadamard operations and quantized cache path are cheap enough.

For a single transformer block on RTX 3090:

  • prefill speedup on Llama-2-7B is about 1.97x to 2.16x at sequence length 2048;
  • prefill speedup on Llama-2-70B reaches 3.16x to 3.33x;
  • decode peak memory saving is at least 3.63x;
  • Llama-2-70B decode memory saving is about 3.89x across the shown sequence lengths.

The memory result is the most directly useful for long-context serving, because decode is often cache-capacity and memory-bandwidth constrained. The speedup result is also encouraging, but it depends heavily on kernel quality and batch/sequence shape.

The layer microbenchmark gives another view.

For the FFN down-projection-like layer sizes, the paper reports:

  • Llama-2-7B shape: FP16 2.57 ms, INT4+Hadamard 0.80 ms;
  • Llama-2-13B shape: FP16 3.98 ms, INT4+Hadamard 1.14 ms;
  • Llama-2-70B shape: FP16 12.45 ms, INT4+Hadamard 2.91 ms.

The Hadamard transform adds only a small overhead over the INT4 path in this benchmark. That matters because QuaRot would be much less compelling if every rotation erased the INT4 GEMM win.

For decode memory, the detailed table is even more concrete.

For example, on Llama-2-7B with batch size 16 and sequence length 4096, the single-block decode memory drops from 1.416 GB to 0.378 GB, a 3.75x saving. On Llama-2-70B, the shown cases stay near 3.89x saving.

RTN And Group Size Ablations

The paper also checks how far simple round-to-nearest can go after rotation.

RTN is nearly lossless at 8 bits after QuaRot, but 4-bit RTN is still worse than GPTQ, especially on smaller models. For Llama-2-7B, 4-bit RTN has perplexity 8.37, while the GPTQ-based QuaRot result in Table 1 is 6.10. For Llama-2-70B, the RTN gap is smaller: 4.14 versus the GPTQ-based 3.79.

My reading is that rotation fixes the outlier geometry, but it does not make all rounding choices harmless. GPTQ still matters for 4-bit weights, especially in smaller models.

Group size shows the usual accuracy/metadata tradeoff.

Smaller groups improve perplexity:

Method 7B 13B 70B
QuaRot 6.10 5.40 3.79
QuaRot-256G 5.98 5.28 3.63
QuaRot-128G 5.93 5.26 3.61
QuaRot-64G 5.88 5.25 3.58

But smaller groups require more scale metadata and can complicate kernels. This is a common practical boundary: a paper table can prefer smaller groups, while a production runtime may choose the group size that best matches packing and GEMM layout.

KV Cache Quantization

KV cache quantization is a separate pressure point from weight quantization. The cache grows with sequence length and batch size, so it matters most in long-context decode.

The cache ablation keeps the rest of the model high precision and changes only K/V precision. A few readings:

  • 4-bit K and 4-bit V are almost lossless: 5.51 vs 5.47 on 7B, 3.33 vs 3.32 on 70B.
  • 3-bit K and 3-bit V are still close: 5.68 on 7B and 3.39 on 70B.
  • 2-bit cache is much harder, especially on 7B: K2/V2 gives 9.23.
  • keys are more sensitive than values in the shown comparisons: K4/V3 is better than K3/V4 on 7B.

This matches KIVI/KVQuant-style observations: the key cache has structured outlier behavior and directly affects attention logits, so key precision/granularity deserves special care.

Relation To Other Quantization Methods

QuaRot sits in a useful line of equivalent-transform methods:

Method Main target What it does with outliers
LLM.int8() W8A8-ish matmul keeps outlier dimensions in FP16
SmoothQuant W8A8 dense inference migrates activation scale into weights
GPTQ/AWQ W4A16 weight-only avoids activation quantization at runtime
KIVI KV cache uses asymmetric grouping for K and V
QuaRot A4W4KV4 inference rotates the basis to remove coordinate outliers

The important distinction is that QuaRot changes the basis, not just the scale. Scaling can make one channel easier by making the paired weight channel harder. Rotation mixes coordinates so sparse outliers become less concentrated. That is a stronger transformation, but it also requires more careful placement around RMSNorm, RoPE, and the cache.

Compared with QuIP/QuIP#, QuaRot uses related incoherence-processing ideas but applies them to end-to-end activation/cache quantization and tries to fold most rotations into the model so runtime overhead stays small.

Reproduction Notes

I would reproduce QuaRot in layers, not all at once.

First, test function preservation in floating point:

  1. apply the residual-stream rotation and fold / into adjacent weights;
  2. verify full-precision block outputs match the original within numerical noise;
  3. add the FFN online Hadamard before down projection;
  4. add attention value rotation;
  5. add post-RoPE key/query rotation and confirm attention logits are unchanged before quantization.

Then test the quantization path:

  1. plot activation max per hidden dimension before and after rotation;
  2. quantize activations per token and measure reconstruction error;
  3. enable GPTQ weights and compare against RTN;
  4. quantize KV cache separately and reproduce the K/V bit-width ablation;
  5. measure kernel overhead of each online Hadamard block separately.

The last step is important. A mathematically equivalent transform can still be a bad deployment idea if it adds latency on the decode path. QuaRot’s claim depends on the rotations being either folded into weights or implemented with very cheap structured kernels.

Limitations

The paper is strong, but the boundary should be clear.

First, “4-bit inference” does not mean every operation is INT4. RMSNorm, online Hadamard transforms, softmax-related work, query handling, dequantization, and some attention arithmetic still use higher precision. The claim is better read as: all major matrix multiplications and KV cache storage are pushed into the 4-bit regime.

Second, QuaRot is a kernel-aware method. Without CUTLASS/FlashInfer-style support for low-bit GEMM, packing, cache quantization, dequantization, and online Hadamard transforms, the paper’s accuracy result would not automatically translate into speed or memory savings.

Third, GPTQ is still used for the strongest 4-bit weight results. Rotation makes the tensors easier, but it does not remove the need for a good weight quantizer at 4 bits.

Fourth, the method has several engineering knobs: group size, clipping ratio, Hadamard precision, cache format, and rotation placement. The paper shows these are manageable, but they are still part of the deployment surface.

Takeaway

QuaRot is useful because it reframes activation outliers as a basis problem. Instead of preserving a few large coordinate directions in high precision, it rotates the model into a basis where those directions are spread out and ordinary low-bit quantization works better.

The idea is elegant, but the practical value comes from the details: RMSNorm scale folding, FFN and attention-specific Hadamard placement, post-RoPE key rotation, cache-aware quantization, and kernels where the online rotations are cheap. That is why this paper belongs in the full-stack LLM quantization path rather than only in the algebraic-transform bucket.

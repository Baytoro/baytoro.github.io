Paper: QuaRot: Outlier-Free 4-Bit Inference in Rotated LLMs

QuaRot is an outlier-removal paper. SmoothQuant rescales channels; RPTQ reorders them; QuaRot rotates the basis so outliers are spread across dimensions.

Motivation

Activation and KV-cache outliers are a major obstacle to W4A4-style inference. If a few dimensions dominate the range, low-bit uniform quantization loses too much resolution. Orthogonal rotations preserve norms and can be inserted in ways that keep the model function equivalent.

The figure shows the before/after effect on activation outliers. Rotation makes the distribution more quantization-friendly.

Methodology

QuaRot uses Hadamard-style orthogonal rotations. A rotation matrix can be inserted around linear layers so the mathematical function is preserved after folding transformations into weights where possible.

The benefit is that outlier energy is distributed across coordinates. The quantizer then sees a smaller dynamic range per channel/group.

Results

The paper reports improved low-bit LLM inference, including activation and KV-cache quantization settings where naive W4A4 fails. The method is especially relevant for full-stack low-bit inference rather than W4A16 weight-only compression.

Takeaway

QuaRot is a stronger transformation than scaling because it changes the basis. The cost is implementation complexity: rotations must be folded or executed efficiently. If that is handled, rotation is a powerful way to make LLM tensors outlier-free.

Why Rotation Helps More Than Scaling

Scaling can reduce one channel’s range by increasing another tensor’s range. Rotation redistributes energy across dimensions. If outliers are sparse in the coordinate basis, a Hadamard rotation can make the distribution more uniform.

Implementation Question

The main question is where the rotations live. Some can be folded into weights offline. Others may need runtime transforms. The paper’s practicality depends on making those transforms cheap relative to the quantization benefit.

Position In The Route

SmoothQuant rescales. RPTQ permutes. QuaRot rotates. The sequence is useful: each method uses a stronger equivalent transformation to fight activation outliers.

Implementation Reading

The practical trick is using structured rotations such as Hadamard transforms, which are fast and can be fused or implemented efficiently. A dense random orthogonal matrix would be too expensive.

QuaRot differs from SmoothQuant. SmoothQuant rescales channels; QuaRot mixes channels. Rescaling can shrink one channel by making another tensor larger. Rotation changes the basis so outliers become less axis-aligned. That is why it is especially relevant for W4A4 and KV quantization, where activation outliers are the main obstacle.

Experiment Reading

QuaRot should be judged on end-to-end low-bit inference, not only weight perplexity. The hard setting is W4A4KV4, where activations and KV cache are also low bit. Weight-only methods avoid much of this difficulty.

The ablation to watch is rotation placement. Rotating around every possible boundary may add overhead or implementation complexity. The useful rotations are those that remove outliers while being foldable or cheap enough at runtime.

Hadamard-style rotations are attractive because they are structured. They spread energy across dimensions without a dense matrix multiply. That makes the method more plausible as a deployment technique rather than only a mathematical transformation.

Reproduction Checklist

The first sanity check is function preservation. Insert a rotation and its inverse around a linear block in floating point and verify the output difference is numerical noise. Only after that should quantization be enabled. Otherwise it is easy to confuse implementation error with quantization loss.

The second check is outlier reduction. Plot per-channel max values before and after Hadamard rotation. The method should reduce the largest coordinate magnitudes without changing vector norms. The third check is runtime placement: rotations folded into weights are cheap, while rotations executed on the decode path must be measured carefully.

Boundary / Failure Mode

The risk is that rotation overhead depends heavily on where it is applied. A prefill-heavy workload may tolerate extra transforms differently from single-token decode. For decode, every added operation sits on the token latency path. I would therefore measure rotation cost separately for prefill and decode, and only keep rotations that are folded into weights or implemented with very cheap structured kernels.

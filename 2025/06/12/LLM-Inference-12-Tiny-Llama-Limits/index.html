This final post is a boundary marker. The tiny implementation in this series is useful because it is small enough to inspect. But real Llama inference is not just these 200 lines of model code. It adds tokenizer details, checkpoint loading, optimized kernels, paged memory, batching, scheduling, and system-level tradeoffs.

What The Tiny Model Teaches Well

The tiny model is good for the core forward path:

flowchart LR
    ids["token ids"] --> emb["embedding"]
    emb --> norm1["RMSNorm"]
    norm1 --> attn["RoPE + GQA attention"]
    attn --> res1["residual"]
    res1 --> norm2["RMSNorm"]
    norm2 --> mlp["SwiGLU MLP"]
    mlp --> res2["residual"]
    res2 --> head["LM Head"]
    head --> logits["next-token logits"]

It teaches these invariants:

Concept Shape to remember
token ids [B, T]
hidden states [B, T, D]
q [B, T, H, Dh]
k/v in GQA [B, T, G, Dh]
K/V cache [B, G, T_cache, Dh]
logits [B, T, V]
next-token logits [B, V]

These are the shapes I want in muscle memory before reading optimized inference code.

What It Leaves Out

Real Tokenization

The teaching tokenizer is a greedy toy tokenizer. Real Llama models use trained subword tokenizers with special tokens, chat templates, BOS/EOS handling, and compatibility constraints between tokenizer files and model checkpoints.

Real Weights

The tiny model initializes random weights. It demonstrates dataflow, not language quality. Loading real weights introduces:

Issue Why it matters
parameter naming checkpoint keys must match module names
tensor parallel layout weights may be sharded
dtype fp16/bf16/fp8/int4 affect kernels
tied embeddings some models tie embedding and LM Head weights

Optimized Attention Kernels

The teaching code uses explicit q @ k.transpose(...) and softmax. Production inference often uses FlashAttention-like kernels or decode-specialized kernels. Those kernels preserve the same mathematical contract but avoid materializing some intermediate tensors.

An optimized kernel may never store that full tensor. The shape reasoning still helps, but the memory behavior changes.

Paged KV Cache

The teaching cache is a simple concatenated tensor:

Serving systems often use paged or block-based KV memory so many requests can share GPU memory efficiently. The logical shape remains similar, but physical storage becomes an indirection problem.

Batching And Scheduling

The tiny generate loop assumes a simple batch. Real serving systems handle:

Serving issue Example
mixed prompt lengths different T per request
continuous batching new requests join while others decode
prefill/decode imbalance prefill is compute-heavy, decode is memory-heavy
cancellation user stops generation
streaming tokens are returned before the full sequence finishes

This is where systems papers become necessary.

How I Would Continue

After this series, the natural next topics are:

  1. PagedAttention and block-based KV memory.
  2. FlashAttention and decode attention kernels.
  3. Continuous batching and request scheduling.
  4. Tensor parallel inference.
  5. Quantized weight-only inference.
  6. Speculative decoding.

Those are not replacements for the shape-first model. They are layers on top of it.

This is the trace I wish I had before reading inference systems papers. It follows one prompt through prefill and then follows generated tokens through decode. The point is not model quality; the point is knowing what shape should exist at every step.

Setup

Use a tiny model:

Symbol Value Meaning
B 1 one prompt
T 2 prompt has two tokens
D 8 hidden size
L 2 two decoder blocks
H 4 query heads
G 2 KV heads
Dh 2 head dimension
V 10 tiny vocabulary

The prompt is:

Timeline

sequenceDiagram
    participant P as Prompt [B,T]
    participant M as Model
    participant C as Cache per layer
    participant S as Sampler

    P->>M: prefill
    M->>C: K/V length T
    M->>S: logits[:, -1, :] [B,V]
    S->>M: next_ids [B,1]
    M->>C: decode, append length +1
    M->>S: logits[:, -1, :] [B,V]
    S->>M: next_ids [B,1]
    M->>C: decode, append length +1

Prefill Trace

Step Tensor Shape
prompt ids input_ids [1, 2]
embedding x [1, 2, 8]
block 0 output x [1, 2, 8]
block 0 cache K/V cache_0.k/v [1, 2, 2, 2]
block 1 output x [1, 2, 8]
block 1 cache K/V cache_1.k/v [1, 2, 2, 2]
final logits logits [1, 2, 10]
next logits logits[:, -1, :] [1, 10]

The cache sequence length is 2 because the prompt had two tokens.

First Decode Step

Assume the first sampled token is:

The model consumes only that token:

Step Tensor Shape
decode input next_ids [1, 1]
token embedding x [1, 1, 8]
new q q [1, 1, 4, 2]
new k/v before transpose k/v [1, 1, 2, 2]
new k/v in cache layout new_k/new_v [1, 2, 1, 2]
cache after append cache.k/v [1, 2, 3, 2]
attention scores scores [1, 4, 1, 3]
block output x [1, 1, 8]
logits logits [1, 1, 10]

The score shape [1, 4, 1, 3] is the decode signature: one query token attends to three cached key positions.

Second Decode Step

The next decode token again has shape [1, 1], but the cache is longer:

Step Shape
decode input [1, 1]
old cache [1, 2, 3, 2]
new k/v [1, 2, 1, 2]
new cache [1, 2, 4, 2]
attention scores [1, 4, 1, 4]
logits [1, 1, 10]

Only the last axis of scores grows as the sequence grows.

Debug Checklist

When I debug a cache path, I check these invariants:

Invariant Expected
decode input rank always [B, 1]
cache list length num_layers
cache head count G, not H
cache append dimension dim=2
RoPE start position old cache.seq_len
decode score shape [B, H, 1, T_total]
decode logits shape [B, 1, V]

If one of these is wrong, generation might still run for a few steps but the attention history is no longer what I think it is.

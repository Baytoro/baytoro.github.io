[LLM Inference] RoPE: Position Enters Query and Key

RoPE was the first part of the forward path where I had to slow down. It does not append a position vector to the hidden state. It rotates pairs inside q and k. The shape stays the same, but the dot product between q and k becomes position-aware.

Goal

RoPE sits after q/k projection and before attention scores:

flowchart LR
    x["x
[B, T, D]"] --> qkv["QKV projection"]
    qkv --> q["q
[B, T, H, Dh]"]
    qkv --> k["k
[B, T, H, Dh]"]
    qkv --> v["v
[B, T, H, Dh]"]
    q --> ropeq["RoPE"]
    k --> ropek["RoPE"]
    v --> keep["unchanged"]
    ropeq --> attn["attention"]
    ropek --> attn
    keep --> attn

The key point: RoPE applies to q and k, not v.

Shape Trace

Step Tensor Shape
input q/k x [B, T, H, Dh]
even dims x_even [B, T, H, Dh/2]
odd dims x_odd [B, T, H, Dh/2]
positions positions [T]
frequencies inv_freq [Dh/2]
angles positions[:, None] * inv_freq[None, :] [T, Dh/2]
cos/sin cos, sin [T, Dh/2]
broadcast cos/sin cos[None, :, None, :] [1, T, 1, Dh/2]
output y [B, T, H, Dh]

The broadcast is the part I like to inspect explicitly. The same position table is shared across batch and heads, so [T, Dh/2] expands to [1, T, 1, Dh/2].

Common Pitfalls

First, RoPE does not change shape. If q enters as [B, T, H, Dh], q leaves as [B, T, H, Dh].

Second, RoPE does not rotate v. Attention uses q and k to compute scores; v is the content that gets mixed after the scores are computed.

Third, decode position matters. Reusing start_pos=0 for every generated token makes all decode tokens look like they occupy the same position.

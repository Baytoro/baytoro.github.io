Once the model returns logits, inference still needs a policy for choosing the next token. That policy can be greedy, temperature sampling, top-k sampling, or something more advanced. In this teaching repo I keep it minimal: greedy, temperature, and top-k.

Generation is not one model call. It is a loop around model calls.

Generate With Cache

The cache path separates prefill and decode:

The first sampled token is produced from prefill logits. The next model call consumes that sampled token and appends its K/V to cache.

Shape Trace

Step Model input Logits used for sampling Generated shape
prefill [B, T] [B, V] from logits[:, -1, :] [B, T]
sample 1 none yet [B, V] [B, T+1]
decode 1 [B, 1] next loop uses [B, V] [B, T+1]
sample 2 none yet [B, V] [B, T+2]

The ordering is subtle: sampling happens from the previous logits, then the sampled token is fed into the next decode call if another step is needed.

Common Pitfalls

First, generate() returns the prompt plus new tokens. If the prompt length is T and max_new_tokens = N, the output is [B, T + N].

Second, next_ids should stay [B, 1]. Do not squeeze it into [B], because the model expects a sequence dimension.

Third, with cache enabled, do not feed the entire generated sequence after prefill. Feed only next_ids.

Fourth, top-k changes probability support, not tensor shape.

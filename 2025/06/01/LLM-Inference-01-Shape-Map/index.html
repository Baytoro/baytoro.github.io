This series is my shape-first walkthrough of Llama-style inference. I am not trying to reproduce a production inference engine here. The goal is narrower: if I look at one token batch and one decoder-only Transformer, can I tell where every tensor goes, what each dimension means, and which object gets cached during generation?

The source of truth for the runnable code is the small teaching repo above. The blog version is a more narrative set of notes: what I had to keep straight, where I usually make mistakes, and how I would debug the forward path when a tensor shape does not match.

Goal

The full inference path can be compressed into one sentence:

A decoder-only language model turns token ids with shape [B, T] into logits with shape [B, T, V], then uses the last position [B, V] to choose the next token.

Here is the high-level dataflow:

flowchart LR
    text["text prompt"] --> tok["tokenizer"]
    tok --> ids["input_ids
[B, T]"]
    ids --> emb["token embedding
[B, T, D]"]
    emb --> blocks["L decoder blocks
[B, T, D]"]
    blocks --> norm["final RMSNorm
[B, T, D]"]
    norm --> head["LM Head
[B, T, V]"]
    head --> last["last position
[B, V]"]
    last --> sample["sample / argmax
[B, 1]"]

The main symbols I use throughout the series are:

Symbol Meaning Example
B batch size number of prompts
T sequence length number of tokens in the current forward call
V vocabulary size number of possible next tokens
D hidden size width of the model state
L number of decoder blocks model depth
H query attention heads attention parallel groups
G key/value heads G <= H in GQA
Dh head dimension D / H
F MLP hidden dimension SwiGLU expansion width

The shape convention matters more than it looks. A lot of LLM bugs are not conceptual bugs; they are mistakes like taking softmax over the wrong axis, flattening batch and time too early, or feeding [B] into a decode step that expects [B, 1].

Shape Trace

The first trace I want to keep in my head is the non-cache forward pass.

Step Operation Input shape Output shape What changed
1 tokenizer text [B, T] string becomes integer ids
2 embedding [B, T] [B, T, D] each id gets a learned vector
3 decoder block [B, T, D] [B, T, D] context is mixed, shape preserved
4 final RMSNorm [B, T, D] [B, T, D] normalize hidden states
5 LM Head [B, T, D] [B, T, V] hidden state becomes vocab logits
6 last position [B, T, V] [B, V] only the last token predicts the next token
7 sampling [B, V] [B, 1] choose one next token id

The important invariant is that the Transformer body works in hidden space. The vocabulary dimension V appears only at the LM head. Until then, every block keeps [B, T, D].

Series Map

I will build the forward path in this order:

Post Topic Main shape
1 Shape-first overview [B, T] -> [B, T, V]
2 Embedding and LM Head [B, T] -> [B, T, D] -> [B, T, V]
3 RMSNorm and QKV Projection [B, T, D] -> q/k/v
4 RoPE q/k position rotation
5 Causal Self-Attention [B, H, T, Dh]
6 GQA / MQA H query heads, G KV heads
7 KV Cache [B, G, T_cache, Dh]
8 SwiGLU and TransformerBlock [B, T, D] -> [B, T, D]
9 Decoder-only model L stacked blocks
10 Sampling and generate [B, V] -> [B, 1]
11 Token-by-token trace prefill plus decode loop
12 What the tiny model leaves out production gaps

Common Pitfalls

The first mistake is treating token ids as vectors. They are not. Token ids are integer indices with shape [B, T]. The embedding table is what maps them into dense vectors.

The second mistake is using the whole logits tensor for sampling. During autoregressive generation, the next token is predicted from the last sequence position:

The third mistake is forgetting that generation keeps appending to the sequence. The prompt is not discarded. If the prompt has length T and we generate N new tokens, the final id tensor has shape [B, T + N].

Takeaways

For me, the clean mental model is:

  1. input_ids carry positions and token choices: [B, T].
  2. The Transformer body carries contextual hidden states: [B, T, D].
  3. The LM head returns one distribution per position: [B, T, V].
  4. Generation samples only from the last position: [B, V].

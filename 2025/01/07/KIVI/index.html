KIVI: 2-bit KV Cache Quantization

Paper: KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

KIVI targets the memory that grows with sequence length: KV cache. Weight quantization reduces static model memory, but it does not stop KV cache from dominating long-context serving.

Motivation

For each generated token, every layer stores key and value vectors. Long prompts and large batches make this cache huge. If KV cache can be quantized safely, serving can support larger batches or longer context.

The figure shows the most important empirical observation: keys and values have different outlier patterns. Keys have fixed outlier channels, while values do not show the same channel-wise structure.

Methodology

KIVI uses asymmetric 2-bit quantization but with different granularity:

  • Key cache: per-channel quantization, because a few channels are consistently large.
  • Value cache: per-token quantization, because values are mixed by attention output and do not have the same fixed-channel outlier pattern.

The method also keeps a small residual cache in higher precision for recent tokens. Once enough tokens accumulate, they are quantized and appended to the low-bit cache. This matches the streaming nature of autoregressive decoding.

Results

The paper reports about 2.6x peak KV-cache memory reduction and throughput gains around 2.35x to 3.47x in reported settings, while preserving accuracy across LLaMA, Mistral, and Falcon evaluations.

Takeaway

KIVI is the KV-cache counterpart to GPTQ/AWQ. It does not make weights smaller; it makes long-context serving cheaper. The asymmetric key/value granularity is the important idea because it comes from observed tensor statistics, not a uniform bit-width assumption.

Why Key And Value Need Different Granularity

The key cache is used to compute attention scores. If a few channels are consistently outliers, per-token quantization spreads their error across channels. Per-channel quantization contains that error.

The value cache is used after Softmax as the content mixed into the output. The paper observes no fixed channel-outlier pattern there, so per-token quantization is more appropriate.

This asymmetry is the main technical contribution. A uniform “KV INT2” label would hide the important part.

Residual Cache

Recent tokens are kept in higher precision temporarily. This avoids quantizing very small groups immediately and preserves accuracy for the most recent context. Once enough tokens accumulate, they are quantized in bulk.

Relation To vLLM

PagedAttention improves how KV cache is allocated. KIVI reduces how much memory each KV element consumes. These methods are complementary: one is a memory-management layout, the other is a numeric representation.

Source-Level Notes

KIVI targets KV cache, not model weights. During long-context decoding, KV cache can dominate memory. Quantizing it reduces the number of active tokens and requests that fit in GPU memory.

The asymmetric part is the key observation: keys and values have different quantization behavior. Keys are better quantized per-channel because outliers are channel-structured. Values are better quantized per-token because their error pattern is token-local.

Serving Reading

The residual cache keeps recent KV entries in higher precision before flushing them into the quantized cache. That avoids repeatedly quantizing very fresh tokens and reduces quality loss near the current decode step.

KIVI pairs naturally with vLLM: PagedAttention controls where KV blocks live, while KIVI controls how many bits those blocks consume. Memory layout and numeric representation are separate but complementary problems.

Experiment Reading

The strongest ablation is symmetric versus asymmetric K/V granularity. If per-channel key quantization and per-token value quantization each help for their tensor, using one policy for both should lose accuracy or waste metadata. That validates the paper’s central observation.

Long-context evaluation is essential. For short contexts, KV cache memory may not dominate and quantization error has fewer tokens over which to accumulate. KIVI is really about making long-context serving fit and keeping quality stable as cache length grows.

I would also inspect interaction with attention sinks or special tokens. If certain early tokens remain important across the whole decode, aggressive KV quantization can have a disproportionate effect. Residual high-precision cache helps recent tokens, but older important tokens still need robust quantization.

Reproduction Checklist

I would test key-only, value-only, and both K/V quantization. If key quantization fails under per-token granularity but works per-channel, and value quantization shows the reverse, that reproduces the main asymmetric claim.

A serving benchmark should report maximum context length or batch size under a fixed GPU memory budget. KIVI is about capacity as much as perplexity. If memory savings do not translate into longer context or more concurrent requests, the systems benefit is incomplete.

EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty

Paper

EAGLE is a speculative decoding paper, but the interesting part is not just “use a smaller model to draft tokens.” Its main claim is more specific: for an autoregressive LLM, the feature right before the LM head is a better draft target than the next token itself.

The target model is still the model being sampled. EAGLE only proposes candidate continuations, and the target LLM verifies them with the usual speculative sampling correction. That matters because speedups are only useful if the decoding distribution is preserved.

Motivation

Figure cropped from the paper PDF: EAGLE improves inference latency on MT-bench across Vicuna and LLaMA2-Chat models under greedy decoding.

Speculative decoding tries to reduce the number of expensive target-model forward passes. A draft model proposes several future tokens, then the target model checks them in parallel. If enough draft tokens are accepted, one target forward pass can advance the sequence by more than one token.

The usual failure mode is draft quality. A cheap draft model can be fast, but if its proposal distribution is too different from the target model, many drafted tokens are rejected. Then the target model still has to run often, and the acceleration disappears.

EAGLE attacks this from inside the target model. Instead of training a draft model to imitate final token probabilities directly, it trains a lightweight autoregressive head to predict the target LLM’s second-to-top-layer feature. The frozen target LM head then converts that feature into token logits.

This is a useful framing: token IDs are discrete and jumpy, while high-level hidden features are continuous and usually smoother. If the draft model can predict the next feature well, it can reuse the target model’s own output head rather than learning a separate vocabulary distribution from scratch.

Feature Uncertainty

The paper’s uncertainty example: the next hidden feature depends on which token was sampled, not only on the previous feature.

The paper’s key observation is that feature prediction is ambiguous if the draft model only sees previous features. Suppose two tokens are both plausible under the same distribution. Sampling one token or the other changes the next model state. A feature predictor that does not know which token was sampled is being asked to predict a mixture of futures.

That is the “feature uncertainty” in the title. The future feature is not a deterministic function of the old feature alone. It is conditioned on the sampled token:

EAGLE therefore feeds the draft model a shifted token sequence. In plain terms, after a token is sampled, that token is made visible to the feature predictor before it predicts the next feature. This removes a large part of the multi-modal target and makes feature-level autoregression more stable.

Draft Model

EAGLE’s pipeline: a lightweight draft model predicts features, the frozen LM head produces token candidates, and tree attention lets the method draft multiple branches.

The draft model is trained on hidden features extracted from the target LLM. It takes target-model features plus shifted tokens as input and predicts the next second-to-top-layer feature. The loss is applied in feature space, while the target LM head maps predicted features into token logits during generation.

This design has two consequences:

  • The draft model is tied to the target LLM’s representation space.
  • The generated token distribution still passes through the target LLM’s LM head.
  • The final acceptance step still uses the target model, so the accelerated sampler does not become a different model.

The second point is easy to miss. EAGLE is not just a tiny language model trained on the same text. It is a dynamics model over the target LLM’s internal features.

Greedy And Non-Greedy Decoding

Non-greedy decoding results from the paper: EAGLE keeps useful speedup when sampling is enabled.

Greedy decoding is the cleanest case for acceleration because each step has one next token. Sampling is harder. Once token choice is stochastic, the draft model must cope with multiple possible futures, and the acceptance path can branch.

EAGLE’s shifted-token input is especially important here. It tells the draft model which branch was actually taken before the next feature is predicted. That makes the method better matched to non-greedy generation than a feature predictor that only sees the previous hidden state.

The paper also uses tree-structured drafting. Instead of drafting a single chain only, EAGLE can draft a candidate tree and let the target model verify candidates efficiently. This increases the chance that verification accepts a useful continuation even when sampling produces multiple likely branches.

Main Results

Main result tables from the paper: speedup, average acceptance length, and generation-speed comparisons across model families and tasks.

The reported speedups are strongest when the target model is large and the draft overhead is small relative to a target forward pass. This is the natural regime for speculative decoding: the method is most attractive when target inference is expensive.

The tables also show why acceptance length matters. A headline speedup is not just a property of the draft model’s raw latency. It depends on how many drafted tokens survive target verification. Better feature prediction increases the average accepted length, which then reduces the number of target passes needed per generated token.

Ablations

Input ablation from the paper: using both features and shifted tokens gives the strongest draft behavior.

The ablation is one of the most useful figures in the paper. A token-only draft loses the representational advantage of feature prediction. A feature-only draft still suffers from uncertainty because it does not know which sampled token led to the current state. The combination of feature plus shifted token is the point.

This is also the best mental model for EAGLE:

  1. Predict in a smoother internal space.
  2. Condition on the actual sampled token to avoid ambiguous futures.
  3. Use the target LM head and target verification to preserve the original sampler.

Verification Algorithm

Algorithm excerpt from the paper PDF: multi-round speculative sampling still performs acceptance and correction through the target model.

The verification step is what separates speculative decoding from approximate decoding. The draft model is allowed to be wrong. When it is wrong, the target model corrects the sample according to the speculative sampling rule.

That makes EAGLE a serving optimization rather than a model replacement. You pay extra engineering complexity for lower latency, but the semantic contract remains: samples should follow the target LLM distribution.

Reading Notes

EAGLE is most compelling when the serving stack can access target-model internals. If the target LLM is only available through a black-box API, feature-level drafting is not practical. It also requires training and maintaining a draft model for the target model’s hidden representation.

The paper’s useful contribution is the uncertainty argument. Speculative decoding papers often focus on draft-model size or tree width, but EAGLE points out that the draft target itself matters. Token prediction, feature prediction, and feature prediction with shifted tokens are different learning problems.

My takeaway: EAGLE works because it treats decoding as short-horizon state extrapolation inside the target model. It is not just faster guessing. It is a model-aware draft that uses the target LLM’s own feature geometry, output head, and verifier.

INQ: Incremental Network Quantization

H.J. Chen
  2023-05-28 2023-05-28 Created  
  • Paper Reading

Paper: Incremental Network Quantization: Towards Lossless CNNs with Low-Precision Weights

INQ is a useful paper to reread because it makes a simple point that still matters in modern quantization: low-bit conversion is not just a scalar rounding problem. It is also an optimization and scheduling problem. If every weight in a trained model is snapped to a small codebook at the same time, the network receives a large structured perturbation. If only part of the weights are quantized, frozen, and then the remaining weights are allowed to retrain, the model can gradually absorb that perturbation.

The paper is from ICLR 2017 and focuses on CNN weight quantization. It does not solve activation quantization, transformer quantization, KV-cache quantization, or post-training LLM compression. Its setting is narrower: start from a pre-trained full-precision CNN, convert all weights into zero or signed powers of two, and use retraining to keep ImageNet accuracy close to the original model. The narrowness is exactly why the idea is clean.

What Problem INQ Solves

The deployment target assumed by INQ is hardware where multiplication by a weight can become a cheap sign change plus a bit shift. That requires the non-zero weights to be powers of two. A normal uniform INT8 or INT4 codebook does not have this property; it is friendly to integer matrix multiply units, but not specifically to shift-based multiplication.

So the paper asks for a constrained model:

  • every final weight is either zero or a signed power of two;
  • the number of candidate values is controlled by an expected bit-width;
  • the final quantized CNN should have little or no accuracy loss compared with the 32-bit reference;
  • retraining is allowed during the quantization process.

The “accumulated” wording matters. A stage does not quantize 75 percent more weights; it extends the frozen set until the frozen set reaches 75 percent of that layer.

Partition Strategy

The default partition rule is pruning-inspired: quantize larger-magnitude weights first. The paper’s intuition is that large weights define a stable low-precision backbone, while small and medium weights still have room to absorb residual error during retraining.

This is related to pruning, but the meaning is different. In pruning, small weights are often removed first because they are assumed to be less important. In INQ, large weights are quantized first because the authors want the main structure of the network to become fixed early. The remaining weights act as a correction buffer.

The paper compares this rule against random partition on ResNet-18:

Random partition gives 32.11 percent top-1 error and 11.73 percent top-5 error. The pruning-inspired schedule gives 31.02 percent top-1 error and 10.90 percent top-5 error. Since lower error is better, this is a meaningful gap for such a small design choice.

My reading is that this result is less about magnitude being a perfect importance metric and more about ordering. Quantization error is not independent noise. The order in which parameters are frozen changes the optimization path.

ImageNet 5-Bit Results

The headline result is 5-bit weight quantization on common CNNs:

The numbers are reported as top-1 and top-5 error rates on ImageNet validation center crops. INQ improves or preserves the reference model in all five cases:

  • AlexNet moves from 42.76 percent top-1 error to 42.61 percent.
  • VGG-16 moves from 31.46 percent to 29.18 percent.
  • GoogLeNet moves from 31.11 percent to 30.98 percent.
  • ResNet-18 moves from 31.73 percent to 31.02 percent.
  • ResNet-50 moves from 26.78 percent to 25.19 percent.

The VGG-16 and ResNet-50 improvements are large enough that I would not read them as “quantization is inherently regularizing” without caution. The baseline models, training recipe, Caffe conversions, and fine-tuning schedule all matter. The safe claim is narrower: after staged retraining, 5-bit power-of-two weights did not hurt these reported ImageNet models.

That is still a strong result for 2017. The method is weight-only, but it shows that a very restrictive codebook can work if the conversion schedule gives the model enough adaptation capacity.

  • 4-bit INQ: 31.11 percent top-1 error, still better than the reference.
  • 3-bit INQ: 31.92 percent top-1 error, slightly worse than the reference.
  • 2-bit ternary INQ: 33.98 percent top-1 error, now noticeably worse but still much better than earlier ternary baselines in the paper.

The schedule becomes longer as bit-width decreases. The paper uses more incremental stages for 4-bit, 3-bit, and 2-bit ternary models because the codebook becomes more restrictive. This is a useful practical lesson: lower precision does not only need a different codebook; it usually needs a different training schedule.

This is also where the “expected bit-width” terminology matters. A power-of-two codebook can be compactly encoded, but the real model size depends on pruning sparsity, index storage, and any entropy coding used after quantization.

The expected bit-width controls the candidate codebook, while the layer-wise maximum and distribution determine which exponent values are actually used.

The table also shows that zero is not rare. For example, the convolutional layers keep a non-trivial mass at zero after quantization. That means INQ is not just “round each weight to the nearest power of two”; it also creates a sparse-ish distribution because small weights fall below the representable threshold.

For debugging an implementation, this table suggests several checks:

  • verify that each layer’s non-zero values are exactly signed powers of two;
  • verify that frozen weights do not move after the mask is applied;
  • count how many exponent bins are actually occupied per layer;
  • monitor the zero fraction after every incremental stage, not only at the end.

This is encouraging, but I would treat it as a small extension rather than the core contribution. Activation quantization has different failure modes: dynamic ranges are input-dependent, calibration matters, and hardware kernels care about activation layout and accumulation precision.

Relation To Later Quantization Methods

INQ is not the method I would use directly for current LLM quantization. It requires retraining data and many training iterations, while common LLM workflows often demand post-training quantization from a checkpoint and a small calibration set. Still, the optimization lesson survives:

  • GPTQ quantizes weights sequentially and uses a Hessian approximation to update the remaining weights.
  • AdaRound chooses rounding directions by minimizing reconstruction error instead of using naive nearest rounding.
  • BRECQ reconstructs blocks so that local output error, not just scalar weight error, drives quantization.
  • AWQ protects activation-salient weights because not all weights should be treated equally.

These methods are different technically, but they avoid the same failure mode as INQ: simultaneous local rounding can create global model error that the network cannot absorb.

The biggest conceptual difference is the source of adaptation. INQ adapts by retraining the still-full-precision weights. GPTQ adapts by an approximate second-order compensation update. AdaRound and BRECQ adapt by reconstruction objectives. AWQ adapts the scale/search process around salient channels. The shared theme is controlled error absorption.

The most likely implementation bugs are mask bugs. If a frozen quantized weight receives even one normal SGD update, it is no longer guaranteed to stay in . In PyTorch, I would explicitly reapply the frozen quantized values after every optimizer step or store frozen and trainable tensors separately. Relying only on gradient masking can be fragile when weight decay, momentum buffers, or optimizer state are present.

Learning-rate resets are another detail from Algorithm 1 that should not be ignored. Each quantization stage changes the optimization landscape. Restarting the base learning rate and policy gives the remaining trainable weights a chance to compensate for the new frozen error.

Limitations

The first limitation is cost. INQ is not a calibration-only method. It needs training data and repeated fine-tuning. That makes it less suitable for large models when retraining is expensive or impossible.

The second limitation is the codebook. Powers of two are attractive for shift-based hardware, but modern accelerators often provide efficient dense INT8/INT4 arithmetic. On such hardware, a uniform or group-wise affine format may be more practical than a power-of-two codebook.

The third limitation is that the partition heuristic is simple. Magnitude is a reasonable signal, but it is not the same as sensitivity. Later methods use curvature, reconstruction loss, activation statistics, or channel salience because large scalar magnitude alone does not fully describe quantization damage.

Finally, the paper’s strongest results are on CNNs. CNN weight distributions, batch normalization behavior, and retraining recipes are not the same as transformers. The idea of gradual error absorption transfers, but the exact method should not be copied blindly into LLM compression.

Takeaways

The part I want to remember from INQ is not just “power-of-two quantization.” The more durable idea is:

INQ’s schedule is easy to explain: quantize important weights first, freeze them, retrain the rest, and repeat. That simple loop is enough to make 5-bit power-of-two CNN weights work surprisingly well in the paper’s ImageNet experiments.

For modern work, I would treat INQ as an ancestor of more sophisticated sequential and reconstruction-based quantizers. It is old, but it teaches the right instinct: do not judge a quantizer only by the scalar distance between and . Judge it by whether the network has a mechanism to absorb the structured error created by that choice.

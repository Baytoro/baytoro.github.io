INQ: Incremental Network Quantization

Paper: Incremental Network Quantization: Towards Lossless CNNs with Low-Precision Weights

INQ is an old paper, but it is still a useful baseline because it makes one point very clearly: low-bit weight quantization is not only a representation problem. It is also an optimization schedule problem. If all weights are snapped to a codebook at once, the network loses too many degrees of freedom. If only part of the model is quantized and the rest is allowed to adapt, the error can be absorbed gradually.

Motivation

The target is CNN weight compression. The paper is not trying to quantize activations, LayerNorm, KV cache, or transformer blocks. It focuses on weights and asks whether a trained network can be converted into a low-precision representation without losing accuracy.

The codebook is hardware-friendly: non-zero values are powers of two. Multiplication by a quantized weight can be implemented with sign changes and bit shifts. The difficult part is selecting which value each weight should take while preserving task accuracy.

The figure shows the incremental procedure: partition weights, quantize one partition, freeze it, retrain the rest, and repeat until all weights are fixed to the low-precision set.

The algorithm has three repeated steps:

  1. Weight partition. Decide which weights should be quantized in this round. The paper’s default rule is magnitude-based: larger weights are quantized first.
  2. Group-wise quantization. Map the selected weights to the nearest value in the power-of-two codebook.
  3. Retraining. Keep quantized weights frozen and update the remaining full-precision weights with backpropagation.

A subtle point: the magnitude rule is not just a heuristic for importance. By freezing large weights first, the method fixes the high-signal part of the network and leaves small weights to absorb the residual error. This is close in spirit to gradual pruning schedules, except the frozen weights are not removed; they are constrained to a cheap representation.

Results

The paper reports experiments on AlexNet, VGG-style networks, GoogLeNet, and ResNet. The main result is that 5-bit weight quantization is close to lossless, and in some cases the retrained quantized model slightly outperforms the original model. At lower bit-widths, the incremental schedule degrades much more gracefully than direct one-shot rounding.

The result should be read carefully. INQ is weight-only, so the end-to-end speedup depends on whether the inference backend can exploit power-of-two weights. It also assumes retraining is allowed. This is different from later post-training quantization papers, where the model may be quantized with only a small calibration set.

What I Remember

INQ is not the method I would use for current LLM compression, but its optimization lesson keeps reappearing:

  • GPTQ quantizes weights sequentially and updates the remaining weights using a Hessian approximation.
  • BRECQ reconstructs blocks instead of snapping all layers independently.
  • AWQ protects a small set of activation-salient channels instead of treating all weights uniformly.

All of these methods avoid the same failure mode: quantization error is structured, and the model needs a controlled way to absorb it. INQ is the simple staged version of that idea.

Reading Notes

There are two details worth checking in the paper instead of only remembering the name.

First, the quantization set is not an arbitrary low-bit grid. It is power-of-two based. That means the method is optimizing for a hardware model where multiplication can be replaced by shift operations. If the target hardware already has fast dense INT8/INT4 matrix multiply, this power-of-two choice may not be the best modern format. The codebook is tied to the deployment assumption.

Second, the partition schedule is doing real work. If the largest weights are quantized first, then subsequent retraining changes the smaller remaining weights to compensate. This is different from a sensitivity method such as HAWQ: INQ does not estimate curvature, but it still imposes an ordering on which errors the network must absorb first.

One way to think about it is:

Stage Frozen part Trainable part Role
early largest weights small/medium weights stabilize high-magnitude structure
middle more weights remaining weights absorb accumulated error
final all weights none or short fine-tune fixed low-bit model

The limitation is obvious from this table: INQ needs retraining. If a deployment setting only gives a model checkpoint and a small calibration set, INQ is not directly applicable. That is why later PTQ methods became more important for foundation models.

The important detail is that INQ does not quantize every weight at once. It partitions weights into a frozen quantized group and a still-trainable full precision group. Large-magnitude weights are quantized first because they usually encode more stable structure; smaller weights are allowed to adapt during retraining. That incremental schedule is what makes the method less destructive than direct power-of-two rounding.

What I Would Reproduce

If I were implementing this today, I would first reproduce the three-stage loop on a small ResNet: partition, quantize, retrain. The useful diagnostic is not only final accuracy, but also how the histogram of unquantized weights shifts after each stage. If the remaining full precision weights do not compensate for the frozen group, the next partition will amplify error.

The method is not a modern LLM quantizer, but it is still a clean baseline for understanding why quantization is often an optimization problem, not a one-shot encoding problem. AdaRound, BRECQ, and GPTQ all keep this lesson: a quantized weight should be chosen with downstream error in mind, not only nearest scalar distance.

MnasNet: Platform-Aware Neural Architecture Search for Mobile

H.J. Chen
  2020-06-24 2020-06-24 Created  
  • Work hard 
  • >
  • PaperReading 
 
  • NAS 
  • | Mobile 

Tan M, Chen B, Pang R, et al. MnasNet: Platform-Aware Neural Architecture Search for Mobile. CVPR 2019.

Paper

MnasNet is a turning point for hardware-aware NAS. Earlier image-classification NAS papers mostly optimized accuracy and reported FLOPs afterward. MnasNet puts measured mobile latency directly into the reward.

This matters because FLOPs are a poor proxy for mobile inference. Two operators with similar FLOPs can have very different latency depending on memory access, kernel implementation, and hardware.

Multi-Objective Reward

MnasNet uses an RL controller to sample architectures. The reward combines accuracy and latency:

Here (T) is the target latency and (w) controls how strongly latency is penalized. When a model exceeds the target, the reward drops. When it stays within the target, the search can focus more on accuracy.

The figure shows both the platform-aware search loop and the accuracy-latency tradeoff. The key signal is that latency is measured on real mobile phones rather than inferred from FLOPs.

Factorized Hierarchical Search Space

Searching every layer independently would be too large. MnasNet splits the network into stages and searches block-level choices:

  • inverted bottleneck block type;
  • kernel size;
  • expansion ratio;
  • number of layers;
  • output channels;
  • skip connection behavior.

This gives more flexibility than MobileNetV2 while keeping the space manageable.

Measurement Protocol

The most important reproduction detail is latency measurement. Device model, runtime, thread count, warmup, and batch size all affect the result. Since the reward uses latency directly, noisy latency measurements become noisy architecture labels.

This is the practical difference between hardware-aware NAS and paper-only FLOPs optimization.

Results

MnasNet reports a better ImageNet accuracy-latency Pareto frontier than MobileNetV2 and NASNet mobile models under Pixel-phone latency constraints. It also became a direct predecessor of MobileNetV3.

Takeaway

MnasNet changes the NAS question from “Which architecture is most accurate?” to “Which architecture is best for this platform under this latency target?” That is the right question for deployment-oriented model design.

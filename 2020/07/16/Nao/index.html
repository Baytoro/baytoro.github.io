Neural Architecture Optimization

H.J. Chen
  2020-07-16 2020-07-16 Created  
  • Paper Reading 
 
  • NAS 

Luo R, Tian F, Qin T, et al. Neural Architecture Optimization. NeurIPS 2018.

Paper / Code / PyTorch Code

NAO is an interesting NAS paper because it does not search directly in the discrete architecture space, and it also does not relax every edge operation into a DARTS-style mixture. It learns a separate continuous representation of architecture strings. Once an architecture is embedded into that space, NAO uses a performance predictor to define a differentiable surface, moves the embedding in the direction of higher predicted accuracy, and then decodes the moved point back into a discrete architecture.

The useful mental model is:

  1. a discrete cell is serialized as a token sequence;
  2. an encoder maps that sequence into continuous hidden states;
  3. a predictor learns a dev-accuracy surface over the hidden states;
  4. a decoder reconstructs a valid architecture from hidden states;
  5. search is done by gradient ascent on the predictor, not by sampling a controller action.

Figure 1. The core loop of NAO: encode a cell architecture, move its embedding on the learned predictor surface, then decode the optimized embedding into a new architecture.

The paper is from the same era as ENAS, PNAS, AmoebaNet, and DARTS, so the reported compute is not directly comparable to modern NAS practice. But the formulation is still worth reading. NAO makes a concrete attempt to turn “architecture search” into “architecture representation learning plus gradient optimization”.

Problem Setting

NAS has a difficult search space: the architecture is discrete, the evaluation is expensive, and a local edit in the string representation may or may not be a local edit in model behavior. Earlier methods typically used reinforcement learning, evolutionary search, Bayesian optimization, or progressive search. NAO asks a different question: can we learn an embedding space in which gradient steps are meaningful?

Encoder, Predictor, Decoder

NAO has three learned components. They are trained together, but each has a different job.

The encoder maps a discrete architecture string into a continuous representation:

How I read this formula: the architecture is first treated like a sentence. A single-layer LSTM reads the token sequence, and the hidden state at every token position is kept. NAO does not collapse the architecture into one scalar or one one-hot vector. It keeps a sequence of hidden states so the decoder can attend to different parts of the original structure.

The predictor maps the architecture embedding to predicted dev performance:

How I read this formula: the predictor only sees a mean-pooled version of the encoder hidden states. This makes the predictor simpler than the decoder. It does not need to reproduce the architecture token by token; it only needs a representation good enough to rank or regress performance. The target is the measured dev-set accuracy after training that child architecture.

How I read this formula: the decoder is autoregressive. It predicts token using the embedding and previously generated tokens. This is important because the decoder is not just producing a vector. It must output a complete architecture string that satisfies the grammar of the search space.

The paper also uses a small but important symmetry trick. If two architecture strings only differ by swapping the two branches inside a node, they describe the same computation. NAO augments training data with such symmetric strings and the same score. This pushes the encoder and predictor toward permutation invariance and gives roughly a 2% pairwise-accuracy gain in their CIFAR-10 predictor diagnostic.

The algorithm has a clean outer loop:

  1. start from an initial candidate set;
  2. train and evaluate those architectures to get real dev scores;
  3. train , , and with the joint loss;
  4. choose the top- architectures as seeds;
  5. apply the gradient step to their embeddings;
  6. decode the moved embeddings into new architectures;
  7. evaluate the new architectures and repeat.

One practical detail I like: if the decoded architecture is exactly the same as the seed, the paper increases the step size until the decoder emits a different architecture. That is a heuristic, but it exposes a real problem. The latent update is only useful if it crosses a decoder decision boundary without jumping into a nonsensical region.

Diagnostics

NAO needs two things to be true: the predictor must rank architectures usefully, and the decoder must reconstruct architecture strings reliably. The paper checks both.

For NAS, ranking can be more relevant than absolute regression error because search mostly needs to know which candidate is better.

For the decoder, it measures average Hamming distance between the decoded string and the original string:

How I read this formula: this is a reconstruction check. If the decoder cannot recover the original architecture from its own encoder output, then decoding a moved point is even less trustworthy. The paper reports that with about 500 evaluated architectures, the predictor reaches more than 78% pairwise accuracy and the decoder’s average Hamming distance is below 0.5 tokens out of 60.

Figure 2. Left: predictor pairwise accuracy rises while decoder reconstruction distance drops. Right: the mean dev accuracy of generated candidates improves over NAO iterations, and predicted mean accuracy tracks the real value.

The right plot is the more important sanity check. It shows that candidates generated in later NAO iterations have higher measured dev accuracy, not just higher predicted accuracy. That does not prove the learned space is globally smooth, but it supports the claim that the local gradient step is doing useful work within the explored region.

Weight Sharing Variant

The original NAO loop still trains many child architectures from scratch. The authors also combine NAO with ENAS-style weight sharing. The idea is simple: keep the ENAS one-shot training pipeline, but replace the RL controller with the NAO encoder-predictor-decoder. This attacks a different part of the cost:

  • NAO reduces the search algorithm’s dependence on random controller sampling by optimizing in embedding space.
  • Weight sharing reduces child-model evaluation cost by reusing parameters in a supernet.

This distinction matters when reading the result tables. “NAONet” usually means the architecture was searched without weight sharing and then trained normally. “NAONet-WS” means the architecture was found with weight sharing.

This is far fewer than AmoebaNet’s reported 20000 to 27000 evaluated models, but still expensive because each candidate is trained as a small standalone network.

Transfer To CIFAR-100 And ImageNet

The paper transfers the best CIFAR-10-discovered CNN cell to CIFAR-100 and ImageNet. This is important because NAS methods can overfit to a benchmark’s search/evaluation protocol. Transfer is a better test of whether the cell is a useful architecture pattern rather than a CIFAR-10 artifact.

On ImageNet, NAONet is competitive but not dominant. It reports 25.7% top-1 error, close to PNAS and AmoebaNet-A, worse than AmoebaNet-C, and better than the DARTS row shown in the paper. It also uses 11.35M parameters, which is larger than many rows in the table. My takeaway is that the discovered cell transfers, but the comparison is not just accuracy; parameter count and search budget both matter.

Language Modeling Results

NAO also searches an RNN cell on Penn Treebank. This part is useful because it shows the method is not tied to convolutional cells. The search string changes, but the encoder-predictor-decoder framework is the same.

Table 4. Penn Treebank language modeling. NAONet reaches 56.0 test perplexity, while NAONet-WS reaches 56.6 with much lower search cost.

The PTB results have the same tradeoff pattern as CIFAR-10. Full NAONet reports 56.0 test perplexity with 300 GPU days. NAONet-WS reports 56.6 perplexity with 0.4 GPU days. DARTS is very close at 56.1 with 1 GPU day. So the best NAO number is strong, but the weight-sharing version is the more practical row.

Discovered Architectures

The appendix plots the final CNN and RNN cells. These pictures are useful because they remind me that NAS papers are often searching within a very specific grammar. NAO does not invent an arbitrary neural network. It searches wiring and operation choices inside a cell template.

Figure 3. CNN cells discovered by NAO. The upper graph is the normal cell, and the lower graph is the reduction cell.

The CNN cells contain many pooling and asymmetric-convolution choices. The normal cell has several skip-like paths and concatenates unused nodes at the output. The reduction cell has a different routing pattern and more pooling operations, which makes sense because reduction cells are expected to change spatial resolution.

Figure 4. RNN cell discovered by NAO for Penn Treebank.

The RNN cell is mostly ReLU nodes, with tanh at the entry and another internal node, plus a sigmoid node near the upper middle. The final output is an average over the node outputs. I would not try to over-interpret every edge, but the figure is still helpful: the searched cell is a sparse directed computation graph, not a standard LSTM gate layout.

What I Would Watch Carefully

NAO is conceptually clean, but its success depends on several fragile assumptions.

First, the predictor gradient is only useful if the predictor learned a smooth local surface. A high predictor score after the update is not enough; the decoded architecture must also evaluate well. This is why Figure 2(b) is more convincing than only reporting predictor loss.

Second, decoder reliability is central. If the decoder has high reconstruction error, then the latent space is not a stable architecture space. A moved embedding may decode to an arbitrary valid architecture rather than a small improvement over the seed.

Third, the search cost accounting needs attention. NAONet without weight sharing evaluates 1000 architectures for CIFAR-10 and uses a large GPU pool. NAONet-WS is much cheaper, but then the comparison is partly about the ENAS-style weight-sharing setup.

Fourth, the final model scale changes the story. The best CIFAR-10 number uses a very large model with 144.6M parameters. The smaller rows are more informative when comparing cell quality under realistic parameter budgets.

Takeaway

The core contribution of NAO is not just “use an accuracy predictor.” The key idea is to train a reversible-ish architecture representation: encode a discrete cell, learn a performance surface over the embedding, take a gradient step, and decode the result back to a legal architecture.

I see NAO as a bridge between black-box NAS and differentiable NAS. Unlike RL or evolution, it explicitly optimizes a learned continuous space. Unlike DARTS, the continuous variables are not operation mixture weights inside a supernet; they are architecture embeddings learned by an encoder-decoder model. That makes the method more flexible, but also puts a lot of pressure on representation quality.

The paper is worth remembering for this design pattern: if a discrete object is hard to optimize directly, learn a continuous space that can reconstruct the object and supports a task-specific gradient.

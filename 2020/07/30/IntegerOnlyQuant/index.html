Integer-Arithmetic-Only INT8 Inference

H.J. Chen
  2020-07-30 2020-07-30 Created  
  • Paper Reading 
 
  • Quantization 

Paper: Quantization and Training of Neural Networks for Efficient Integer-Arithmetic-Only Inference

This is one of the papers I keep as the reference point for deployment-oriented quantization. It is not only about storing weights in fewer bits. The paper pins down a full arithmetic contract for inference: 8-bit inputs and weights, int32 accumulation, int32 bias, integer-only requantization, and training-time fake quantization that matches the deployed graph.

The target is mobile CPU inference. If a model is compressed to 8-bit but repeatedly dequantizes to float between layers, the memory footprint improves, but the runtime still depends on floating-point kernels. Jacob et al. instead ask for a graph that can run with integer arithmetic all the way through the convolution block.

Figure 1.1 is a compact summary. The inference graph has uint8 inputs and weights, a conv node that accumulates into int32, int32 bias addition, ReLU6 in quantized space, and uint8 output. The training graph remains float, but inserts weight and activation quantization nodes so the forward pass sees the rounding and clipping errors that inference will see.

Quantization-Aware Training

The paper uses simulated quantization during training. In the forward pass, weights and activations are rounded and clipped as if they were low precision. In the backward pass, training keeps using the usual floating-point machinery, with the quantization node acting like a straight-through approximation for gradients.

BatchNorm folding is also part of the deployment story. A Conv + BatchNorm block is converted into a convolution with folded weights and folded bias before quantization. Otherwise an integer graph would still contain a floating-point normalization island.

One practical detail I like: the authors sometimes delay activation quantization at the start of training. For detection, this avoids forcing a still-unstable model through activation clipping too early. It is a small training recipe detail, but it explains why reproducing QAT is not just “insert fake quant nodes and train normally”.

ImageNet Classification

The ResNet result is the first sanity check. The integer model loses accuracy, but the drop is small enough to be useful.

For ResNet-50, top-1 goes from 76.4% to 74.9%. For deeper variants, the quantized models stay around 76.6%-76.7%. This is not a zero-cost conversion, but it is far from the accuracy collapse that earlier very-low-bit schemes often caused.

Table 4.2 is a useful comparison because several older schemes keep activations in float. The proposed method uses 8-bit weights and 8-bit activations and still reaches 74.9% on ResNet-50. That matters more for deployment than weight compression alone: the activation path and the rescale path also have to be implementable by integer kernels.

The Inception v3 experiment is a good reminder that activation choice affects quantization.

With ReLU6, the 8-bit model reaches 75.4% top-1; with unbounded ReLU, it reaches 74.2%. ReLU6 gives the quantizer a natural activation range. The paper is not claiming ReLU6 is universally better, but for MobileNet-era CNN deployment it made the activation dynamic range much easier to manage.

Latency-Accuracy Tradeoff

The paper is strongest when it plots accuracy against real mobile latency. The curves are more informative than one isolated accuracy number.

On Snapdragon 835 big cores, the 8-bit MobileNet points are generally above the floating-point points at similar latency. This is the result the paper is aiming for: not “same model, slightly faster”, but a better operating frontier when model width and quantization are considered together.

The Snapdragon 821 curve is closer, which is also useful. Quantization is not a purely mathematical improvement; it depends on the available kernels and hardware. A method that looks excellent on one CPU can be less dramatic on another if the integer path is not as favorable.

Detection Results

The COCO detection table shows why the paper was important for mobile models. The 50% MobileNet SSD variant drops only from 16.7 to 16.6 mAP, while latency on big cores goes from 121 ms to 61 ms. On LITTLE cores it goes from 270 ms to 146 ms.

For the 100% model, the mAP drop is 22.1 to 21.7, with big-core latency improving from 370 ms to 272 ms. The smaller model benefits more, which matches the paper’s mobile-first target: compact models are the ones where latency budgets are tightest.

The face detection results tell the same story from another task.

Precision and recall move only slightly after quantization. The 100% detector goes from 68/76 to 66/75 precision/recall, and the 25% detector goes from 56/64 to 54/63.

The latency table is more dramatic. For the 100% detector, one big core goes from 337 ms in float to 154 ms in 8-bit. With four big cores, the 8-bit model reaches 69 ms. The paper also reports multi-core numbers for 8-bit, which is important because deployment code has to scale across the actual CPU configuration, not only a single benchmark thread.

Bit-Width Sensitivity

The paper also checks face attribute classification, where the 8-bit points again improve the latency-precision frontier.

The face attribute ablation is useful because it separates weight bit depth from activation bit depth.

The trend is asymmetric. Going from 8 to 7 bits is mostly fine. Dropping weights below 7 bits hurts quickly, especially at 4 bits. Activations can sometimes tolerate 6 bits better than weights, but the age precision table becomes worse when activation or weight precision is pushed too far. This matches the practical rule I usually use: before chasing very low bits, first make sure the 8-bit arithmetic path is exact and stable.

Runtime Checklist

The affine equation is short, but the runtime has many places to go wrong:

  • padding must use the activation zero-point, not integer zero unless they happen to match;
  • bias must use the input-scale times weight-scale accumulator scale;
  • requantization must use fixed-point integer multiply and shift, not hidden float math;
  • BatchNorm has to be folded before quantization;
  • fused activations such as ReLU and ReLU6 should clamp in quantized space;
  • add, concat, and residual-style operators need compatible quantization ranges or explicit rescaling.

This is why I read the paper as a systems paper, not just a quantization paper. The math is deliberately simple because the hard part is making the graph, the training recipe, and the kernel implementation agree.

Relation To Later Work

Later papers extend the same idea in different directions. Q8BERT and I-BERT apply integer-aware thinking to Transformer models, but they need additional approximations for GELU, Softmax, LayerNorm, and attention. Weight-only LLM quantization solves a different problem: it reduces memory bandwidth and model size, but it does not automatically remove floating-point activation and normalization paths.

Jacob et al. are still the baseline I use when checking a quantization method. The first question is not “what is the average bit-width?” It is: where are the scales, where is real zero, what is the accumulator type, and can the whole deployed graph avoid floating-point islands?

Takeaway

The paper’s contribution is the complete INT8 contract. It defines a quantization format, shows how to train against that format, maps convolution to int32 accumulation plus fixed-point requantization, and validates the result on real mobile latency. That combination is why this paper became the reference for practical CNN quantization.

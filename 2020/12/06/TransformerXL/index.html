Paper: Transformer-XL: Attentive Language Models Beyond a Fixed-Length Context

Code: kimiyoung/transformer-xl

Transformer-XL is an early long-context Transformer paper that is still worth reading carefully. The idea is not simply “make the context longer.” The paper identifies two concrete failures in fixed-length Transformer language models:

  • context fragmentation: training cuts a long corpus into short independent segments, so information cannot flow across segment boundaries;
  • evaluation recomputation: a vanilla Transformer can use a sliding window at inference, but each shifted window has to be recomputed from scratch.

Transformer-XL fixes both with a recurrence over segment hidden states. The model caches hidden states from previous segments, reuses them as memory for the next segment, and changes positional encoding from absolute positions to relative distances so the cached states remain positionally meaningful.

All crops below are taken from the original 2019 PDF.

Fixed-Length Transformer LM

A vanilla Transformer language model can only attend inside the segment it is currently processing. If the segment length is , the largest direct dependency visible to the model is bounded by , even if the original article is thousands of tokens long.

Figure 1. Vanilla Transformer LM training and evaluation with segment length 4. Training sees independent segments. Evaluation can slide the segment one token at a time, but that recomputes the whole segment repeatedly.

This has two different costs.

First, training loses cross-segment context. The first tokens of each segment are predicted with little left context even if the previous segment contained exactly the information needed. This is what the paper calls context fragmentation.

Second, evaluation is expensive. To give each prediction the longest context seen during training, a vanilla model evaluates a full length- segment, predicts only the last position, shifts the window by one token, and evaluates another full segment. That procedure uses context, but it throws away almost all computation from the previous step.

For a decoder-only model this is an unnatural use of self-attention. The hidden states for old tokens do not change when the next token arrives. Transformer-XL turns that observation into a recurrent state.

Segment-Level Recurrence

Transformer-XL processes a stream as consecutive segments, but it does not discard the previous segment’s hidden states. For each layer, it stores the hidden state sequence from previous segments as a memory and concatenates that memory with the current segment when forming keys and values.

This is similar in spirit to truncated BPTT for RNNs, but the stored state is different:

Model family Reused state What is truncated
RNN-LM with truncated BPTT Usually the last hidden state Gradient through time
Transformer-XL A sequence of hidden states per layer Gradient across segments
Modern KV-cache decoding Projected keys and values per layer Usually no training gradient, inference only

Transformer-XL is not exactly the same abstraction as the modern KV cache. The paper describes caching hidden states and then using them to form keys and values for the next segment. But conceptually it is one of the clean ancestors of state reuse in decoder-only Transformers: do not recompute old token representations when the new segment only needs to attend to them.

Training And Evaluation Behavior

During training, the previous memory is fixed. Gradients do not propagate into old segments:

The stop-gradient choice is a practical compromise. It keeps training close to ordinary segment training in memory cost, while letting each segment condition on previous segments in the forward pass.

During evaluation, the memory can be longer than one previous segment. The paper uses a memory length and a segment length , so each segment can attend over positions. The old representations are reused instead of recomputed. This is where the large evaluation speedup comes from: the model still attends to history, but it does not run all layers again for every shifted window.

The causal mask has to cover two regions:

  • memory positions are always in the past, so current tokens may attend to them;
  • inside the current segment, token may attend only to positions up to .

That mask is what makes chunked stream processing equivalent to autoregressive modeling rather than leaking future tokens.

Why Absolute Position Breaks Memory Reuse

Caching hidden states alone is not enough. If a Transformer uses absolute positional embeddings, then each segment reuses the same position indices . Token in the previous segment and token in the current segment both carry the same absolute position even though their relative distance to the query is different.

For recurrence, the model needs to know where a memory token is relative to the current query, not where that token sat inside its original segment.

The paper makes this precise by decomposing the absolute-position attention score:

The four terms can be read as:

Term Role in absolute attention
content-to-content addressing
content query to absolute key position
absolute query position to key content
absolute query position to absolute key position

Those and terms are tied to positions inside a segment. They do not survive state reuse cleanly.

Relative Positional Encoding

Transformer-XL replaces absolute positional dependence with relative distance dependence. The new attention score is:

Here is a sinusoidal relative positional encoding for the distance between the query position and the key position . The learned vectors and replace the absolute query-position terms with global content and position biases.

The four relative terms have a useful interpretation:

Term Meaning
(a) content-based addressing Which token content should this query attend to?
(b) content-dependent positional bias Given this query content, which relative distances are useful?
(c) global content bias Which key contents are generally important?
(d) global positional bias Which relative distances are generally important?

The comparison to Shaw et al. (2018) is important. Shaw-style relative attention mainly keeps terms (a) and (b), and it uses learned relative embeddings. Transformer-XL keeps two additional bias terms and uses sinusoidal relative encodings. The paper argues that the sinusoidal structure helps the model generalize to longer memory at evaluation time than it saw during training.

There is also an implementation issue. Naively computing for every pair would be quadratic in the number of pairwise distances. Appendix B shows the usual efficient trick: compute the relative logits as a matrix product over all possible distances, then shift rows so each query sees the correct relative offset. In later codebases this family of operations is often called a relative shift.

What The Architecture Actually Buys

It is useful to separate the two proposed pieces:

Piece Main purpose Without it
Segment-level recurrence Reuse past hidden states and extend context beyond one segment Context is fragmented and evaluation recomputes old segments
Relative positional encoding Make cached states positionally coherent Memory states carry stale absolute positions

The recurrence solves the systems and context problem. The relative position scheme makes the recurrence mathematically usable.

This is why the method is stronger than simply increasing segment length. A larger segment helps, but it increases attention cost and still imposes a hard boundary. Transformer-XL keeps the training segment manageable and adds a rolling memory that can be longer during evaluation.

Main Results

The headline numbers are strong for the 2019 language modeling setting. Transformer-XL reports state-of-the-art or near state-of-the-art results on word-level and character-level benchmarks.

Table 1. On WikiText-103, the large Transformer-XL reaches 18.3 perplexity, improving over the contemporary adaptive-input result of 20.5.

WikiText-103 is the benchmark that most directly matches the paper’s motivation. The articles are long enough that cross-segment dependencies matter. The paper uses attention length 384 during training and 1600 during evaluation for the standard word-level setting.

Table 2. On enwik8, the 24-layer Transformer-XL reaches 0.99 bits per character. The 12-layer 41M-parameter model already matches the 64-layer vanilla Transformer result from Al-Rfou et al. (2018).

Table 3. On text8, the 24-layer Transformer-XL reaches 1.08 bits per character.

The character-level results show that the architecture is not only improving a word-level softmax setup. On enwik8, the paper trains with attention length 784 and evaluates with attention length 3800. That train/eval mismatch is exactly where relative positional encoding matters.

Table 4. On One Billion Word, the large Transformer-XL reports 21.8 perplexity.

One Billion Word is shuffled at the sentence level, so it does not preserve long document dependencies. The improvement there is therefore not mainly about modeling thousand-token discourse. The paper uses it as evidence that recurrence also reduces context fragmentation for short sequences.

Table 5. On Penn Treebank, Transformer-XL reaches 54.52 perplexity without two-step finetuning, close to the best finetuned MoS result.

Penn Treebank is much smaller, so this result is less central to the long-context argument. It is still useful because it shows the method does not only work when the dataset is large.

Ablation: Recurrence And Position Encoding

The ablation table is the most important evidence in the paper. It asks whether the performance comes from recurrence, from the new positional encoding, or from both.

Table 6. WikiText-103 ablation. Recurrence plus the Transformer-XL relative position scheme gives the best result and can benefit from longer evaluation attention length.

The pattern is clear:

  • using recurrence with the paper’s relative positional encoding gives the best perplexity;
  • replacing it with Shaw et al. relative encoding is worse;
  • removing recurrence is worse;
  • absolute encodings do not generalize cleanly to longer attention length;
  • increasing evaluation attention length helps only when the positional scheme can handle reused states.

The 151M setting is especially useful to read. The model is trained with a finite backpropagation length, but perplexity improves when the evaluation attention length is increased. That is the intended behavior: train on manageable segments, then reuse a longer memory at inference.

One Billion Word And Evaluation Speed

The paper also isolates context fragmentation using One Billion Word. Since the dataset is shuffled and lacks document-level long dependencies, an improvement from recurrence is harder to attribute to long-range discourse. It is more likely to come from not starting every segment cold.

Tables 7 and 9. On One Billion Word, recurrence improves perplexity even without document-level long dependency. The same state reuse gives very large evaluation speedups over the vanilla sliding-window Transformer.

The table reports:

Variant One Billion Word PPL
Transformer-XL 25.2
With Shaw et al. encoding 25.7
Without recurrence 27.1

For evaluation speed, the paper compares against a vanilla Transformer that repeatedly evaluates shifted windows. The largest reported slowdown of the vanilla baseline is 1,874x relative to Transformer-XL. This number is not a claim that attention itself becomes 1,874x cheaper. It is a consequence of avoiding massive repeated full-window recomputation.

Effective Context Length

The paper introduces Relative Effective Context Length (RECL) because ordinary effective context length is hard to compare across models with different base perplexities. RECL asks whether increasing context still gives a relative improvement over a shared short-context baseline.

This is the strongest part of the paper for me. The benchmark tables show that the model is good, but the context-length analysis shows why it is good. The model is not just a larger Transformer with a better softmax; it is extracting measurable value from longer history.

Attention Visualization

The appendix visualizes attention behavior for the WikiText-103 model with 16 layers, 10 heads per layer, and memory length 640.

Figure 5. Average attention over the previous 640 tokens. Most heads prefer nearby tokens, but some heads spread attention over much longer ranges.

The average heatmap is unsurprising at first: nearby context gets more attention. The useful detail is that a few heads maintain broad attention over the memory span. Those heads are the mechanism by which the model can keep long-range information accessible instead of collapsing entirely into local n-gram behavior.

Figure 6. Three wide-range heads selected from different layers. The low-level head is broad, while later heads become sparse and more token-specific.

The paper interprets the three selected heads as different long-range behaviors:

  • an early-layer head scans broadly across memory;
  • a middle-layer head picks sparse positions across the full range;
  • a final-layer head gives each target token a distinct sparse focus.

That pattern is plausible: early layers gather candidate information, deeper layers decide which pieces matter for the current prediction.

Figure 7. The attention score decomposition shows different behavior for content addressing, content-dependent positional bias, and global positional bias.

The score-term visualization is a useful sanity check for the relative attention formula. Term (a), the pure content-based term, is comparatively broad. Term (b), the content-dependent positional bias, resembles the final attention distribution more strongly. Term (d), the global positional bias, also favors nearby positions but is flatter. This supports the paper’s claim that the four-term decomposition is not just algebraic decoration; the terms learn different roles.

Implementation Notes

If I were implementing Transformer-XL from scratch, these are the pieces I would treat as bug-prone:

  1. Memory shape. Each layer needs its own memory tensor. The memory length can differ between training and evaluation.
  2. Stop-gradient. The memory used during training must be detached, otherwise the graph grows across segments.
  3. Causal mask. Current tokens can attend to all memory positions and to previous current-segment positions, but never to future current-segment positions.
  4. Relative shift. Relative attention logits need the correct distance alignment. An off-by-one error can silently preserve tensor shapes while corrupting position semantics.
  5. Position scheme. Absolute positional embeddings are not a drop-in choice when hidden states are reused across segments.
  6. Memory update. After each segment, append the new hidden states and keep only the latest states.
  7. Train/eval mismatch. If evaluation memory is longer than training memory, the relative position encoding must be able to represent those longer distances.

Relation To Later LLM Systems

Transformer-XL sits before the current LLM serving vocabulary, so it is easy to read it through later ideas:

  • XLNet directly builds on Transformer-XL’s recurrence and relative positions.
  • Modern decoder inference uses KV cache rather than recomputing previous tokens; Transformer-XL is an earlier training-and-evaluation version of the same state-reuse instinct.
  • T5-style relative bias, RoPE, and ALiBi are not the same method, but they belong to the same broader move away from fixed absolute position embeddings.
  • Sliding-window and recurrent-memory Transformers keep revisiting the same tradeoff: finite memory is cheap enough to use, but it is still finite.

The limitation is equally important. Transformer-XL does not make arbitrary full-context attention cheap. For a segment length and memory length , attention still scales like per layer. The method avoids recomputing old segments and extends usable context, but it does not remove attention’s dependence on the visible memory size.

The stop-gradient boundary is another limitation. The model can attend to old hidden states in the forward pass, but learning signals do not backpropagate through all historical tokens. That is the price paid to keep training feasible.

Takeaway

The core lesson of Transformer-XL is that long-context modeling needs both a state mechanism and a position mechanism. Caching hidden states solves the fixed-window systems problem, but it only works if the model interprets cached states by relative distance rather than stale absolute indices.

The paper’s strongest evidence is not just the perplexity table. It is the combination of:

  • better language modeling results on WikiText-103, enwik8, text8, One Billion Word, and PTB;
  • ablations showing recurrence and the proposed relative encoding both matter;
  • RECL analysis showing longer usable context;
  • evaluation speedups from avoiding sliding-window recomputation;
  • attention visualizations showing that some heads actually use long memory.

That combination is why Transformer-XL is still a useful reference point. It is not the final answer to long-context attention, but it is one of the cleanest demonstrations that Transformer language models need memory reuse and position handling to move beyond fixed-length segments.

SMASH: One-Shot Model Architecture Search through HyperNetworks

H.J. Chen
  2020-02-12 2020-02-12 Created  
  • Work hard

Brock A, Lim T, Ritchie J M, Weston N. SMASH: One-Shot Model Architecture Search through HyperNetworks. ICLR 2018.

  • Paper
  • Code

SMASH is an early one-shot NAS paper, but it is not the same kind of one-shot method as ENAS or DARTS. It does not keep one shared supernet and select subgraphs. Instead, it trains a HyperNetwork that maps an architecture encoding to a set of generated weights.

The core bet is:

where (c) is an architecture description, (H) is the HyperNetwork, and (W) is a subset of weights for the sampled CNN. If the validation error under (H(c)) correlates with the validation error after normal training, then architecture search becomes much cheaper: sample many architectures, score them with generated weights, keep the best, and train only the final architecture normally.

SMASH Loop

The algorithm is short enough to fit in one figure.

The first loop trains the HyperNetwork. Each step samples a minibatch and a random architecture (c), generates weights (H(c)), evaluates the sampled network (f_c(H(c), x_i)), and updates (H). The second loop samples architectures on a validation set and ranks them by their SMASH score. The selected architecture is then fixed and trained from scratch with freely learned weights.

This is important: generated weights are only a proxy. The final reported model is not deployed with HyperNetwork-generated weights.

Memory-Bank Search Space

The paper needs a way to describe variable CNN topologies in a tensor form that a HyperNetwork can consume. The proposed answer is a memory-bank view of feed-forward networks.

Instead of thinking of a CNN as a simple chain of layers, SMASH treats each operation as reading from and writing to memory banks. This makes several connectivity patterns expressible with the same machinery:

Pattern Memory-bank behavior
ResNet-like read a bank, transform it, add/write back
DenseNet-like read many previous banks, write to a fresh bank
FractalNet-like use a more complex branching read/write pattern

The sampled network uses a normal CNN skeleton: stem, block 1, transition, block 2, transition, block 3.

Inside a block, each op starts with a generated (1 \times 1) convolution over the memory banks, followed by up to two parallel paths of two convolutions each. The (1 \times 1) weights are generated by the HyperNetwork; the other convolution weights are normally learned and shared across ops within a block. This design keeps the dynamic part manageable while still making connectivity and width variable.

Architecture Encoding

The architecture (c) has to encode enough structure for (H(c)) to generate useful weights. SMASH encodes the read/write pattern, op choices, output units, dilation, and related settings into a tensor.

The paper uses a fully convolutional HyperNetwork so the output shape can change with the input architecture tensor. Conceptually, each spatial slice of the encoding corresponds to a slice of generated weights. The channel dimension stores one-hot architectural facts such as which memory banks are read, which banks are written, and what operation settings are active.

This is a clever trick, but it also explains why SMASH is not a universal graph-to-weights solution. The search space has to be engineered so that the encoding is regular enough for a convolutional generator.

Does The Proxy Rank Architectures?

The key experiment is not the final CIFAR number. The key experiment is whether the SMASH score is correlated with true performance.

For SMASHv1, the authors train a SMASH network on CIFAR-100 for 300 epochs, sample 250 random architectures, rank them by SMASH validation error, and fully train every fifth architecture for 30 epochs. Figure 4 shows 50 architectures. Lower is better on both axes, and the positive correlation is what makes the method plausible.

The authors are careful not to overclaim this. The correlation is one experimental condition, not a theorem. They then deliberately weaken the setup.

With a smaller “crippled” HyperNetwork, the relationship between generated-weight validation error and true validation error mostly breaks down. The rank plot also shows that scores from different HyperNetwork seeds have nontrivial spread.

This is the main limitation in practice: one-shot evaluation is only useful if the proxy ranking is reliable. A cheaper proxy that changes the ordering of architectures is not just noisy; it can actively select the wrong model.

Architectural Gradient By Proxy

SMASH also asks whether the architecture tensor itself can be optimized by gradient. Since (E = f(H(c), x)), one can in principle backpropagate to (c) and use (\frac{dE}{dc}) as a search signal.

The paper tests whether the HyperNetwork actually uses the encoding by corrupting (c), for example by shuffling dilation values. The correct encoding gives better validation performance, suggesting that (H) has learned a real architecture-to-weight mapping.

But the attempted gradient-descent-style update over discrete architecture choices did not beat random perturbations. This part reads more like a useful negative result than a complete algorithm.

Benchmark Results

SMASHv2 expands the search space with variable filter sizes, variable groups, and the full op structure from Figure 2. The best SMASHv2 models are then trained normally and compared with hand-designed and automatic methods.

SMASHv2 is not state of the art against strong human-designed models. It is much closer to the automatic-design baselines of that period. The paper claims the discovered model is found with far less compute than Large-Scale Evolution, but the comparison is not perfectly symmetric: SMASH starts from a more structured search space and does not grow networks from trivial initial models.

Transfer Results

The paper also transfers the best CIFAR-100 SMASHv2 architecture to STL-10 and ImageNet32x32.

The STL-10 result is not great against Wide ResNet: SMASHv2 has 41.52 +/- 2.10 error, while WRN-40-4 reports 35.02 +/- 1.14. A smaller 3x3 SMASHv2 variant improves to 37.76 +/- 0.58. On ImageNet32x32, SMASHv2 gets 38.62 top-1 and 16.33 top-5 error, better than the listed WRN baselines in the table.

There is also an interesting earlier transfer observation in the text: the architecture found on CIFAR-100 beats the architecture found directly on STL-10 when both are trained on STL-10, suggesting that larger search datasets may produce architectures that generalize better.

What The Found Architecture Looks Like

The appendix visualization is messy, but that is part of the point. The discovered architecture is not a clean hand-designed motif.

This reinforces the engineering tradeoff in SMASH. The search space is flexible enough to produce long, irregular read/write graphs, but the method still depends on an encoding and HyperNetwork that can assign meaningful proxy weights to such graphs.

Takeaways

SMASH is historically useful because it separates two ideas that later get blended in one-shot NAS:

  • Cheap architecture evaluation can be learned and amortized.
  • The learned evaluator must be validated by ranking correlation, not only by final best accuracy.
  • A HyperNetwork evaluator is different from a shared-weight supernet.
  • Encoding design is part of the method; it constrains what the search can express.
  • Generated weights are a proxy, not the final model parameters.

My read is that SMASH is less a production NAS recipe and more a clean early experiment in amortized model evaluation. The paper’s best contribution is not “HyperNetworks solve NAS”; it is the explicit question: can a learned weight generator rank architectures well enough to make search cheap?

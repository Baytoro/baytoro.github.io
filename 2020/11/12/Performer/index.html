Performer is an efficient-attention paper, but it is different from the sparse-attention line represented by Reformer, Longformer, and BigBird. It does not choose a fixed sparse pattern or assume that the attention matrix is low-rank. Instead, it treats softmax attention as a kernel and estimates that kernel with random features.

Why Positive Features Matter

A naive random Fourier feature view would suggest using trigonometric features, because the Gaussian kernel has the usual random feature representation. The paper’s warning is that attention is not just a kernel approximation problem. Attention normalizes scores into a convex combination of values.

Negative random feature coordinates can create unstable score estimates. This is especially bad when the true softmax kernel value is near zero, because small positive weights are common and still matter after normalization.

The paper also discusses a hyperbolic variant and a regularized softmax kernel, but the practical message is simpler: positive features are much more stable than trigonometric features for attention.

The figure visualizes why. In regions where the softmax kernel value is small, the trigonometric estimator can have much larger mean squared error. Positive random features behave better exactly in the low-score regions that would otherwise create normalization trouble.

The ORF Part Of FAVOR+

The full method is FAVOR+: Fast Attention Via positive Orthogonal Random features.

There are two separate ideas:

Part Role
FA Reassociate kernel attention so is computed before multiplying by .
R+ Use positive random features for softmax, avoiding negative score estimates.
O Make the random projection vectors orthogonal to reduce estimator variance.

The orthogonal part is easy to underweight when reading the paper. It is not just an implementation detail. For a fixed random feature budget, orthogonal random features reduce approximation error compared with IID Gaussian features, which means the model can use fewer features for the same quality target.

The MSE plots match the theory: orthogonal features beat IID features, and positive features beat features by a large margin in this attention-output experiment.

The caveat is that this is a JAX implementation benchmark from the paper’s setup. Modern exact-attention kernels such as FlashAttention attack a different problem: they preserve exact softmax attention and reduce memory traffic. Performer changes the mathematical computation through approximation.

Approximation Is Not Free

The paper is honest about error propagation. A single attention approximation may be tight, but a Transformer stacks many attention heads, MLPs, nonlinearities, and residual paths. Small layer errors can compound.

The pretrained-model experiment is therefore important.

On LM1B, the authors transfer a pretrained Transformer into a Performer and recover accuracy through fine-tuning. On PG-19, the difference between feature choices becomes more visible: trigonometric softmax approximation is unstable, while positive softmax features with redrawing can match the Transformer curve.

I read this as the paper’s best practical warning. “Linear attention” is not one thing. Kernel choice, feature count, redraw schedule, and numerical treatment are part of the model.

Protein Sequence Modeling

The TrEMBL experiments are useful because they test long biological sequences rather than only synthetic attention approximations.

The setup uses 36-layer models with sequence length . In the unidirectional case, Performer-ReLU is close to or better than the Transformer and clearly ahead of Reformer. In the bidirectional case, Performer-RELU is strongest in the plotted runs; Performer-SOFTMAX tracks the regular Transformer closely, while Linformer is much worse.

This is where generalized kernel attention matters. FAVOR+ is not only a way to approximate softmax. It also lets the model use other kernelizable attention functions, such as ReLU features, while retaining the same linear-time structure.

Practical Notes

If I were reproducing Performer, I would track these details before judging the method:

  • random feature dimension ;
  • positive feature variant and whether SMREG is used;
  • orthogonal versus IID feature construction;
  • feature redraw schedule;
  • causal prefix-sum numerical stability;
  • exact attention baseline implementation;
  • whether the task rewards approximation or needs exact token-token scores.

The last point matters. Performer and FlashAttention answer different questions. Performer asks: can I replace full attention with a linear-time approximation? FlashAttention asks: can I compute exact attention with much better IO behavior? They can both be useful, but they should not be compared as if they preserve the same operator.

Takeaway

Performer is valuable because it gives kernelized attention a concrete, mathematically motivated implementation path. FAVOR+ makes softmax attention approximable with positive orthogonal random features, and the reassociation of removes the explicit attention matrix.

The limitation is the same thing that makes it fast: it is an approximation. Feature design, redraws, numerical stability, and task distribution decide whether the approximation is harmless. I would treat Performer as a strong long-sequence baseline when memory is the blocker, but not as a drop-in replacement when exact softmax behavior is required.

Language Models are Few-Shot Learners

H.J. Chen
  2020-11-10 2020-11-10 Created  
  • Paper Reading 
 
  • LLM 
  • | AIGC 
  • | Transformer 

Paper

GPT-3 is not important because it changes the Transformer architecture. It is important because it changes the way the model is used. The model is still a decoder-only autoregressive language model, but the task is now placed in the context window as natural language instructions and examples. The parameters do not change at evaluation time.

This paper turns the GPT-2 zero-shot observation into a systematic evaluation protocol: zero-shot, one-shot, and few-shot prompting.

What Changed from GPT-2

GPT-2 showed that a large WebText language model can perform some tasks without supervised fine-tuning. GPT-3 asks a sharper question: if we scale the same idea much further, can the model adapt to a new task from examples in the prompt?

The paper’s answer is: often yes, but not uniformly.

GPT-3 does very well on tasks where the input-output format can be inferred from examples and where the needed knowledge is likely present in pre-training. It still struggles on tasks requiring robust reasoning, exact symbol manipulation, calibrated truthfulness, and reliable instruction following. That mix is what makes the paper useful: it shows both the strength and the boundary of in-context learning.

Figure: Larger models make more effective use of examples placed in the context window.

This figure is the shortest version of the paper’s thesis. The 175B model benefits much more from additional in-context examples than the 13B or 1.3B models. The natural language prompt helps, but scale changes how efficiently the model extracts a task from demonstrations.

Formula Reading: The Base LM Objective

The training objective is the same autoregressive negative log-likelihood:

This formula says that every token is predicted from all previous tokens in the context. There is no explicit supervised task label, no special loss for reasoning, and no gradient update for downstream tasks in the evaluation protocol.

My interpretation:

  • The objective is local next-token prediction, but the context can contain task descriptions, demonstrations, and partial answers.
  • If the model learns to use patterns in the prefix to predict the next token, then “learning from examples in the prompt” is a possible behavior under the same objective.
  • GPT-3’s few-shot ability is therefore not a separate training algorithm. It is a behavior induced by a large conditional language model.

That point is easy to miss. GPT-3 is still just optimizing next-token prediction during training. The new thing is that the prefix at inference time becomes a temporary task specification.

Evaluation Settings

Figure: GPT-3 distinguishes zero-shot, one-shot, few-shot, and traditional fine-tuning.

The figure is the interface definition for the whole paper.

Zero-shot means the model receives a task description and the test input, but no solved example. One-shot means it receives one solved example before the test input. Few-shot means it receives several solved examples. Fine-tuning is shown for contrast: GPT-3 does not perform gradient updates in the evaluated zero/one/few-shot settings.

For a prompt with demonstrations, I read the conditional distribution as:

Here is the sequence of input-output demonstrations and is the query. The model predicts only through a forward pass. The examples change the hidden activations, not the weights.

This is the central conceptual shift. In supervised fine-tuning, the model stores task adaptation in parameters. In in-context learning, the model stores task adaptation in the activations induced by the prompt.

Model Family

Figure: GPT-3 trains a family of decoder-only models from 125M to 175B parameters.

The largest model has 175B parameters, 96 layers, hidden size 12288, 96 attention heads, head dimension 128, and a 2048-token context window. All models are trained for 300B tokens. Batch size is measured in tokens, reaching 3.2M tokens for the largest model, while learning rate decreases as model size grows.

The table is important because the paper is built around scaling comparisons. GPT-3 is not evaluated as one isolated model. The smaller models show whether a result appears gradually with scale or suddenly only at 175B.

Training Data

Figure: GPT-3 mixes filtered Common Crawl with WebText2, Books, and Wikipedia.

The training mix is not proportional to raw dataset size. Filtered Common Crawl is by far the largest source, but higher-quality datasets are upsampled. This is why the “epochs elapsed” column differs across sources. Wikipedia is only 3B tokens, but it is seen more often than filtered Common Crawl relative to its size.

The data recipe matters for interpreting results. GPT-3’s knowledge and task behavior come from a broad web-scale corpus, but that also increases risks:

  • benchmark contamination,
  • duplicated text,
  • social bias,
  • low-quality pages,
  • memorization of rare strings.

The paper spends real space on these issues, which is necessary for a model trained on this kind of data.

Training Compute

Figure: GPT-3 175B uses much more training compute than earlier BERT, RoBERTa, and T5-scale models.

The compute figure gives the physical meaning of “scale.” GPT-3 175B is not just a bigger checkpoint; it represents a jump in training compute. The model family is also designed so the smaller models act as controlled points on a scaling curve.

This matters because the paper is not claiming that 175B parameters alone are magic. It is studying the interaction of parameter count, data, and compute under the same language-modeling objective.

Formula Reading: Compute Scaling

Figure: Validation loss follows a power-law trend as training compute increases.

The figure includes the fitted relation:

Here is validation loss and is compute. The exponent is small, which means loss improves slowly with compute. But on log-log axes, the improvement is smooth over a large range.

My interpretation:

  • There is no obvious saturation at GPT-3 scale in this plot.
  • Scaling is expensive because the exponent is shallow.
  • The smooth curve supports the paper’s decision to extrapolate from smaller models.
  • Many downstream gains are easier to believe when the base LM loss itself follows a predictable scaling trend.

This is why scaling laws became central after GPT-3. The downstream behavior is complicated, but the base loss gives a surprisingly regular signal.

Aggregate Performance

Figure: Average accuracy across 42 benchmarks improves with model size, and few-shot improves fastest.

This figure is the headline result. Zero-shot improves with scale. One-shot improves more. Few-shot improves the most. That pattern supports the in-context learning story: larger models are not only better language models; they are also better at using examples in the prompt.

The faint background lines are individual tasks, and they are noisy. The aggregate trend should not be read as every task improving equally. It means the average direction is strong enough to survive the task-level variance.

LAMBADA and Completion Tasks

Figure: GPT-3 few-shot strongly improves LAMBADA accuracy and lowers perplexity.

LAMBADA is useful because it tests whether the model can predict a final word that depends on a long context. The few-shot setting also lets the prompt define the expected answer format. That is important because a raw LM may continue a sentence with multiple words, while LAMBADA expects exactly one word.

The result illustrates a recurring GPT-3 pattern: examples in the context do two things at once. They describe the task and constrain the output format.

Closed-Book Question Answering

Figure: GPT-3 is much stronger on TriviaQA than on Natural Questions or WebQuestions.

In closed-book QA, the model cannot retrieve documents. It must answer from parameters and the prompt. GPT-3 performs especially well on TriviaQA, where few-shot reaches 71.2. Natural Questions and WebQuestions are much lower.

Figure: TriviaQA accuracy improves smoothly with model size, with few-shot above one-shot and zero-shot.

My interpretation is that this section shows both knowledge storage and task-format sensitivity. Scaling helps the model store more factual associations, but the exact dataset distribution still matters. TriviaQA aligns better with the model’s pre-training distribution and prompt format than the other QA sets.

Translation

Figure: GPT-3 few-shot translation improves with scale and is strongest when translating into English.

Translation is one of the most interesting comparisons with GPT-2. GPT-2 already showed that translation pairs appear in web text. GPT-3 scales that behavior until few-shot translation becomes competitive with previous unsupervised NMT work on several language pairs.

The asymmetry matters: translation into English is stronger than translation from English. That makes sense for an English-dominant language model. The model has richer target-language statistics for English output, so decoding into English is easier.

Winograd and Commonsense

Figure: GPT-3 improves on Winogrande with scale, but still remains below fine-tuned SOTA.

Winograd-style tasks are meant to test commonsense disambiguation. GPT-3 improves with scale, especially in the few-shot setting, but the result is not a full solution. The asterisks in the table also remind us that contamination analysis matters for some benchmarks.

Figure: PhysicalQA and related commonsense benchmarks show smoother improvements, with PIQA above fine-tuned SOTA in the reported setting.

PIQA is a physical commonsense benchmark. GPT-3 does well here, but the ARC and OpenBookQA rows are more modest. This split is a useful warning: “commonsense” is not one capability. Some questions can be answered from common textual patterns, while others need more structured or grounded reasoning.

Reading Comprehension and SuperGLUE

Figure: CoQA improves smoothly with scale, and the SuperGLUE table shows a mixed task-by-task picture.

CoQA is conversational reading comprehension. The few-shot curve approaches human and fine-tuned model performance but does not fully close the gap. The SuperGLUE table below it is more mixed. Some tasks show strong signs of life, while others remain weak.

Figure: SuperGLUE improves with both model size and number of in-context examples.

This figure is one of the clearest demonstrations of in-context learning. The right panel fixes the model and increases the number of examples in context. Performance rises as more examples are provided. That is exactly what we want to see if examples are being used as task information rather than decorative text.

Still, the curve is not a replacement for fine-tuning. It shows that context examples help, but the final score remains below the strongest supervised systems.

Arithmetic and Symbol Manipulation

Figure: Arithmetic performance is near zero for smaller models and improves sharply at 175B for several tasks.

Arithmetic is a good stress test because it is less forgiving than language continuation. Two-digit addition can be memorized statistically, but five-digit arithmetic and multi-step operations require more systematic manipulation.

The figure shows a sharp jump at 175B for some tasks, especially two- and three-digit addition/subtraction. But the model is still weak on harder arithmetic. This is not a calculator; it is a language model that has learned some algorithm-like behavior from text.

Figure: GPT-3 175B improves from zero-shot to one-shot to few-shot on arithmetic and word manipulation tasks, but remains brittle.

The table makes the limitation concrete. Few-shot helps, but performance drops quickly as digit length or symbolic difficulty increases. Word unscrambling and reversed-word tasks are also uneven. These results are useful because they show where scale alone is not enough for reliable algorithmic generalization.

Few-Shot Grammar Correction

Figure: A few grammar-correction examples in the prompt are enough for GPT-3 to continue the pattern.

This qualitative example is close to how people later used LLMs in practice. The prompt gives several bad-English/good-English pairs, and GPT-3 continues with corrected outputs. There is no gradient update and no explicit grammar correction head.

The important point is format induction. GPT-3 is not only answering isolated benchmark questions. It can infer a text transformation from examples and keep applying it for several more lines.

Human Detection of Model-Generated Text

Figure: Human ability to detect generated news articles decreases as model size increases.

This result is not just a capability benchmark; it is a risk signal. Larger models generate text that is harder for humans to distinguish from human-written news-style articles. The curve approaches random chance for the largest model in the tested setup.

The paper uses this to motivate misuse concerns. A model that can produce plausible long-form text has obvious benefits, but it also creates detection, attribution, and trust problems.

Training Curves

Figure: Training and validation loss both continue improving over 300B tokens.

The training curves are a useful overfitting check. Validation loss continues to decrease, and the train-validation gap does not explode with scale. This supports the paper’s claim that the models are still learning useful distributional structure rather than merely memorizing the training set.

The curves also show why the paper’s conclusions are expensive. Improvements continue, but they require very large compute budgets.

Contamination Analysis

Figure: Most benchmark changes are small after clean-data filtering, but some tasks are flagged for review.

Data contamination is a major concern for GPT-3 because the training corpus is huge and web-derived. The plot compares performance changes when evaluating on verified clean subsets. Most points stay near zero, which suggests contamination does not explain most results.

But the flagged tasks still matter. PIQA and Winograd receive special attention, and the paper marks affected results. My reading is conservative: contamination analysis does not invalidate GPT-3, but any web-scale LM benchmark should be treated as an estimate rather than a perfectly isolated measurement.

Bias and Social Effects

Figure: The 175B model shows gender-skewed descriptive word associations in generated text.

The bias table is a reminder that language modeling learns the distribution it is trained on. If the corpus contains skewed associations, the model can reproduce or amplify them. This is not a side issue for deployment; it follows directly from the same objective that gives the model broad capabilities.

The paper also discusses misuse, fairness, representation, and environmental cost. Those sections are less mathematically central than the scaling results, but they are technically important. A model that can generalize from prompts can also generalize harmful patterns from prompts.

What In-Context Learning Is and Is Not

The phrase “few-shot learner” can be misleading if read too literally. GPT-3 is not running SGD inside the prompt. There is no parameter update. A more precise description is:

The model has learned during pre-training to map certain contexts to likely continuations. When the context contains examples, the continuation can follow the demonstrated mapping. This looks like learning because behavior changes with examples, but the mechanism is forward-pass conditioning.

This distinction helps explain both strengths and failures:

  • It can adapt instantly to formats that resemble text patterns seen in pre-training.
  • It is sensitive to wording, ordering, and example choice.
  • It can fail at systematic rules that are easy to state but rare or hard to infer from surface text.
  • It does not know when the prompt asks for an impossible or underspecified task.

Limitations

GPT-3 is impressive, but the paper is explicit about its limits.

First, context length is finite. The 2048-token window typically fits 10 to 100 examples, depending on the task. Many real tasks need more evidence than that.

Second, few-shot prompting is unstable. Example selection, ordering, label words, and formatting can change results.

Third, the model is not instruction-aligned. It predicts continuations. It does not reliably optimize helpfulness, honesty, or harmlessness.

Fourth, symbolic reasoning remains brittle. Arithmetic and word manipulation improve with scale but do not become dependable algorithms.

Fifth, evaluation is contaminated by the realities of web data. The paper checks overlap, but perfect isolation is difficult.

Takeaway

GPT-3’s core contribution is not a new loss or a new block. It is the demonstration that scale changes the interface:

GPT-1 showed that a generatively pre-trained decoder can be fine-tuned for NLP tasks. GPT-2 showed that zero-shot behavior appears when the LM is trained on broad web text. GPT-3 shows that examples in the context can become a practical task interface.

The paper also makes the remaining problems visible: alignment, factuality, contamination, bias, and reliable reasoning. Those problems are not footnotes. They are the direct next questions raised by making language models large enough to use through prompts.

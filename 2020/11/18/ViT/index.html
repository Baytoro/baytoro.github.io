An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale

H.J. Chen
  2020-11-18 2020-11-18 Created  
  • Paper Reading 
 
  • Transformer 
  • | ViT 
  • | Vision 

Dosovitskiy A, Beyer L, Kolesnikov A, et al. An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale. ICLR 2021.

Paper / Code

ViT is important because it removes most of the CNN assumptions from the image classifier and then asks a very direct question: if an image is converted into a sequence, can the same Transformer stack used in NLP handle vision?

The answer is yes, but with a condition. A plain Transformer is not a cheap drop-in replacement for a ResNet on small supervised image datasets. It has less locality and translation bias, so it needs large-scale pre-training to catch up. Once the pre-training dataset is large enough, the same lack of hard-coded visual bias becomes useful: the model scales cleanly, transfers well, and reaches strong accuracy with less pre-training compute than the large CNN baselines compared in the paper.

This note reads ViT as an engineering recipe:

  • how the image is tokenized;
  • what is actually standard Transformer and what is vision-specific;
  • why patch size changes the compute profile;
  • why JFT-300M changes the result compared with ImageNet-only training;
  • what the figures say about learned position, attention distance, and scaling;
  • what later work such as DeiT, Swin, and MAE had to fix or extend.

All figures and tables below are cropped from the official arXiv PDF.

The main architecture choice is not a new attention variant. The main choice is to treat a 2D image as a 1D sequence of learned patch tokens and then rely on scale.

What Is New And What Is Not

ViT keeps the following Transformer pieces almost unchanged:

  • multi-head self-attention;
  • MLP block with GELU;
  • residual connections;
  • LayerNorm before each sub-layer;
  • learned token embeddings;
  • a BERT-style class token.

The vision-specific parts are small:

  • patch extraction at the input;
  • a linear projection from flattened patch pixels to ;
  • learned position embeddings for the patch sequence;
  • interpolation of position embeddings when fine-tuning at a higher resolution.

That last point matters. The paper often pre-trains at resolution and fine-tunes at higher resolution, such as , , or . Patch size stays fixed, so the sequence becomes longer. The model can accept a longer sequence, but the learned position embedding table no longer has exactly the right spatial grid. ViT handles this by 2D interpolation of the pre-trained position embeddings.

This is also where the paper is honest about inductive bias. A CNN has locality, translation equivariance, and a 2D neighborhood structure in every convolution. ViT uses the 2D structure only when cutting patches and when interpolating positions for a new resolution. Everything else has to be learned.

This is why ViT-L/16 is much more expensive than ViT-L/32 even though the layer width and depth are the same.

The same model sizes in working-note form:

  • ViT-Base: 12 layers, hidden size 768, MLP size 3072, 12 heads, 86M parameters.
  • ViT-Large: 24 layers, hidden size 1024, MLP size 4096, 16 heads, 307M parameters.
  • ViT-Huge: 32 layers, hidden size 1280, MLP size 5120, 16 heads, 632M parameters.

The model-size table looks simple, but it is one reason the paper was influential. Instead of designing a special vision attention block, the authors show that BERT-like scaling rules are already a strong baseline for image classification.

Training And Fine-Tuning Recipe

Table 3 from the appendix. The large-scale experiments use Adam, batch size 4096, 10k warmup steps, linear decay for most pre-training runs, and high weight decay.

The training recipe is as important as the architecture. ViT is not trained from scratch on ImageNet and then declared better than CNNs. The paper evaluates transfer from large supervised pre-training datasets:

  • ImageNet-1K: 1.3M images;
  • ImageNet-21k: 14M images;
  • JFT-300M: about 303M high-resolution images and 18k classes.

The main pre-training setup:

Item Setting
Optimizer Adam
Batch size 4096
Warmup 10k steps
Weight decay usually 0.1 on JFT
Pre-training resolution 224
Fine-tuning optimizer SGD with momentum
Fine-tuning batch size 512
Typical fine-tuning resolution 384, higher for some ImageNet results

The high weight decay is not cosmetic. The paper states that strong regularization is key when training on smaller datasets, especially ImageNet. This fits the central ViT story: the architecture has fewer visual priors, so it overfits more easily when the data is not large enough.

During transfer, the model removes the whole pre-training head and attaches a new zero-initialized linear head. This is a small implementation detail, but it avoids carrying a classifier whose output space was tied to the pre-training dataset.

Main Results

Table 2 from the paper. ViT-H/14 and ViT-L/16 pre-trained on JFT-300M outperform the BiT-L ResNet baseline on the reported transfer tasks while using less pre-training compute.

The headline result is not just “ViT gets high ImageNet accuracy.” The more important result is the accuracy per pre-training compute.

From Table 2:

  • ViT-H/14, JFT-300M: ImageNet 88.55, CIFAR-100 94.55, VTAB 77.63, 2.5k TPUv3-core-days.
  • ViT-L/16, JFT-300M: ImageNet 87.76, CIFAR-100 93.90, VTAB 76.28, 0.68k TPUv3-core-days.
  • ViT-L/16, ImageNet-21k: ImageNet 85.30, CIFAR-100 93.25, VTAB 72.72, 0.23k TPUv3-core-days.
  • BiT-L ResNet152x4, JFT-300M: ImageNet 87.54, CIFAR-100 93.51, VTAB 76.29, 9.9k TPUv3-core-days.
  • Noisy Student EfficientNet-L2: ImageNet 88.4/88.5, 12.3k TPUv3-core-days; the table does not report CIFAR-100 or VTAB.

The clean comparison is ViT-L/16 versus BiT-L. Both use JFT-300M. ViT-L/16 is slightly better on ImageNet, CIFAR-100, Pets, and VTAB, while using about TPUv3-core-days instead of . The paper is careful that pre-training efficiency also depends on optimizer and schedule, but the gap is large enough that the architecture is clearly competitive.

ViT-H/14 improves further, especially on ImageNet, CIFAR-100, and VTAB. It also uses more compute than ViT-L/16, but still much less than the CNN baselines in the table.

Low-Data Transfer

Figure 2 from the paper. VTAB is split into Natural, Specialized, and Structured tasks with only 1000 training examples per task.

VTAB is useful because it tests whether a pre-trained representation transfers to small downstream datasets. ViT-H/14 beats BiT-L on the overall VTAB score and does especially well on the Natural and Structured groups. The Specialized group is closer.

This matters because the criticism of ViT is obvious: if it needs 300M images, is it only a brute-force ImageNet model? VTAB says the large supervised pre-training produces a representation that transfers to low-data settings. It does not mean ViT is data-efficient during pre-training. It means the pre-trained representation is useful after the expensive pre-training stage.

Data Scale Is The Turning Point

Figures 3 and 4 from the paper. Larger ViT models underperform or overfit more on small pre-training sets, but they improve strongly when the pre-training data reaches ImageNet-21k and JFT-300M scale.

This is the most important figure in the paper for understanding why ViT initially looked risky.

On ImageNet-only pre-training, large ViTs do not automatically win. ViT-L can underperform ViT-B even though it has more capacity. That is a sign of overfitting and weak data support, not a sign that the Transformer block cannot process images.

As the pre-training dataset grows, the ordering changes:

  • On ImageNet, the CNN bias is helpful and the larger ViT variants do not shine.
  • On ImageNet-21k, ViT becomes competitive and model scaling starts to help.
  • On JFT-300M, larger ViT variants benefit clearly from scale.

The few-shot curve on the right is even more direct. ResNets are better at smaller JFT subsets, but their improvement flattens earlier. ViT is worse on small subsets and better when the subset grows to 90M or 300M images.

The practical takeaway: ViT trades hand-coded visual priors for data. If data is scarce, that trade can be bad. If data is abundant, it becomes powerful.

Compute Scaling

Figure 5 from the paper. ViT gives a better transfer-accuracy versus pre-training-compute frontier than the ResNet baseline in this controlled JFT-300M scaling study.

The scaling study controls the pre-training data and compares three families:

  • pure ViT;
  • ResNet BiT;
  • hybrid models with a ResNet stem feeding a Transformer.

The paper reports that ViT uses roughly - less compute to reach the same transfer performance, averaged over five datasets. Hybrids help at small compute budgets, but the gap shrinks for larger models.

This is an important nuance. The conclusion is not “CNNs are useless.” The hybrid result says local convolutional processing can help when the model or compute budget is smaller. The stronger claim is that at large scale, the pure Transformer is an excellent scaling target and does not saturate in the tested range.

How To Scale The Transformer

Figure 8 from the appendix. The paper varies depth, patch size, width, and MLP width under a small controlled setup.

The appendix asks a practical scaling question: if compute increases, where should it go?

The controlled experiment starts from a smaller ViT-like model and scales different dimensions. The paper’s observations:

  • increasing depth gives the clearest improvement up to a point;
  • decreasing patch size helps because it increases token resolution;
  • scaling width alone is weaker;
  • scaling all dimensions together is robust.

This is close to how later ViT families are usually built. Larger models often combine more layers, enough width, and smaller patch sizes, but the sequence-length cost of small patches makes the compute tradeoff harsh.

What The Model Learns

Figure 7 from the paper. The patch projection learns image-like basis filters, the learned position embeddings recover 2D spatial structure, and attention heads cover both local and global distances.

This figure is useful because it answers a natural question: if the model is given only a flattened patch sequence and a learned 1D position embedding, does it recover image structure?

The left panel shows principal components of the first patch projection. They look like low-level image filters. This is expected, but still important: the linear patch projection is not just a random tokenizer after training. It learns a useful local basis inside each patch.

The center panel shows cosine similarity between position embeddings. Nearby patches tend to have similar embeddings, and row/column structure appears even though the default position embedding is learned as a 1D sequence. This supports the paper’s claim that explicit 2D-aware position embeddings did not improve much.

The right panel shows mean attention distance by layer and head. Some heads attend globally even in early layers, while other early heads stay local. Later layers become more global. That is a different kind of receptive field from a CNN: the model can use image-wide information immediately, but it also learns localized heads when useful.

Figure 6 from the paper. Attention from the output token often highlights semantically relevant regions of the input image.

These attention visualizations should not be over-interpreted as a full explanation, but they show that the class token is not just averaging the image uniformly. It can place high attention on discriminative regions such as the animal, aircraft, or object body.

Position Embeddings

The paper uses standard learned 1D position embeddings. That choice looks suspicious for images, but the ablation in the appendix is surprisingly calm:

Position setting ImageNet 5-shot linear score
No position embedding 0.61382
1D position embedding 0.64206
2D position embedding 0.64001
Relative position embedding 0.64032

The exact numbers are from Table 8 in the appendix. The key point is not that 1D is theoretically best. The point is that learned position embeddings are enough for this classification setup, and explicit 2D position structure is not the bottleneck. The learned embedding similarity in Figure 7 already shows that the model recovers useful spatial organization.

For transfer to higher resolution, however, the 2D layout comes back. The position embedding table must be interpolated as a grid. That is one of the few places where ViT manually uses image geometry.

Class Token Versus Pooling

The main model uses a learnable class token, inherited from BERT. The appendix also tests global average pooling over patch tokens. The initial GAP attempt worked poorly, but the paper finds that the failure is mainly a learning-rate issue. With a better learning rate, GAP and class token work similarly.

I still like the class-token design for the original paper because it keeps the model interface close to NLP Transformers. It makes the architecture easy to explain:

The class token is the readout position. Patch tokens provide visual evidence. Self-attention decides how information moves between them.

For later vision systems, pooling or task-specific heads often matter more. Dense prediction models cannot depend only on a final class token; they need spatial features at many positions.

Real Hardware Cost

Figure 12 from the appendix. On the paper’s TPUv3 timing setup, ViT has comparable speed to similar ResNets and large ViT variants fit larger per-core batches.

The paper includes a useful hardware note. FLOPs do not perfectly predict runtime because memory layout, accelerator kernels, and batch size matter.

In the TPUv3 measurements:

  • ViT speed is comparable to similar ResNet models across input sizes.
  • Large ViT variants fit larger per-core batches than large ResNets.
  • The expected bad scaling with image size becomes visible mostly at the largest models and highest resolutions.

This does not mean plain ViT is always hardware-efficient. On GPUs, in dense tasks, or at very high resolution, global attention can still become expensive. But the figure explains why the original ViT was practical at the paper’s training scale: it maps well enough to accelerator-friendly dense matrix operations.

Self-Supervision In The Original Paper

The paper briefly tests masked patch prediction as a self-supervised objective, inspired by BERT’s masked language modeling. The setup corrupts 50% of patch embeddings:

  • 80% are replaced with a learnable mask embedding;
  • 10% are replaced with a random other patch embedding;
  • 10% are kept unchanged.

The target is a coarse 3-bit mean color of each corrupted patch, so the target space has color classes. This is a preliminary experiment, not the final form of masked image modeling.

The result is interesting historically: ViT-B/16 reaches ImageNet accuracy with self-supervised pre-training, about points better than training from scratch, but still about points behind supervised pre-training in the paper’s setup.

Later work made this direction much more important. MAE, BEiT, DINO, and related methods showed that self-supervised or masked image pre-training can be a strong way to train ViT-style models without JFT-style supervised labels.

Why The Paper Changed Vision Backbones

Before ViT, attention in vision was often added carefully inside CNN-like structures or applied with specialized local/axial patterns. ViT made a different bet:

  1. Keep the Transformer as standard as possible.
  2. Use patch tokens to make the sequence length manageable.
  3. Pre-train at large scale.
  4. Transfer to downstream datasets.

That recipe shifted a lot of vision research. The follow-up branches are easy to see:

Direction Problem it addresses Example papers
Data-efficient ViT training Plain ViT needs large supervised pre-training DeiT
Hierarchical backbones Plain ViT lacks multi-scale dense features Swin Transformer, PVT
Self-supervised pre-training JFT labels are not a scalable public recipe MAE, BEiT, DINO
Multimodal pre-training Patch tokens can share Transformer tooling with text tokens CLIP, ALIGN
Large-scale vision-language models ViT becomes the image encoder inside multimodal systems Flamingo, BLIP, GPT-4V-style systems

This is why ViT is more important than its first ImageNet number. It made “image as token sequence” a default abstraction.

Limitations

The paper’s own limitations are clear.

First, plain ViT is not data-efficient from scratch. If the training set is small, CNN inductive bias helps. The paper needs ImageNet-21k or JFT-300M scale to make the strongest case.

Second, the original model is mainly an image classification architecture. It does not naturally produce a feature pyramid. Detection, segmentation, and other dense tasks need additional design. This is exactly where Swin and other hierarchical ViTs became useful.

Third, global self-attention becomes expensive as resolution grows. At with patches, there are tokens including the class token. At with the same patch size, there are tokens. The attention matrix grows from about entries to more than entries per head.

Fourth, the best results depend on JFT-300M, which is not a public dataset. The ImageNet-21k results are strong, but the full “large scale training trumps inductive bias” claim is clearest with the in-house dataset.

Takeaway

ViT is a simple paper with a large consequence. The architecture says:

The experiment says:

  • on small pre-training data, CNN inductive bias still matters;
  • at ImageNet-21k and JFT-300M scale, ViT becomes very strong;
  • the compute-accuracy frontier is favorable for large ViT models;
  • the model learns spatial structure even with simple learned 1D position embeddings;
  • dense prediction and data-efficient training require follow-up work.

My short version: ViT did not prove that convolution was obsolete. It proved that convolution was no longer the only reasonable default for visual representation learning once pre-training scale became large enough.

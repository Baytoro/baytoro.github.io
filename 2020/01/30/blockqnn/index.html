BlockQNN: Efficient Block-wise Neural Network Architecture Generation

H.J. Chen
  2020-01-30 2020-01-30 Created  
  • Paper Reading 
 
  • NAS 

Paper

BlockQNN is a follow-up to early RL-based NAS papers such as NAS-RL and MetaQNN. The difference is the search unit. Instead of generating a whole CNN layer by layer, BlockQNN searches for a reusable block, then stacks that block to build the final network.

That sounds like a small modeling change, but it matters. Modern CNNs are already built from repeated motifs: residual blocks, inception blocks, dense blocks, inverted residual blocks. If the repeated motif is good, the full network can scale to different depths and input resolutions with much less search cost.

Motivation

The original NAS-RL formulation is expensive because the controller emits an entire architecture and then trains a child model to get a reward. MetaQNN makes the controller simpler by using Q-learning, but it still searches over whole layer sequences. BlockQNN asks a more constrained question:

Can we search for a good network block, then reuse that block as the building unit?

The figure compares hand-crafted blocks, earlier auto-generated whole-network designs, and BlockQNN’s block-wise search. The red box is the key point: the agent only needs to construct the inside of one block. The final network is obtained by stacking the learned block.

Contribution

The paper’s useful contributions are:

  1. It formulates block generation as a Q-learning problem, where the agent sequentially chooses layer/component codes.
  2. It uses an early-stop reward so sampled blocks do not need full training during search.
  3. It adds a distributed asynchronous framework to train sampled candidates in parallel.
  4. It proposes Faster BlockQNN, which predicts block performance before full training and reduces search cost.
  5. It reports strong results: 2.35% error on CIFAR-10, 32 GPUs for 3 days for standard BlockQNN, and a faster version using 1 GPU for about 20 hours.

The headline ImageNet number is also notable for an early NAS paper: the depthwise BlockQNN variant reports 82.0% top-1 and 96.0% top-5 when trained at 224 x 224 and tested at 320 x 320.

Methodology

Network structure code

BlockQNN describes a block as a sequence of network structure codes. Each code stores the information needed to build one component layer. The paper’s state includes:

  • layer index,
  • layer type,
  • kernel size,
  • predecessor 1,
  • predecessor 2.

The predecessor fields are what allow multi-branch connectivity. A new layer does not have to consume only the immediately previous layer; it can point to earlier components inside the block. That is how the search space can include residual-like and inception-like wiring.

Q-learning loop

The Q-learning setup is straightforward:

The agent starts from an input state, samples actions to create a block, stacks the block into a network, trains/evaluates that network, and uses validation accuracy as reward. The Q-table is updated with the usual Bellman-style rule:

The search uses epsilon-greedy exploration. Early in search, random actions dominate. As epsilon decreases, the agent exploits blocks with higher learned Q-values. This is similar in spirit to MetaQNN, but the state-action graph is now about block construction rather than full CNN generation.

Early-stop reward

Training every sampled block to convergence would make the method too slow. BlockQNN therefore trains candidates briefly and uses an early-stop reward:

The left plot shows why shaped intermediate rewards help: the learning curve with shaped reward rises faster than the one that ignores intermediate reward. The right plot explains the early-stop correction. Raw early accuracy is not always aligned with final accuracy, so the paper subtracts FLOPs and density terms to make the reward less biased toward overly large or dense blocks.

This reward is an engineering compromise. It is not a perfect estimate of final accuracy, but it is cheap enough to run many times.

Faster BlockQNN

The paper then adds a predictor to avoid training every sampled architecture:

Faster BlockQNN encodes each layer, embeds the layer sequence, feeds it through an LSTM, concatenates an epoch embedding, and predicts accuracy with an MLP. The idea is to learn from partial training curves and architecture structure so the search can rank candidates before spending full training cost.

This faster version is less accurate than the standard BlockQNN setting, but the compute reduction is large: the paper reports a comparable result with 1 GPU in 20 hours.

Results

Search behavior

The Q-learning curve rises as epsilon decreases, and the top block candidates appear in the final exploitation stage. The discovered blocks are not random chains. They contain short connections and multi-branch structures, which is exactly the kind of pattern hand-designed residual and inception networks also use.

The figure also shows a smaller Block-QNN-S block. This matters because the unconstrained search can produce large models; once parameter limits are added, the discovered structure is simpler but still competitive.

Block variants

The paper explores several variants:

  • Block-QNN-Connection: searches the connection style between blocks instead of simply stacking them.
  • Block-QNN-Faster: uses the performance predictor to reduce search time.
  • Block-QNN-Depthwise: replaces convolution with a depthwise-style cell to reduce parameters.

The results are easiest to read as tradeoffs:

Model Params CIFAR-10 error CIFAR-100 error
Block-QNN-S 6.1M 3.30 17.05
Block-QNN-S more filters 39.8M 2.80 15.56
Block-QNN-Faster 3.9M 3.57 18.21
Block-QNN-Faster more filters 34.4M 3.15 16.74
Block-QNN-Connection 3.9M 3.01 16.07
Block-QNN-Connection more filters 33.3M 2.35 14.83
Block-QNN-Depthwise 3.3M 2.58 15.28

The 2.35% CIFAR-10 number comes from the larger connection-search version. The 2.58% depthwise model is interesting for a different reason: it is much smaller and transfers well to ImageNet.

Search cost

Method Best CIFAR-10 error GPUs Time
MetaQNN 6.92 10 10 days
NAS 3.65 800 28 days
NASNet-A 2.65 450 3-4 days
BlockQNN 2.80 32 3 days
Faster BlockQNN 3.15 1 0.8 days
Depthwise BlockQNN 2.58 32 3 days
Connection BlockQNN 2.35 32 1 day

The exact comparison is not perfectly apples-to-apples, because these papers use different search spaces and training recipes. Still, the direction is clear: searching reusable blocks cuts the cost dramatically compared with whole-network NAS.

The transfer result is the main argument for block-wise search. The block is learned on CIFAR-style tasks, but the depthwise version can be scaled to ImageNet and remain competitive.

Takeaway

BlockQNN is best read as a search-space paper. The Q-learning itself is simple; the important move is narrowing the generation problem from “build a whole network” to “build a reusable block”.

The method still inherits the limits of its search space and training proxy. The searched blocks are CNN motifs, not arbitrary computation graphs, and the best numbers depend on extra choices such as block connection search, more filters, and depthwise operations. But as an early NAS engineering paper, it makes a useful point: reducing the granularity of search can be just as important as changing the search algorithm.

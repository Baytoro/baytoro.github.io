Learning Transferable Architectures for Scalable Image Recognition

H.J. Chen
  2020-01-12 2020-01-12 Created  
  • Work hard 
  • >
  • PaperReading 
 
  • NAS 

Paper

NASNet is the paper that turns the expensive NAS-RL idea into a more transferable design pattern. Instead of searching a whole ImageNet-scale network directly, it searches for small convolutional cells on CIFAR-10, then stacks those cells to build larger ImageNet models.

The important contribution is the search space. Once the cell is found, the number of cell repeats and filter counts can be scaled without changing the cell topology.

Motivation

The original NAS-RL paper could discover good architectures, but searching directly over a large full network is expensive. NASNet asks a more reusable question:

Can we search for a small building block on CIFAR-10 and transfer that block to ImageNet?

The answer depends on constraining the search space. If the controller searches arbitrary whole networks, transfer is fragile. If it searches repeated motifs, the learned component can be reused at different depths, resolutions, and compute budgets.

Contribution

The paper contributes:

  1. The NASNet search space: architectures are built from repeated Normal Cells and Reduction Cells.
  2. A transfer recipe: search the cell on CIFAR-10, then stack it for ImageNet.
  3. ScheduledDropPath, where the probability of dropping a path increases during training.
  4. Strong results on CIFAR-10, ImageNet classification, and COCO detection with NASNet features.

The headline numbers:

Task Result
CIFAR-10 2.40% error
ImageNet 82.7% top-1 / 96.2% top-5
ImageNet mobile-scale setting 74.0% top-1
COCO detection 43.1% mAP test-dev

Methodology

Normal and reduction cells

NASNet fixes the macro layout and searches the repeated cell structure. There are two cell types:

  • Normal Cell: keeps the feature map resolution.
  • Reduction Cell: reduces spatial resolution by using stride-2 operations.

For CIFAR-10, cells are stacked between a few reduction points. For ImageNet, the image is larger, so the network uses more reduction stages. The topology of each cell is learned; the number of repeats and initial filters are scaling knobs.

Controller block

Each cell is built from blocks. In the paper’s main NASNet-A search, . For each block, the controller predicts five decisions:

  1. Select the first hidden state.
  2. Select the second hidden state.
  3. Select an operation for the first hidden state.
  4. Select an operation for the second hidden state.
  5. Select how to combine the two outputs.

The operation set includes identity, pooling, standard convolution, factorized convolution, dilated convolution, and depthwise-separable convolution. At the end of the cell, unused hidden states are concatenated to form the output.

NASNet-A cell

The found NASNet-A cells contain many separable convolutions and learned skip-style connections. There are no manually inserted residual links between cells; the searched cell already learns its own internal connectivity.

ScheduledDropPath

The authors found ordinary DropPath was not enough. ScheduledDropPath drops paths in a cell with a probability that increases linearly over training. This is a small but practical detail: without strong regularization, these searched cells can overfit.

Results

CIFAR-10

Model Params Error
NAS v3 + more filters 37.4M 3.65%
NASNet-A (6 @ 768) 3.3M 3.41%
NASNet-A (6 @ 768) + cutout 3.3M 2.65%
NASNet-A (7 @ 2304) + cutout 27.6M 2.40%
NASNet-C (4 @ 640) 3.1M 3.59%

The large NASNet-A with cutout reaches 2.40% error averaged across 5 runs, and the best single run reported in the paper is 2.19%.

ImageNet transfer

The key claim is transfer: the cells are searched on CIFAR-10, then all ImageNet models are trained from scratch with those cells.

Model Params Mult-Adds Top-1
Inception ResNet V2 55.8M 13.2B 80.1
NASNet-A (7 @ 1920) 22.6M 4.93B 80.8
SENet 145.8M 42.3B 82.7
NASNet-A (6 @ 4032) 88.9M 23.8B 82.7

NASNet-A reaches 82.7% top-1 and 96.2% top-5 on ImageNet with fewer mult-adds than SENet in the comparison table.

Smaller compute setting

For the <1.5B mult-add regime, the paper reports:

Model Params Mult-Adds Top-1
MobileNet-224 4.2M 569M 70.6
ShuffleNet (2x) ~5M 524M 70.9
NASNet-A (4 @ 1056) 5.3M 564M 74.0

This is one reason NASNet mattered: the same cell family could scale down and still beat mobile-oriented baselines from that period.

Detection transfer

The paper also plugs NASNet-A ImageNet features into Faster R-CNN on COCO. The best reported test-dev mAP is 43.1%, which supports the claim that the learned features transfer beyond classification.

Takeaway

NASNet’s main lesson is that the search space can matter more than the controller. By forcing architectures to be made of reusable cells, the paper makes search results transferable across scale.

There are still limitations. The search is expensive, and the method assumes a hand-designed macro skeleton with normal/reduction cell placement. But the cell-based formulation became the template for many later NAS papers because it turns an architecture into something you can scale, compare, and reuse.

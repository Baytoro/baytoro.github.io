Joint Neural Architecture Search and Quantization

H.J. Chen
  2020-01-23 2020-01-23 Created  
  • Paper Reading 
 
  • Quantization

Paper

JASQ is a useful paper to read after NASNet, ENAS, DARTS, and early hardware-aware NAS. The question is simple: if the final model will be compressed before deployment, why search for a float architecture first and only quantize it afterwards?

The paper joins the two decisions. A candidate model contains both a NASNet-style cell architecture and a per-cell quantization policy. The search objective is not raw validation accuracy. It is validation accuracy under a target storage budget. That is the main idea worth keeping.

Problem

Classical NAS mainly optimizes topology. Quantization mainly optimizes how weights are represented. In deployment, these two decisions interact:

  • A large architecture may tolerate lower precision because it has more redundancy.
  • A small architecture may need more bits in sensitive cells to avoid an accuracy collapse.
  • A uniform 8-bit policy is easy to implement, but it assumes every layer has the same quantization sensitivity.

JASQ turns the quantization bit-width into a searchable design choice.

The framework has two modes:

  1. Fix an existing architecture, such as ResNet, DenseNet, MobileNet, or SqueezeNet, and search only its quantization policy.
  2. Search both the architecture and the quantization policy, producing JASQNet and JASQNet-Small.

The important difference from a normal NAS pipeline is the evaluation point. The candidate is trained, quantized, evaluated, and then ranked. So the evolution does not merely search for a strong float model; it searches for a model that survives the target compression policy.

  3. Select the best candidate as the parent.
  4. Select the worst candidate as the one to remove.
  5. Mutate the parent’s architecture and quantization policy.

This matters because the search can make small local changes in either topology or precision. It does not have to redraw the whole architecture every time.

Joint Search Versus Single Search

Figure 7 is the most direct summary of the paper’s claim.

The red circles are fixed architectures with quantization search only. The blue squares are architecture-search baselines without joint quantization. The orange point is JASQNet. The blue pentagon is JASQNet float.

The gap between JASQNet float and JASQNet is the quantization-policy effect: error is almost unchanged, but size moves far left. Compared with only architecture search, JASQNet is much smaller. Compared with only quantization search on existing architectures, it reaches a better size-error position.

This plot is also a good warning about what the method does not prove. JASQNet is not strictly better than every architecture search baseline in accuracy. The claim is trade-off quality under a storage constraint, not absolute top accuracy.

Search Process Analysis

Many NAS papers search on a smaller proxy network and then evaluate a wider or deeper final network. JASQ tests whether that proxy trick helps here.

The result is reasonable for joint search. If quantization sensitivity depends on width, depth, and cell placement, then a small proxy network may distort the precision policy. Searching architecture alone can sometimes tolerate a proxy gap; searching architecture plus quantization makes the proxy mismatch more damaging.

One detail I like here: increasing the population size does not automatically improve the mean fitness curve. With a limited iteration budget, a very large population may reduce selection pressure or spread updates too thinly. The result is empirical, but it is a useful reminder that evolutionary NAS hyperparameters are part of the method, not just implementation trivia.

Limitations

JASQ is clean, but it is also narrower than later hardware-aware NAS.

  • The objective optimizes storage size, not measured latency, energy, or memory bandwidth.
  • The quantization policy is per-cell, not a fully layer-wise or operator-wise policy.
  • The bit choices are limited to 4/8/16 bits.
  • The ImageNet first and last layers are left unquantized.
  • The search space is constrained to NASNet-style cells.
  • The ImageNet architecture is transferred from CIFAR-style search, while the ImageNet quantization policy needs another search because the macro layout changes.
  • The paper mostly discusses weight storage. Activation quantization and real inference kernels are not the focus.

These limitations matter. A 4.9 MB model is not automatically faster if the deployment stack does not have efficient mixed-precision kernels. Storage-aware search is a useful proxy, but it is not the same as hardware-aware search.

Takeaway

The part I would remember from JASQ is the objective design:

This is a simple way to make NAS respect a deployment budget. The search does not blindly minimize size; it asks the model to fit under a target and then uses accuracy to choose among feasible candidates.

JASQ is not a complete hardware-aware NAS system. But as a bridge paper, it is valuable: it moves quantization from a post-processing step into the architecture search loop. That idea shows up again in later mixed-precision, hardware-aware, and co-design methods.

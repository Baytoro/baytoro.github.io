Joint Neural Architecture Search and Quantization

H.J. Chen
  2020-01-23 2020-01-23 Created

Paper

JASQ is a small but useful NAS paper to read after NASNet, ENAS, DARTS, and ProxylessNAS. Its question is simple: if the final model will be compressed anyway, why search the architecture first and quantize it later as a separate step?

The paper joins the two decisions. An individual in the search population contains both a cell-based architecture and a per-cell quantization policy. The fitness is not only validation accuracy, but validation accuracy under a target storage budget. That framing is the part I care about most.

Motivation

Classical NAS optimizes the topology. Quantization optimizes the representation of weights. In deployment, however, the two interact. A large architecture may tolerate aggressive quantization; a compact architecture may need more bits in sensitive cells. A uniform 8-bit policy is easy to implement, but it assumes every layer has the same redundancy.

JASQ treats the quantization bit as another searchable choice:

There are two use cases in the paper:

  1. Fix an existing architecture, such as ResNet or MobileNet, and search only its quantization policy.
  2. Search both the architecture and the quantization policy, producing JASQNet and JASQNet-Small.

This is different from pure architecture search. The model is evaluated after quantization, so the search is biased toward networks that survive compression.

This is a practical objective. It does not ask the search to minimize size forever. It asks the search to satisfy a storage target, then spend the remaining capacity on accuracy.

Evolution Strategy

The search uses tournament selection:

  1. Initialize a population of candidate models.
  2. Randomly sample a subset from the population.
  3. Select the best and worst individual in the subset by the objective above.
  4. Mutate the best individual to produce a child.
  5. Train the child, quantize it, evaluate its validation accuracy and size.
  6. Push the child into the population and remove the worst individual.

The architecture mutation randomly changes one field in a cell combination, such as an input index or an operation. The quantization mutation randomly picks one cell bit (b_i) and resets it to another bit choice.

For the reported joint search, the cost is modest by old NAS standards: 1 GPU for 3 days. The appendix says the final population and sample sizes are both 16, and the implementation uses parameter sharing to accelerate evolution.

Results

Fixed architectures

Before searching new architectures, the paper fixes several known networks and searches only their quantization policies on ImageNet.

Some representative rows:

Model Float acc / size 8-bit acc / size JASQ policy acc / size
ResNet18 69.76 / 46.76 MB 69.64 / 11.47 MB 70.02 / 7.21 MB
ResNet34 73.31 / 87.19 MB 73.23 / 21.32 MB 73.77 / 11.92 MB
MobileNet-v1 69.57 / 16.93 MB 68.77 / 4.05 MB 70.59 / 4.10 MB
MobileNet-v2 71.81 / 14.02 MB 68.06 / 3.45 MB 72.19 / 4.25 MB
SqueezeNet 58.09 / 2.35 MB 57.93 / 1.20 MB 60.01 / 1.22 MB

The interesting part is not just compression. The learned mixed-precision policy often improves top-1 accuracy over the float model. For example, MobileNet-v1 gains 1.02 points while shrinking from 16.93 MB to 4.10 MB. This is probably a regularization effect from quantization-aware retraining, not magic from lower precision itself.

For very small models, the learned policy can be slightly larger than uniform 8-bit, but it avoids the large accuracy drop. MobileNet-v2 is the clearest example: uniform 8-bit gets 68.06%, while the learned policy gets 72.19%.

Joint search

The joint search produces two models:

  • JASQNet: target size (T_S = 3) MB during search.
  • JASQNet-Small: target size (T_S = 1) MB during search.

The key comparison is between each float searched model and its quantized version:

Model CIFAR-10 error / size ImageNet error / size
JASQNet float 2.94 / 13.2 MB 27.25 / 18.8 MB
JASQNet 2.90 / 2.5 MB 27.22 / 4.9 MB
JASQNet-Small float 3.08 / 7.2 MB 34.14 / 11.2 MB
JASQNet-Small 2.97 / 0.9 MB 34.10 / 2.5 MB

The parameter count does not change after quantization. What changes is storage size. This is why Table 2 separates #Params/M from Size/MB.

JASQNet is not the most accurate CIFAR-10 architecture in the table. NASNet-A and AmoebaNet-B have lower error. The trade-off is search cost and storage: NASNet-A reports 500 GPUs for 4 days and 13.2 MB on CIFAR-10; AmoebaNet-B reports 450 GPUs for 7 days and 11.2 MB. JASQNet reports 1 GPU for 3 days and 2.5 MB.

Takeaway

JASQ’s main idea is still relevant: compression should be part of the architecture search objective, not only a post-processing step. The paper shows that a mixed-precision policy can preserve or even improve accuracy while cutting storage aggressively.

There are also clear limitations:

  • The objective optimizes storage size, not measured latency, energy, or memory bandwidth.
  • The search space is constrained to NASNet-style cells.
  • The ImageNet architecture is transferred from CIFAR-style search, while the ImageNet quantization policy needs another search because the cell layout changes.
  • The paper focuses on weight storage. It does not fully answer what happens with activation quantization and real inference kernels.

So I would read JASQ as a bridge paper: earlier than many hardware-aware NAS works, but already pointing toward joint design of architecture and deployment constraints. It is less complete than latency-aware methods such as MnasNet or ProxylessNAS, but the target-size objective and per-cell mixed precision are clean and easy to reason about.

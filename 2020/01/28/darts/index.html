DARTS: Differentiable Architecture Search

H.J. Chen
  2020-01-28 2020-01-28 Created  
  • Paper Reading 
 
  • NAS 

Liu H, Simonyan K, Yang Y. DARTS: Differentiable Architecture Search. ICLR 2019.

Paper / Code

DARTS is the paper that makes NAS feel much less like black-box search. NASNet and AmoebaNet search over discrete cells with RL or evolution, which works but costs thousands of GPU days. DARTS keeps the cell-based search space, relaxes the operation choice into a continuous variable, and updates architecture parameters with gradients.

The method is not magic. It still depends on a hand-designed search space and a discrete cell extraction step at the end. But as a baseline for differentiable NAS, it is a clean paper: one softmax relaxation, one bilevel objective, and a small set of experiments that show the speed/quality tradeoff clearly.

Motivation

Earlier NAS methods usually treat architecture search as a discrete optimization problem. A controller or evolutionary loop samples a cell, the child model is trained or partially trained, and the validation score becomes feedback. That gives a natural search loop, but it is expensive because the architecture itself is not differentiable.

DARTS asks a narrower question:

Can the operation choice on each edge be relaxed so that the architecture is optimized with gradient descent?

This fits the NASNet-style cell search space very well. Instead of searching a whole network directly, DARTS searches for a normal cell and a reduction cell, then stacks the selected cells into a larger network for final evaluation.

Contribution

The paper contributes:

  1. A continuous relaxation of discrete operation choices in a cell-based NAS search space.
  2. A bilevel optimization formulation where network weights are trained on the training set and architecture parameters are trained on the validation set.
  3. First-order and second-order approximations for the architecture gradient.
  4. Experiments on both convolutional cells and recurrent cells, including transfer from CIFAR-10 to ImageNet and from PTB to WikiText-2.

The headline numbers are:

Task DARTS result Search cost
CIFAR-10 2.76 +/- 0.09% test error 4 GPU days
PTB 55.7 test perplexity 1 GPU day
ImageNet mobile setting 26.7% top-1 error 4 GPU days
WikiText-2 69.6 test perplexity 1 GPU day

The paper reports NASNet-A at 2000 GPU days and AmoebaNet-A at 3150 GPU days in the same CIFAR/ImageNet comparison context. That is the main reason DARTS became a common baseline: it makes gradient-based NAS cheap enough to iterate on.

Methodology

Continuous relaxation

The cell is represented as a directed acyclic graph. Each node is a latent feature representation, and each edge contains an operation. Before relaxation, selecting an operation is a categorical decision.

For convolutional cells, the candidate operation set contains:

  • 3x3 and 5x5 separable convolutions,
  • 3x3 and 5x5 dilated separable convolutions,
  • 3x3 max pooling and 3x3 average pooling,
  • skip-connect,
  • zero.

The zero operation means “no connection”. Reduction cells are handled separately from normal cells; the architecture parameters for normal cells and reduction cells are shared across all cells of the same type.

There are two versions:

  • Second-order DARTS uses a one-step unrolled weight update when computing the architecture gradient.
  • First-order DARTS sets the unrolled step size to zero, so the architecture update assumes the current weights are already good enough.

The first-order version is cheaper, but the paper’s tables show it is usually worse: on CIFAR-10, first-order DARTS reports 3.00 +/- 0.14% test error, while second-order DARTS reports 2.76 +/- 0.09%.

Deriving the discrete cell

The continuous model is not the final architecture. After search, DARTS converts the mixed graph back into a discrete cell. For each node, it keeps the strongest non-zero incoming operations from distinct previous nodes. The paper uses for convolutional cells and for recurrent cells.

This detail is easy to miss: zero operations are excluded during the final selection. Otherwise a cell could end up with fewer useful incoming edges, and the comparison with previous cell-based NAS methods would be unfair.

The learned convolutional normal cell is mostly separable convolution and skip-connect edges. The reduction cell uses more pooling. The recurrent cell is learned with a similar mixed-operation idea, but its candidate operations are linear transformations followed by tanh, relu, sigmoid, identity, or zero.

Results

Search progress

The search curve is useful because it shows how little time the method needs before it finds cells in the range of NASNet/AmoebaNet references. For convolutional cells, the validation error gets close to the NASNet-A and AmoebaNet-A reference lines after tens of GPU hours. For recurrent cells, the initialization sensitivity is more visible: some runs improve quickly, while one run stays flat.

CIFAR-10 and PTB

The compact comparison:

Model Metric Params / search
ENAS + cutout on CIFAR-10 2.89% error 4.6M / 0.5 GPU days
Random search on CIFAR-10 3.29 +/- 0.15% error 3.2M / 4 GPU days
DARTS first-order on CIFAR-10 3.00 +/- 0.14% error 3.3M / 1.5 GPU days
DARTS second-order on CIFAR-10 2.76 +/- 0.09% error 3.3M / 4 GPU days
ENAS on PTB 58.6 test perplexity 24M / 0.5 GPU days
Random search on PTB 59.4 test perplexity 23M / 2 GPU days
DARTS first-order on PTB 57.6 test perplexity 23M / 0.5 GPU days
DARTS second-order on PTB 55.7 test perplexity 23M / 1 GPU day

The CIFAR-10 result is competitive with much more expensive search methods, but not strictly the best number in the table. AmoebaNet-B + cutout reports 2.55 +/- 0.05% error, at 3150 GPU days. DARTS is more interesting because it reaches a strong cell with a few GPU days.

The PTB result is stronger: second-order DARTS reaches 55.7 test perplexity, slightly better than the manually tuned LSTM + 15 softmax experts row at 56.0.

Transfer

The CIFAR-10 searched cell transfers to ImageNet mobile setting with 26.7% top-1 error, 8.7% top-5 error, 4.7M parameters, and 574M multiply-adds. This is close to NASNet-A’s 26.0% top-1 error and 8.4% top-5 error, but with 4 GPU days of search instead of 2000.

The recurrent-cell transfer to WikiText-2 is less impressive than the PTB result but still beats the ENAS transferred cell in the table: DARTS gets 69.6 test perplexity, while ENAS gets 70.4.

Takeaway

DARTS is important because it changes the unit of NAS optimization. Instead of sampling complete discrete cells and waiting for rewards, it trains a supernet-like relaxed cell and lets validation gradients shape the operation probabilities.

My main notes:

  • The bilevel split is the core idea: weights learn from training data, architecture learns from validation data.
  • The first-order approximation is a useful speed knob, but the second-order version gives better reported results.
  • The final discrete architecture is still obtained by a heuristic top-k extraction step, so the relaxation and the final cell are not exactly the same object.
  • The random-search baseline is not terrible, which means the search space itself is doing a lot of work.

That last point is the practical lesson. DARTS makes NAS cheaper, but it does not remove the need to design a good search space. Later differentiable NAS papers spend a lot of effort on exactly this weakness: how to make the supernet training signal match the final discrete model more reliably.

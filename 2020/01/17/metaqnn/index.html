Designing Neural Network Architectures using Reinforcement Learning

H.J. Chen
  2020-01-17 2020-01-17 Created  
  • Paper Reading 
 
  • NAS 

Paper / Project / Code

MetaQNN is one of the early reinforcement-learning based NAS papers. It is worth reading together with Zoph & Le’s controller-RNN NAS paper, because the search strategy is different: instead of training an RNN controller to emit architecture strings, MetaQNN uses tabular Q-learning over a hand-designed state-action graph.

The paper is not trying to discover arbitrary neural computation. The search space is deliberately limited to standard CNN components: convolution, pooling, fully connected layers, global average pooling, and softmax. That constraint is important. The interesting part of the paper is how the authors turn “choose a CNN architecture” into a finite-horizon Markov Decision Process that can be explored with a practical amount of computation.

Motivation

CNN design contains many coupled choices: layer type, ordering, filter size, number of channels, stride, pooling position, and termination point. Exhaustively enumerating this space is impossible even when every option is discretized.

Figure 1 summarizes the whole loop: sample a topology, train it, store its validation accuracy, and update the Q-values from replay memory.

The paper’s framing is direct:

  1. Let an agent build a CNN one layer at a time.
  2. Train the sampled CNN on the target dataset.
  3. Use validation accuracy as the reward.
  4. Update the agent so that future sampled architectures become better.

This is a clean formulation, but it only works if the architecture space is constrained enough. MetaQNN therefore spends a lot of effort on the state definition and action restrictions, not only on the reinforcement learning update.

Contribution

The useful contributions are:

  1. Formulate CNN architecture generation as a finite MDP, where a trajectory is a full network topology.
  2. Define a discrete state space for common CNN layers and use action constraints to avoid invalid or obviously degenerate networks.
  3. Use Q-learning with epsilon-greedy exploration and experience replay to search the architecture graph.
  4. Show that the discovered CNNs can outperform earlier networks that use only standard convolution, pooling, and fully connected layers.
  5. Release model definitions and code, although the original implementation is tied to an old Caffe/Python 2 stack.

The last point matters historically. MetaQNN is not only a conceptual NAS paper; it includes trained topologies, Caffe prototxt files, and a server-client training setup.

Methodology

State and Action Space

The MDP view is the core modeling choice. A path through this graph corresponds to one CNN, and the green path in the figure is one sampled architecture.

Each state represents the current layer choice plus enough metadata to decide what layer can come next. The notation used in the paper is:

  • C(d, f, l): convolution with d filters, receptive field size f, and stride l.
  • P(f, l): pooling with receptive field size f and stride l.
  • FC(d): fully connected layer with d neurons.
  • GAP / SM: global average pooling or softmax termination.

The experimental search space is small enough for tabular Q-learning but still large enough to contain useful CNNs:

Layer type Main choices
Convolution layer depth < 12, filter size {1, 3, 5}, stride 1, channels {64, 128, 256, 512}
Pooling layer depth < 12, (filter, stride) in {(5, 3), (3, 2), (2, 2)}
Fully connected layer depth < 12, at most two consecutive FC layers, neurons {512, 256, 128}
Termination global average pooling or softmax

The state also includes a binned representation size. This prevents the agent from repeatedly shrinking a feature map until later convolutions or pooling operations no longer make sense. For example, too many stride-2 pooling layers can reduce a 32 x 32 image to 1 x 1, so the action graph disallows transitions that would create invalid feature maps.

This is one of the most practical pieces of the paper: NAS needs a search space, but it also needs guardrails. Without them, much of the budget would be wasted on architectures that are legal as strings but useless as CNNs.

Q-learning Loop

MetaQNN uses the standard Q-learning update:

where s_i is the current state, u is the action, s_j is the next state, and the reward r is the validation accuracy of the completed CNN. The paper sets:

  • alpha = 0.01
  • gamma = 1
  • initial Q-values to 0.5
  • final policy to epsilon = 0.1, not 0, so the final sampler can still generate several high-quality variants for ensembling

The search loop is:

  1. Sample a CNN topology by walking through the state-action graph with epsilon-greedy exploration.
  2. Train the sampled topology with a short, aggressive schedule.
  3. Store the topology and validation accuracy in replay memory.
  4. Sample 100 previous models from memory and update Q-values backward along their trajectories.
  5. Anneal epsilon and repeat.

The epsilon schedule is deliberately exploration-heavy at the beginning:

Epsilon 1.0 0.9 0.8 0.7 0.6 0.5 0.4 0.3 0.2 0.1
Unique models trained 1500 100 100 100 150 150 150 150 150 150

So one full search run trains about 2700 unique models before the final fine-tuning stage. During exploration, each model is trained for only 20 epochs with Adam, batch size 128, initial learning rate 0.001, and dropout inserted after every two layers. The reported search cost is 8-10 days per dataset on 10 NVIDIA GPUs.

Why Replay Memory Helps Here

In a normal supervised training loop, one minibatch update is cheap. In NAS, one “environment step” can mean training a CNN. MetaQNN therefore cannot afford to learn only from the most recent sampled architecture.

The replay dictionary gives each trained architecture multiple chances to update the Q-table. If the same topology is sampled again, the paper does not retrain it; it reuses the stored validation accuracy. This is a simple engineering choice, but it matters because the expensive part is CNN training, not the Q-value update.

Results

Search Behavior

The Q-learning curves are the first sanity check. As epsilon decreases, the sampled models should become better on average. The paper reports that, for SVHN, mean model accuracy increases from 52.25% at epsilon = 1.0 to 88.02% at epsilon = 0.1.

This does not prove that the agent found a globally optimal architecture. It does show that the Q-table learned useful preferences inside the constrained search graph.

The learned preferences are also interpretable. In the appendix, the authors analyze Q-values by layer depth: convolution and pooling have higher Q-values early in the network, while fully connected and termination states become more likely deeper in the network. That matches the rough shape of hand-designed CNNs.

Benchmark Numbers

MetaQNN is strongest when compared with networks using similar layer types. The top CIFAR-10 model reaches 6.92% test error, better than the standard-layer baselines listed in the paper.

Method CIFAR-10 SVHN MNIST CIFAR-100
All-CNN 7.25 - - 33.71
MetaQNN ensemble 7.32 2.06 0.32 -
MetaQNN top model 6.92 2.28 0.44 27.14
ResNet-110 6.61 - - -
ELU network 6.55 - - 24.28
Tree+Max-Avg pooling 6.05 1.69 0.31 32.37

All numbers are test error percentages. The comparison against ResNet and more complex pooling methods is less flattering, but also less direct: those models use architectural ideas outside the MetaQNN search space. The more honest reading is that MetaQNN does well within a plain CNN search space, but the search space itself limits the ceiling.

Discovered Architectures

It reaches 6.92% test error with 11.18M parameters. The top five CIFAR-10 models range from 11.18M down to 1.10M parameters, but the error varies from 6.92% to 11.63%. That spread is a useful reminder: validation-guided architecture search can find good candidates, but the top architectures are not all equally strong.

One design motif mentioned in the paper is the frequent use of 1 x 1 convolution near the input. The authors interpret it as a learned linear transformation of RGB channels, similar in spirit to preprocessing into another color space. I would treat that as an observation rather than a general rule, but it is a nice example of Q-value analysis producing inspectable architecture hints.

Transfer

The authors also test whether the best CIFAR-10 architecture transfers to other datasets. SOTA means the reference state-of-the-art number listed in the paper.

Target Scratch Fine-tune SOTA
CIFAR-100 27.14 34.93 24.28
SVHN 2.48 4.00 1.69
MNIST 0.80 0.81 0.31

The architecture transfers better than the weights. Fine-tuning from CIFAR-10 weights is worse than training from scratch in all three reported cases. That is not too surprising: the searched architecture can be reusable, but the learned filters from CIFAR-10 are not necessarily a good initialization for digit datasets or CIFAR-100.

Takeaway

MetaQNN is a good example of early NAS engineering. The paper’s main lesson is not that Q-learning is the final answer for architecture search. Later work moved toward controller RNNs, cell-based search, weight sharing, differentiable NAS, and hardware-aware search because training thousands of child models is too expensive.

The lasting idea is the decomposition:

  • Define a searchable but valid architecture graph.
  • Use a cheap policy representation over that graph.
  • Evaluate sampled architectures with a consistent reward.
  • Reuse expensive evaluations through replay or other performance-estimation tricks.

The limitation is equally clear. The method inherits the bias of its search space: only standard CNN layers, coarse discrete hyperparameters, and fixed training recipes. It can discover strong combinations inside that box, but it cannot invent residual blocks, depthwise separable convolutions, attention, or hardware-aware operators unless those choices are explicitly added to the state-action graph.

For me, MetaQNN is most useful as a baseline mental model for NAS: before thinking about supernets or differentiable relaxations, first ask what the states are, which actions are legal, how much one reward costs, and whether the search space itself is the real bottleneck.

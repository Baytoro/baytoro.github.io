S3: Searching Vision Transformer Search Spaces

H.J. Chen
  2022-12-12 2022-12-12 Created  
  • Paper Reading 
 
  • NAS 
  • | ViT 
  • | Vision 

Chen M, Wu K, Ni B, Peng H, Liu B, Fu J, Chao H, Ling H. Searching the Search Space of Vision Transformer. NeurIPS 2021.

Paper

S3 is a meta-NAS paper for Vision Transformers. Most NAS papers start with a fixed search space and then optimize architectures inside it. S3 moves one level up: first ask whether the search space is good, evolve that space, and only then run architecture search inside the evolved space.

That question matters because search quality is bounded by the space. A weak space can make a strong optimizer look bad, while a carefully designed space can make even simple search methods competitive. For ViTs, this is especially visible because depth, embedding width, Q-K-V dimension, MLP ratio, window size, and stage layout are tightly coupled.

What Is Being Searched

The left side of the figure is the main idea:

  1. decompose a search space by dimensions;
  2. estimate the quality tendency of each dimension;
  3. move each dimension toward a better region;
  4. compose the updated dimensions into a new search space.

The right side is the ViT family explored by the paper. It is not a flat DeiT-style sequence of identical blocks. It is a four-stage hierarchical transformer with patch embedding, downsampling between stages, window self-attention, and FFN blocks. The searched dimensions include:

  • stage depth, written as the number of blocks in each stage;
  • embedding dimension per stage;
  • per-block Q-K-V dimension;
  • MLP ratio;
  • window size;
  • number of attention heads.

The important detail is that S3 does not require the same choice in every stage. A shallow stage can shrink while a deeper stage grows. That is where most of the paper’s architecture insight comes from.

Problem Formulation

Ordinary NAS can be written as:

The search space is fixed. S3 changes the setup by explicitly searching for a better first:

Then it trains a supernet over and searches for the best architecture inside that searched space.

This separation is useful. If the search space is poor, optimizing is trying to win inside a bad game. S3 instead tries to improve the game board before selecting a model.

E-T Error

The paper needs a way to score a search space. It uses E-T Error, which averages two terms:

The expected error term is:

where is ImageNet top-1 error and is the resource constraint. This term measures the average quality of the space.

The top-tier term is the average error of the top 50 candidates under the same constraint. This term estimates the upper end of the space.

I like this metric because it catches two different failure modes:

Failure mode Why E-T helps
The space has one good model but most candidates are bad remains high
The average candidate is fine but the best models are not strong remains high
A dimension looks useful only because a few lucky samples work both terms must improve

The metric is still only as good as the performance proxy. S3 does not train every candidate from scratch. It trains a once-for-all supernet, following the AutoFormer style, and evaluates many inherited-weight subnets. That makes the search-space metric practical, but it also means the supernet ranking quality is critical.

Search-Space Evolution

The algorithm alternates between supernet optimization and space evolution.

For a current space , S3 trains a supernet and samples architectures from it. For each search dimension, it groups candidates by the value of that dimension and computes E-T Error for each group. Then it fits a simple linear tendency between dimension value and E-T Error. If larger values make the error better, the dimension moves upward. If larger values make the error worse, it moves downward.

This is deliberately simple. The paper is not trying to learn a complex controller over search spaces. It uses the supernet to answer a local question: for this dimension, which direction improves the space?

Some implementation details are worth keeping:

  • space search runs for 3 iterations;
  • the threshold for space evolution is 0.4;
  • evolution step sizes are 1 block, 64 embedding channels, 0.5 MLP ratio, 64 Q-K-V channels, and 7 window-size units;
  • supernet training uses AdamW, weight decay 0.05, batch size 1024, 20 warmup epochs, stochastic depth 0.2, and a 300-epoch DeiT-like recipe on 16 V100 GPUs;
  • sandwich training samples the largest, smallest, and two middle models per iteration;
  • the authors avoid in-place distillation because it collapses for their transformer training.

So this is not a cheap search procedure. The claim is not “free NAS”. The claim is that spending compute on the search space can give a better architecture family.

What The Space Learns

Figure 2 is the most useful part of the paper for manual model design. It starts from a deliberately symmetric space and lets each stage evolve.

The discovered tendencies are:

  1. Stage 3 gets deeper. The number of blocks in stage 3 grows during search, while stages 1, 2, and 4 shrink.
  2. Later stages get wider. Embedding and Q-K-V dimensions increase in the deeper stages, especially stage 4.
  3. Q-K-V can be smaller than embedding. The searched Q-K-V dimension is often below the embedding dimension, with a larger gap in deeper layers.
  4. MLP ratio increases with depth. Shallow layers prefer smaller MLP ratios, while deeper layers can use larger ratios.
  5. Window size is stage-dependent. Shallow layers move toward smaller windows, while deeper layers prefer larger windows.

The third-stage observation is interesting because it mirrors CNN backbones: much of the representational budget sits in the middle/high-resolution stage, not evenly across all stages.

The block-number plots tell the same story from the E-T Error side. For stage 3, adding blocks improves the top-tier region. For the other stages, fewer blocks are often enough. This is the kind of signal that a manually fixed uniform space would hide.

Why Window Size Changes With Depth

The paper gives a small diagnostic to justify the window-size trend.

The attention maps use the top-left patch as the reference position. Earlier blocks concentrate attention near the reference. Deeper blocks attend farther away, and the top-5/top-10 relative-distance box plots shift right.

This does not prove that every ViT should use the exact S3 window schedule, but it explains the search result: shallow layers benefit from local windows, while deeper layers can use larger windows because their useful attention region has expanded.

Does The Supernet Proxy Work?

S3 depends on inherited-weight evaluation. If the supernet proxy is wrong, E-T Error becomes noise.

Figure 5 checks 10 sampled architectures and compares inherited performance with fine-tuned or retrained performance. The points are close to the diagonal, which supports the proxy in this setting. It is not a complete statistical proof, but it is the right sanity check.

Figure 6 compares three search spaces:

  • Space A: initial space;
  • Space B: one-step evolved space;
  • Space C: two-step evolved space.

The error distribution shifts left from A to C, meaning sampled candidates become better on average. Table 5 gives the top searched architecture in each space:

Space Params FLOPs Top-1
A 28M 4.7G 65.5
B 29M 4.7G 78.0
C 28M 4.7G 82.1

That gap is the core empirical argument for S3. The final architecture is not merely the result of a better evolutionary search. The search space itself has changed enough that the same resource level becomes much more productive.

This matters because searched classifiers can overfit to ImageNet. Here the architecture choices transfer to dense prediction under the Swin-style downstream setup.

ADE20K UperNet S3-T 44.87 mIoU / 46.27 ms+flip above Swin-T 44.51 / 45.81

The gains are not huge everywhere, but they are consistent enough to support the paper’s point: the searched space does not only produce an ImageNet-specific classifier.

Relation To AutoFormer And ViTAS

S3 is closely related to AutoFormer. AutoFormer shows that a weight-entangled ViT supernet can evaluate and deploy subnets. S3 reuses that idea as an estimator for search-space quality, then changes the space before the final architecture search.

The distinction is:

Paper Main target Reusable idea
AutoFormer search architectures in a fixed ViT space weight-entangled transformer supernet
S3 search the ViT search space, then search architectures E-T Error and dimension-wise space evolution
ViTAS improve supernet fairness for ViT NAS cyclic channel sharing

S3 also has a RegNet flavor. RegNet studied design-space quality for CNNs, but it relied on training many sampled models for a short time. S3 instead uses a trained once-for-all transformer supernet to get many performance estimates more cheaply.

Reproduction Notes

If I were reproducing S3, I would not start from the final ImageNet table. I would first validate the measurement loop:

  1. implement the hierarchical search-space encoding;
  2. train a small supernet on a reduced setting;
  3. sample subnets and check inherited accuracy against a few retrained models;
  4. compute , , and E-T Error by dimension value;
  5. verify that one evolution step moves a dimension in the predicted direction;
  6. only then scale to the 300-epoch recipe and evolution search.

The final architecture search uses evolutionary search under resource constraints. The supplementary algorithm uses a population of 50, 20 generations, and the top 10 candidates as parents. That is a small part of the total cost compared with repeated supernet training.

The dangerous failure mode is a misleading supernet. If inherited accuracy is biased toward certain widths, depths, or channel slices, S3 may evolve the space toward whatever the supernet trained best, not toward what would retrain best. This is why Figure 5 is more important than it first appears.

Limitations

S3 improves search-space design, but it still has clear boundaries.

  • The “infinite” space is still hand-structured as a four-stage window-attention transformer family. It does not discover new attention operators, convolutional stems, normalization variants, or training recipes.
  • The E-T metric depends on inherited-weight evaluation. If the once-for-all supernet has ranking bias, the search-space update can be biased too.
  • The compute budget is substantial. Space evolution requires training supernets, and the reported recipe uses 300 epochs on 16 V100 GPUs.
  • The optimization target is mainly ImageNet accuracy under parameter/FLOP constraints. Real deployment may care about latency, memory traffic, activation size, and kernel availability.
  • The design observations are tied to this hierarchical ViT setting. “Stage 3 should be deeper” is a strong clue, not a theorem for every transformer backbone.

Takeaway

S3 is useful because it makes search-space design measurable. Instead of treating the ViT search space as a fixed human prior, it evaluates whether each dimension is moving the candidate distribution in a better direction.

The paper’s lasting value is not only that S3-T/S/B beat several 2021 baselines. The more general lesson is that NAS has two coupled problems: how to search, and what space to search in. For Vision Transformers, S3 shows that the second problem is large enough to deserve its own optimization loop.

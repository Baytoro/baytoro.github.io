FedMask: Joint Computation and Communication-Efficient Personalized Federated Learning

H.J. Chen
  2022-09-03 2022-09-03 Created  
  • Paper Reading 
 
  • FL 
  • | Pruning 

Li A, Sun J, Zeng X, Zhang M, Li H, Chen Y. FedMask: Joint Computation and Communication-Efficient Personalized Federated Learning via Heterogeneous Masking. SenSys 2021.

Paper

FedMask is a personalized FL paper that targets three problems at once: non-IID data, communication cost, and on-device computation. The core idea is not to communicate full model weights. Each device keeps a fixed model weight tensor and learns a personalized binary mask over those weights. During federation, the clients exchange masks instead of dense parameters.

This makes FedMask different from ordinary model compression after FL. The sparse model is not a post-training artifact; the mask is the object being optimized and communicated.

Motivation

Classic FedAvg assumes clients collaborate on one shared global model. That becomes awkward on mobile devices:

  • Data is non-IID, so one global model may not fit each client.
  • Uploading dense model updates is expensive.
  • Large DNNs are hard to train and run on device.

The paper positions FedMask against several FL baselines:

The table is a good summary of the target. FedAvg gives neither personalization nor communication/computation saving. Top-k compression reduces communication but does not solve personalization. Per-FedAvg personalizes, but it still pays dense training and communication costs. FedMask tries to keep all three columns checked.

Contribution

The paper’s contributions are:

  1. It formulates personalized FL as heterogeneous binary mask learning over fixed model weights.
  2. It communicates only binary masks, so each parameter is represented by one bit instead of a full floating-point update.
  3. It adds structured sparsity through mask learning, reducing runtime computation instead of only communication.
  4. It proposes a personalization-preserving mask aggregation rule on the server.
  5. It evaluates the method on image classification, human activity recognition, and next-character prediction.

The headline numbers reported in the paper:

Metric Reported improvement
Inference accuracy up to 28.47% higher
Communication cost up to 34.48x lower
Computation cost up to 2.44x lower
Inference speed up to 1.56x faster
Energy per inference up to 1.78x lower

Methodology

Masked local model

FedMask keeps the real-valued model parameters fixed and learns a binary mask . The model used for inference is:

Each mask entry is binary. A mask value of 0 prunes the corresponding parameter or structured unit; a value of 1 keeps it active.

This is why communication becomes cheap. Instead of sending full gradients or weights, a client sends a binary mask. The server and clients already share the fixed parameter tensor, so the mask is enough to reconstruct the local sparse model.

Three-stage workflow

FedMask has three main stages.

First, each client performs one-shot pruning. This initializes a local binary mask from its own data. The goal is to avoid starting every device from the same dense structure.

Second, each selected client optimizes its local mask. The mask is trained through a real-valued proxy and then binarized. The model weights stay frozen, so local training is mask optimization rather than ordinary weight training.

Third, the server aggregates masks. This is not a simple dense weight average. Since different clients may keep different channels or parameters, the aggregation has to preserve heterogeneity instead of forcing every client into the same subnet.

Personalization-preserving aggregation

The aggregation rule updates shared mask units when they are comparable across clients, while allowing client-specific mask structures to remain different. The paper also illustrates this by transforming channel masks into mask representations before server-side aggregation:

The important point is that the server is not trying to produce one universal sparse architecture. It is coordinating the masks so clients can still benefit from federation without losing local personalization.

Algorithm shape

The pseudocode is useful for seeing what is frozen and what moves:

  • The server initializes model weights and a global mask.
  • Clients download , prune once, and keep a local mask.
  • In each round, selected clients update masks on local data.
  • Clients return masks, not dense model weights.
  • The server aggregates masks and broadcasts the result for the next round.

This is a very different communication object from FedAvg. The learned mask is both the compression mechanism and the personalization mechanism.

Experiments

Setup

The paper evaluates four tasks:

Task Dataset Devices / classes
Image classification EMNIST 2414 / 64
Image classification CIFAR-10 400 / 10
Human activity recognition HAR 30 / 6
Next-character prediction Shakespeare 1129 / 80

The baselines include FedAvg, Top-k, Per-FedAvg, LG-FedAvg, BNN-FedAvg, and standalone local training. This is a useful comparison set because each baseline stresses a different axis: communication compression, personalization, binary networks, or no federation.

Accuracy versus communication

The red star is FedMask. Across IC-CIFAR10, IC-EMNIST, HAR, and NCP, it sits near the low-communication and high-accuracy corner. This is the core empirical claim: mask communication can be cheap without collapsing accuracy.

BNN-FedAvg also communicates cheaply, but the accuracy is much worse in the plots. Standalone local training has no communication, but it usually gives up too much accuracy because each device trains alone.

Computation cost

The computation-cost plot shows why structured masks matter. If pruning were only unstructured, communication would shrink but inference/training kernels may not become much faster. FedMask tries to learn masks that remove structured units, so the active computation graph is smaller.

The figure reports reductions across all four tasks. The gains are largest for HAR in this plot and smaller for NCP, which is a reminder that the benefit depends on the model and layer structure.

Memory and inference latency

FedMask also reduces model footprint relative to dense baselines:

Application FedMask Baseline
IC-CIFAR10 365.30 MB 537.21 MB
IC-EMNIST 364.72 MB 538.09 MB
HAR 2.69 MB 4.41 MB
NCP 0.92 MB 1.53 MB

BNN-FedAvg is much smaller than FedMask, but that is not a free win: the earlier accuracy-communication plot shows BNN-FedAvg loses a lot of accuracy. FedMask is a middle point: not as tiny as a fully binarized model, but substantially more accurate.

The inference-time bars report speedups around 1.38x to 1.56x over dense baselines across the tested applications.

Takeaway

The useful idea in FedMask is that the mask is not just a compression artifact. It is the personalized model.

My notes:

  • Fixing and learning turns FL communication from dense parameter exchange into binary structure exchange.
  • Heterogeneous masks are a natural fit for non-IID clients because each client can keep a different sparse subnet.
  • Structured sparsity is important; otherwise lower communication would not necessarily reduce device computation.
  • The tradeoff is that the method depends on a good fixed weight initialization and a mask aggregation rule that does not erase personalization.

I would read FedMask as an early systems-oriented PFL paper: it is less about finding the best global optimizer and more about choosing the right object to federate. For mobile AI, federating masks can be a better systems interface than federating full models.

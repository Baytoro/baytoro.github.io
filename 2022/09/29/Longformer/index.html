Paper: Longformer: The Long-Document Transformer

Code: https://github.com/allenai/longformer

Longformer is a practical long-context Transformer paper. It does not try to keep full attention and make it slightly faster. It changes the attention pattern so most tokens attend locally, while a small number of task-specific tokens receive global attention.

That design gives Longformer two properties that matter in real document tasks:

  • It scales roughly linearly with sequence length when the local window size is fixed.
  • It can reuse pretrained RoBERTa weights with minimal architectural changes.

Why It Matters

The standard Transformer attention matrix is dense. For sequence length , full self-attention has time and memory complexity. This is tolerable at BERT’s 512-token regime, but it becomes expensive for long QA, document classification, coreference, and summarization.

The paper compares full self-attention with several Longformer implementations. The full attention curve grows quickly and runs out of memory for longer sequences. The vectorized chunk implementation and CUDA implementation keep memory growth much closer to linear.

The important engineering point is that sparse attention only helps if the implementation matches the sparsity pattern. A local-window pattern implemented as many tiny inefficient gathers can lose the theoretical advantage.

Attention Pattern

Longformer combines three attention ideas: sliding-window attention, dilated sliding-window attention, and task-specific global attention.

With a fixed window size , each token attends to nearby tokens on both sides. The complexity becomes instead of . Stacking layers expands the receptive field, so a token can indirectly receive information from faraway tokens through multiple local hops.

Dilated sliding windows increase the receptive field without increasing the number of attended positions. This is similar to dilated convolutions: the model samples farther positions with gaps between them.

Global attention is the task escape hatch. Some tokens need to read or write across the whole document:

  • [CLS] for classification.
  • Question tokens for QA.
  • Candidate answer tokens for WikiHop.
  • The first token in LED summarization.

Those global tokens attend to the full sequence, and the full sequence can attend back to them. This keeps the model from becoming only a local text smoother.

Compared With Prior Long-Document Work

The paper positions Longformer against earlier efficient Transformer variants and long-document work.

The distinction is not only “sparse attention.” Longformer is designed for transfer learning on document-level NLP tasks. Prior long-sequence models often focused on autoregressive language modeling, or they required task-specific chunking and aggregation. Longformer aims to replace RoBERTa’s self-attention and keep the rest of the pretrained Transformer workflow familiar.

Pretraining From RoBERTa

The practical trick is simple but important: start from RoBERTa, replace full attention with Longformer attention, extend the position embeddings, and continue MLM pretraining on long documents.

The paper also tests how to configure attention windows.

Increasing the window size from lower to higher layers gives the best BPC in this ablation. Adding dilation on two heads helps in the small autoregressive language-modeling setup, though the paper notes that dilation was not used in the RoBERTa transfer setting because it did not fit the pretrained weights as well.

The position embedding story is especially useful. RoBERTa has learned absolute position embeddings up to 512 positions. Longformer extends to 4096 by copying the 512 learned embeddings repeatedly instead of random initialization.

The table shows why this is reasonable. A Longformer initialized with copied position embeddings is far better than one that starts with a random long-position setup, and continued MLM pretraining improves it further. For Longformer-base, BPC moves from 1.957 after copying position embeddings to 1.753 after 2K updates and 1.705 after 65K updates.

The Tasks Are Actually Long

Longformer is evaluated on tasks where the input length can exceed BERT’s 512-token limit by a large margin.

TriviaQA is the clearest example: the average context length is 6,589 wordpieces and the 95th percentile is 17,126. WikiHop and Hyperpartisan also have long tails. A truncation baseline may work on short examples, but it cannot be trusted as the sequence length grows.

This is where Longformer’s design is pragmatic. Instead of chunking the document, running RoBERTa repeatedly, and stitching chunk representations with task-specific logic, the paper can concatenate the available context and process it as one sequence.

Finetuning Results

The main finetuning table compares Longformer-base with RoBERTa-base.

The strongest gains appear where longer context matters. WikiHop improves from 72.4 to 75.0, and Hyperpartisan improves from 87.4 to 94.8. TriviaQA and HotpotQA improve more modestly because their useful evidence can often be found in shorter local regions or through task-specific pipelines. IMDB also improves slightly, which fits the dataset: many reviews are short, but a nontrivial tail is longer than 512 wordpieces.

This result shape is important. Longformer is not a magic upgrade for every NLP benchmark. It helps most when the task has useful information outside the short context window and the model can exploit that information through local plus global attention.

What The Ablation Says

The WikiHop ablation is the best diagnostic table in the paper.

The default Longformer with sequence length 4096 reaches 73.8 accuracy. Training longer reaches 75.0. Reducing the sequence length to 2048 drops to 73.1, and using sequence length 512 with full attention drops to 71.7. This supports the claim that performance is not only coming from extra pretraining; the model benefits from longer context.

The most severe row is “no linear projection, no global attention”, which drops to 65.5. Global attention is not a decorative feature. It gives task tokens a direct path to the whole document.

Longformer-Encoder-Decoder

The paper also introduces Longformer-Encoder-Decoder (LED) for long-document seq2seq tasks. LED uses Longformer-style local plus global attention in the encoder, while the decoder still attends fully to generated tokens and encoded representations.

On arXiv summarization, LED-large with sequence length 16,384 reports 46.63 ROUGE-1, 19.62 ROUGE-2, and 41.83 ROUGE-L in this table. The useful comparison is not only against prior systems, but also against the shorter LED setting.

Increasing the input size from 1K to 4K and then 16K improves both ROUGE-1 and ROUGE-2. That is the cleanest evidence in the paper that the summarization task benefits from reading more of the source document.

Practical Notes

Longformer is a good fit when:

  • The task needs document-level context, not only a short answer span.
  • Most interactions are local, but a few task tokens need global access.
  • You want to reuse pretrained BERT/RoBERTa-style models instead of training a long-context architecture from scratch.
  • The model can tolerate a fixed attention pattern.

The limitation is also clear. Sliding-window attention is an inductive bias. It is efficient because most token pairs cannot directly interact. If a task requires arbitrary token-to-token interactions at many distant positions, a fixed local/global pattern may miss some dependencies unless enough layers or global tokens provide a path.

For implementation, I would pay attention to the kernel. The paper separates loop, chunk, and CUDA implementations because the same mathematical sparsity can have very different runtime behavior. The attention pattern and the memory layout have to be designed together.

Takeaway

Longformer is valuable because it makes long-document modeling feel like a controlled modification of pretrained Transformers. Local windows carry the text stream, global tokens carry the task interface, and copied position embeddings make RoBERTa adaptation practical. The result is not a universal replacement for dense attention, but it is a clean engineering tradeoff for document NLP.

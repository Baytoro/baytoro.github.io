Paper: Learned Step Size Quantization

LSQ is a compact QAT paper. The method keeps the quantizer simple: a clipped uniform grid. The improvement comes from learning the step size and scaling its gradient correctly.

Motivation

For uniform quantization, the step size controls both clipping and resolution. If is too small, many values clip at the quantization bound. If is too large, the grid becomes too coarse. Calibration can choose a reasonable before training, but during QAT the tensor distribution changes.

The paper compares quantizer behavior and shows why the step size should be treated as a trained parameter instead of a fixed statistic.

Results

LSQ is evaluated on low-bit image classification. It is especially strong in 2-bit to 4-bit settings, where step-size errors are costly. Compared with fixed-step or less stable learned-step baselines, LSQ recovers more accuracy while keeping the quantizer hardware-friendly.

Takeaway

LSQ sits between PACT and LQ-Nets. PACT learns activation clipping. LQ-Nets learns a flexible codebook. LSQ learns only the scale of a uniform grid. That is a pragmatic middle ground: enough flexibility to improve accuracy, but still simple enough to map to integer kernels.

When reading newer LLM calibration methods, LSQ is a useful reference point. Many of them also optimize small quantization parameters rather than model weights: clipping ranges, equivalent scaling factors, group scales, or rotations.

Gradient Scaling Is The Paper

Learning a step size sounds simple, but the step-size gradient aggregates error over the whole tensor. Without scaling, can update too aggressively compared with weights, especially for large tensors.

The factor is an engineering fix with a clear role: normalize the step-size gradient so its magnitude is comparable across tensor sizes and bit-widths. This is why the paper is more than “make scale learnable”.

How I Use LSQ As A Baseline

When reading a new QAT method, I compare it against LSQ on three questions:

  1. Does it keep a uniform quantizer?
  2. Does it learn only ranges/scales, or does it learn a codebook?
  3. Does it introduce deployment complexity beyond scale metadata?

LSQ is attractive because the answer to the third question is mostly no. It improves low-bit training while preserving a simple quantized format.

The limitation is that LSQ is QAT. It assumes enough training budget and data to update quantization parameters jointly with the model. For post-training LLM quantization, GPTQ/AWQ/SmoothQuant are more realistic.

Why This Became A Baseline

The method is attractive because it keeps the integer grid uniform. That means the trained model can still map cleanly to standard low-bit arithmetic, unlike arbitrary learned codebooks. At the same time, the step size is task-optimized rather than chosen from min/max statistics.

When I compare later PTQ methods with LSQ, I read LSQ as the QAT upper-middle baseline: it needs training data and gradient updates, but it does not require a new kernel format. That makes it a useful reference point for asking whether a more complicated PTQ method is buying accuracy, deployment simplicity, or both.

Experiment Reading

The ablation to care about is gradient scaling. Without the factor, the step size can move too aggressively because a single scale receives gradients from many quantized values. If the scale oscillates, training may look like the weights are unstable, but the real problem is the quantizer parameter.

I also read LSQ as a good example of keeping deployment and optimization aligned. The optimizer sees a learnable step size, but the final quantizer remains a uniform integer grid. That is a good compromise: enough flexibility for accuracy, not so much flexibility that kernels need a new arithmetic format.

For a reproduction, I would log step sizes per layer over training. If early layers learn very different scales from deeper layers, that is useful signal. If all scales collapse to min/max-like values, the LSQ implementation is probably not getting much benefit over ordinary QAT.

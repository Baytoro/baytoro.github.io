TE-NAS: Training-Free Architecture Search

H.J. Chen
  2022-05-09 2022-05-09 Created  
  • Work hard 
  • >
  • PaperReading 
 
  • NAS 

Chen W, Gong X, Wang Z. Neural Architecture Search on ImageNet in Four GPU Hours: A Theoretically Inspired Perspective. ICLR 2021.

  • Paper: https://arxiv.org/pdf/2102.11535.pdf
  • Code: https://github.com/VITA-Group/TENAS

TE-NAS is a training-free NAS paper. The question is simple: can we rank and prune architectures before doing any gradient descent? The paper answers yes, at least inside NAS-Bench-201 and DARTS-style cell spaces, by combining two initialization-time signals:

  • trainability, estimated by the condition number of the neural tangent kernel;
  • expressivity, estimated by the number of linear regions induced by ReLU activations.

The method is not a predictor trained on many evaluated architectures, and it is not a supernet trained with weight sharing. It builds a full search graph, measures these two properties at random initialization, and prunes low-value operators edge by edge. The headline result is a DARTS-space ImageNet search in about four GPU hours on one GTX 1080Ti.

The part I find most useful is the framing. TE-NAS does not claim that initialization-time theory fully explains generalization. It uses theory as a cheap diagnostic: a network should be trainable enough for gradients to make progress and expressive enough to fit nontrivial functions. A search procedure that ignores either side can select pathological cells.

Why Training-Free NAS

Most NAS methods spend their budget evaluating architectures. They either train sampled candidates, train a weight-sharing supernet, or train a predictor from architecture-performance pairs. All three routes introduce cost or bias:

  • Full candidate training is expensive.
  • Early stopping gives a noisy ranking.
  • Weight sharing can make the supernet ranking disagree with standalone training.
  • Learned predictors need a dataset of already trained architectures.

TE-NAS tries to remove this evaluation loop. For each candidate or supernet state, it only needs a minibatch of inputs and randomly initialized weights. No labels are required for the two main indicators.

This is a strong assumption. A zero-cost proxy is only useful if the search space is constrained enough that the proxy signal is comparable across candidates. TE-NAS is therefore best read together with its search spaces: NAS-Bench-201 and DARTS cells.

The intuition is ordinary numerical conditioning. If the largest and smallest eigenvalues of the training NTK differ too much, gradient descent fits some directions quickly and some directions slowly. A smaller condition number means the architecture is expected to be easier to optimize.

In NAS-Bench-201, the paper reports a negative Kendall-tau correlation between NTK condition number and test accuracy. It is not a perfect predictor. The scatter has obvious outliers. But it is useful enough to reject many bad candidates without training them.

Expressivity: Linear Regions

Trainability alone can prefer networks that are easy to optimize but weak. TE-NAS adds an expressivity signal based on ReLU linear regions.

For a ReLU network, the input space is partitioned into regions where the network behaves as an affine function. More distinct activation patterns suggest richer piecewise-linear behavior.

TE-NAS estimates this without training. It samples inputs, forwards them through a randomly initialized network, records activation patterns from ReLU layers, and counts unique patterns as an approximation to the number of linear regions.

The paper reports a positive Kendall-tau correlation around 0.50 on NAS-Bench-201. Again, this is not a complete theory of accuracy. It is a search signal. The useful part is that it points in a different direction from the NTK condition number.

The Two Signals Prefer Different Operators

The paper’s operator-composition plot explains why TE-NAS uses both indicators.

In NAS-Bench-201:

  • Both indicators like a large amount of conv3x3.
  • The NTK condition number prefers more skip_connect, which helps gradient flow.
  • The linear-region count prefers more conv1x1, which increases expressive variation.
  • Average pooling is not favored by either signal in the top-ranked group.

This is the main design reason for combining the two ranks. If the search only minimizes the NTK condition number, it can become too biased toward easy-to-train structures. If it only maximizes linear regions, it can select expressive but poorly conditioned structures.

Pruning By Importance

Instead of sampling many complete cells, TE-NAS starts from a supernet containing all operators and prunes it.

For each pruning step:

  1. Consider removing each candidate operator from the current supernet.
  2. Measure how NTK condition number changes.
  3. Measure how the linear-region count changes.
  4. Rank removals by the two changes.
  5. Combine the ranks and prune one operator on each edge.
  6. Repeat until the search space becomes a single-path architecture.

The criterion is easy to state:

  • Prefer removals that improve trainability, meaning they reduce the NTK condition number.
  • Prefer removals that preserve expressivity, meaning they do not reduce linear regions too much.

This is different from DARTS. DARTS learns continuous operation weights by optimizing a validation objective. TE-NAS does not train a supernet at all. It repeatedly asks: “If this operator disappeared, would the untrained network look more trainable and still expressive?”

Search Trajectory

The pruning trajectory figure is useful because it shows the behavior of the two signals during search.

The starting supernet has high expressivity because it contains all operations, but it has poor trainability. Early pruning sharply improves the NTK condition number. Later steps fine-tune the architecture while trying not to sacrifice too much expressivity.

This matches a practical intuition about oversized search graphs. The full supernet is not necessarily a good architecture. It can be expressive and badly conditioned at the same time. Search needs to remove structure, not only choose the largest function class.

NAS-Bench-201 Results

NAS-Bench-201 is a good place to test zero-cost search because every architecture in the space has a standardized evaluation. TE-NAS is evaluated on CIFAR-10, CIFAR-100, and ImageNet-16-120.

The compact comparison is easier to read as triples: CIFAR-10 / CIFAR-100 / ImageNet-16-120.

  • GDAS: 93.61 / 70.70 / 41.84, with 28925.91 GPU seconds of search.
  • NAS without training: 91.78 / 67.05 / 37.07, with 4.8 GPU seconds of search.
  • TE-NAS: 93.90 / 71.24 / 42.38, with 1558 GPU seconds of search.
  • Optimal in space: 94.37 / 73.51 / 47.31 from benchmark lookup.

The interesting comparison is with “NAS without training” from Mellor et al. That method is faster, but the accuracy gap is large. TE-NAS spends more zero-cost evaluation time, still far below trained NAS methods, and gets much closer to the best architectures in the benchmark.

DARTS-Space CIFAR-10 Results

The DARTS cell space is more realistic than NAS-Bench-201. It is also more fragile: cells need to be derived and then trained from scratch.

Key rows:

  • DARTS second-order: 2.76 test error, 3.3M parameters, 1.0 GPU day of search.
  • SNAS: 2.85 test error, 2.8M parameters, 1.5 GPU days of search.
  • GDAS: 2.82 test error, 2.5M parameters, 0.17 GPU days of search.
  • PC-DARTS: 2.57 test error, 3.6M parameters, 0.1 GPU days of search.
  • TE-NAS: 2.63 test error, 3.8M parameters, 0.05 GPU days of search.

TE-NAS is not the absolute best CIFAR-10 error in this table. PC-DARTS reports a better 2.57 error. But TE-NAS is competitive while using roughly 0.05 GPU days of search, which is about 1.2 GPU hours. That is the point of the paper: high-quality cell search without the expensive search-time training loop.

ImageNet Results

The ImageNet result is the headline claim in the title.

The paper reports two TE-NAS rows:

  • CIFAR-10 search: 26.2 top-1 error, 8.3 top-5 error, 6.3M parameters, and 0.05 GPU days of search.
  • ImageNet search: 24.5 top-1 error, 7.5 top-5 error, 5.4M parameters, and 0.17 GPU days of search.

The ImageNet-searched cell reaches 24.5 top-1 error and 7.5 top-5 error with 0.17 GPU days of search. The paper describes this as roughly four GPU hours on one GTX 1080Ti.

The strongest comparison in the same table is PC-DARTS searched on ImageNet: 24.2 top-1 error, 7.3 top-5 error, and 3.8 GPU days of search. TE-NAS is slightly worse in accuracy but dramatically cheaper in search time.

What Did It Find?

The appendix shows the cells found on CIFAR-10 and ImageNet.

The cells still look like DARTS-family artifacts: separable convolutions, dilated convolutions, skip connections, and pooling arranged inside a fixed DAG grammar. TE-NAS is not inventing arbitrary macro-architectures. It is choosing operations and edges inside the same style of cell search space used by DARTS.

The paper also studies depth and width preference in the DARTS space.

The high-level reading is that both indicators prefer shallow and wide cells in this space. That matches a known tendency of DARTS-family searches: shallow and skip-heavy structures can have smoother optimization behavior.

Ablations

The appendix checks whether both indicators are needed.

On CIFAR-100 in NAS-Bench-201:

Search rule Accuracy
Only NTK condition number 69.25
Only linear regions 70.48
TE-NAS combined rank 71.24

The combination rule also matters. Directly summing raw metric changes is worse than summing ranks, because the scales of NTK condition number and linear-region count are not comparable. Ranking makes the criterion less dependent on numeric magnitude.

The rank-combination plot reinforces this:

Lower combined rank is better in this plot, so the negative correlation is the desired behavior.

Limitations

TE-NAS is a strong zero-cost NAS baseline, but the assumptions are important.

  • The score is search-space dependent. It works in NAS-Bench-201 and DARTS cells, not necessarily in arbitrary spaces.
  • It evaluates trainability and expressivity, not generalization directly.
  • NTK computation needs Jacobians and eigenvalues, so numerical stability and batch choice matter.
  • Linear-region counting depends on sampled inputs and activation-pattern diversity.
  • The method still ends with a discrete cell that must be trained from scratch for final reporting.
  • The found architectures are constrained by the DARTS cell grammar.

The paper is careful about this. It does not say NTK and linear regions are the only meaningful architecture indicators. It argues that theoretically motivated, training-free indicators can be strong enough to guide practical search.

Takeaway

TE-NAS is valuable because it turns deep-network theory into a usable NAS pruning rule. The method asks two cheap questions at initialization:

  1. Does this architecture look trainable under gradient descent?
  2. Does it still have enough expressive capacity?

That combination is stronger than either signal alone. It also gives a useful lens for reading later zero-cost NAS work: a proxy should not only be cheap and correlated on one benchmark. It should expose what property of the architecture it is measuring, and it should be tested against the failure cases that property misses.

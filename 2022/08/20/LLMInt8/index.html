LLM.int8(): Outlier-Aware INT8 Matmul

H.J. Chen
  2022-08-20 2022-08-20 Created  
  • Paper Reading 
 
  • Quantization 
  • | LLM 
  • | Inference 

Dettmers T, Lewis M, Belkada Y, et al. LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale. NeurIPS 2022.

  • Paper: LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale
  • Code: TimDettmers/bitsandbytes

LLM.int8() is best read as the paper that made a specific LLM quantization failure mode concrete. Standard INT8 recipes can look fine on small or medium transformers, then break when the model reaches the scale where activation outlier dimensions become systematic.

The paper’s answer is not “clip the outliers” and not “fine-tune the quantized model.” It keeps most matrix multiplication in INT8, but detects rare outlier feature dimensions and computes those dimensions in FP16. That makes it a mixed-precision matmul design, not a pure INT8 design.

The Scaling Failure

Figure 1 shows the main empirical story. The ordinary 8-bit baseline tracks the 16-bit baseline up to a point, then collapses around the 6.7B OPT scale. LLM.int8() keeps following the 16-bit curve up to OPT-175B.

This matters because a quantization method can pass small-model tests and still be the wrong method for LLM deployment. The failure is scale-dependent. The paper argues that large-magnitude feature dimensions emerge across layers, and those dimensions dominate both attention behavior and quantization error.

What Is Being Quantized

LLM.int8() targets the parameter-heavy linear layers in transformer inference: feed-forward layers and attention projection layers. The paper does not quantize the attention softmax itself, and it does not focus on training.

For a linear layer, write the activation matrix as X with shape s x h, and the weight matrix as W with shape h x o:

The hard part is that the bad values are not random individual elements. They appear in specific hidden dimensions. In other words, the outlier direction is along h, the same dimension that connects activation columns to weight rows.

Vector-Wise Quantization

The first component is vector-wise quantization. Instead of using one scale for the whole tensor, LLM.int8() treats matrix multiplication as many row-column inner products:

It stores one scale per activation row and one scale per weight column. The INT8 matmul accumulates into INT32, then the output is dequantized by the outer product of those row and column scales.

Compared with a single tensor-wide scale, this gives much better precision. Compared with very fine-grained group quantization, it is still simple enough to map onto ordinary INT8 matmul paths.

But vector-wise quantization alone is not enough once the model has systematic outlier feature dimensions. If a few hidden dimensions are much larger than the rest, per-row activation scales still have to cover them, and ordinary dimensions lose resolution.

Mixed-Precision Decomposition

Figure 2 is the method in one picture. LLM.int8() splits the hidden dimension into two sets:

The normal path uses vector-wise INT8 matmul. The outlier path is extracted and computed in FP16, then both outputs are accumulated back into FP16.

The paper uses a threshold of alpha = 6.0 for identifying outlier features. The key engineering claim is that the outlier set is tiny. For transformers up to 13B parameters, the paper reports at most 7 outlier feature dimensions, roughly 0.1% of the feature dimensions. That is small enough that the FP16 side path can preserve accuracy without giving up the memory benefit of INT8 weights for the main matrix.

This is why the method is practical: it keeps more than 99.9% of values on the low-precision path but refuses to quantize the dimensions that actually break the model.

Perplexity Results

Table 1 is the most useful accuracy table. On C4 validation perplexity, simple INT8 methods degrade as the model scales. At 13B parameters:

Method 13B C4 perplexity
32-bit float 12.45
INT8 absmax vector-wise 16.48
INT8 zeropoint vector-wise 13.47
Absmax LLM.int8() 12.45
Zeropoint LLM.int8() 12.45

Two details are worth keeping:

  • Zeropoint quantization helps because the outliers are often one-sided, but it still fails at 13B.
  • Once the outlier dimensions are moved to the FP16 path, zeropoint no longer has much advantage over absmax.

That second point supports the paper’s interpretation: after removing the pathological outlier dimensions from the INT8 path, the remaining distribution is much easier to quantize.

Outliers As A Phase Shift

The paper defines an outlier feature as a hidden dimension with magnitude at least 6, appearing in at least 25% of layers and at least 6% of sequence dimensions. Figure 3 shows how those features spread with model scale and perplexity.

The parameter-scale plot looks like a sharp phase shift around 6B-6.7B parameters. The perplexity plot looks smoother: as C4 perplexity improves, more layers and sequence positions become affected by these large-magnitude features.

The interpretation I find useful is: model size is a visible proxy, but not the only cause. Data, training quality, and model family can move the threshold. The real deployment lesson is to check activation statistics on the actual model, not to assume a fixed parameter-count cutoff.

Figure 4 adds another piece: once outliers become systematic, their magnitude grows quickly. This is why normal INT8 quantization breaks. A few very large dimensions stretch the quantization range, leaving too little resolution for ordinary values.

Why The Outliers Matter

The outlier statistics table is a good sanity check. For the 6.7B fairseq model, outliers affect 100% of layers and 75% of sequence dimensions. For the 13B fairseq model, the table reports 7 outlier dimensions, 100% of layers, and 73% of sequence dimensions.

The important line from the paper is not only “outliers exist.” It is that removing them is catastrophic:

  • at 6.7B scale, the paper reports about 150k outlier values per 2048-token sequence;
  • those values are concentrated in only about 6 feature dimensions;
  • setting the outlier dimensions to zero can reduce mean top-1 attention softmax probability from about 40% to about 20%;
  • validation perplexity can increase by 600%-1000%;
  • removing the same number of random non-outlier dimensions barely changes the result.

That explains why clipping is the wrong mental model. These dimensions are not noise. They are rare in count but central to the model’s computation.

Hardware Access

The paper’s main deployment win is memory. INT8 storage nearly halves the parameter footprint, while the FP16 side path is tiny. The authors report a 1.96x memory-footprint reduction for BLOOM-176B.

Table 2 makes the consequence concrete. With 8-bit inference, an 8x RTX 3090 24GB server can run OPT-175B/BLOOM, while the 16-bit setup listed there only reaches OPT-66B. A 4x RTX 3090 desktop moves from OPT-30B in 16-bit to OPT-66B in 8-bit.

This is why LLM.int8() became practically important through bitsandbytes. The method changed which model sizes were loadable on available hardware.

Speed Is Not The Main Promise

The speed table is easy to misread. Raw INT8 matmul can be faster, but LLM.int8() also pays for quantization, dequantization, outlier extraction, and the FP16 side path.

The paper reports that LLM.int8() is slower than FP16 for small GPT-3-sized matrices. In the table, LLM.int8() is 0.64x at the 2.7B shape and 0.86x at the 6.7B shape. It becomes faster at larger shapes: 1.22x at 13B and 1.81x at the 175B shape.

The practical reading is:

  • use LLM.int8() for memory first;
  • expect speedup only when the matmul is large enough and the kernels are good;
  • treat outlier decomposition overhead as a real systems cost, not a free side branch.

The BLOOM-176B end-to-end table reinforces that point. INT8 inference is close to the native per-token latency and can use fewer GPUs, but it is not a universal latency win. For batch size 32, the table reports 9.94 ms/token for the bfloat16 8xA100 baseline, 10.44 ms/token for LLM.int8() on 8xA100, 9.40 ms/token on 4xA100, and 9.11 ms/token on 3xA100.

The win is capacity and accessibility. Latency depends on communication, batch size, model sharding, and kernel implementation.

Relation To Later Quantization Work

LLM.int8() is a useful reference point for later LLM quantization methods:

Method Main target How it handles activation difficulty
LLM.int8() W8A8-style inference matmul route outlier feature dimensions to FP16
SmoothQuant W8A8 dense inference migrate activation scale into weights before quantization
GPTQ weight-only PTQ keep activations high precision and compensate weight rounding error
AWQ activation-aware weight-only PTQ use activation statistics offline to protect salient weight channels
KIVI KV cache choose different quantization granularity for key and value cache

SmoothQuant can be read as a direct answer to LLM.int8()’s runtime irregularity. Instead of keeping a separate FP16 outlier path, SmoothQuant tries to smooth the activation outliers offline so the final runtime can use a dense W8A8 path. AWQ and GPTQ avoid activation quantization entirely at runtime by staying weight-only.

Reproduction Notes

If I were reproducing this paper, I would separate the checks into statistics, accuracy, and systems measurements.

For statistics:

  • plot activation max by hidden dimension across model sizes;
  • count how many feature dimensions exceed the threshold alpha = 6.0;
  • verify whether the same dimensions appear across layers and sequence positions;
  • measure the effect of zeroing outlier dimensions versus random dimensions.

For accuracy:

  • compare tensor-wise, row-wise, vector-wise, zeropoint, and LLM.int8() variants;
  • report C4 perplexity by model scale, not only one model;
  • run zero-shot tasks at small, medium, and 175B scale if possible;
  • sweep the outlier threshold and report the FP16 side-path size.

For systems:

  • measure model memory including scales and outlier metadata;
  • report time spent in quantization, INT8 matmul, FP16 outlier matmul, and dequantization separately;
  • benchmark small and large matrix shapes, because the overhead flips the speed conclusion;
  • test end-to-end decoding, not only standalone GEMM.

Takeaway

LLM.int8() is important because it names the LLM activation-outlier problem and gives a practical deployment workaround. Vector-wise quantization gives better INT8 precision for normal values, and mixed-precision decomposition protects the tiny set of hidden dimensions that the model cannot afford to quantize.

The tradeoff is runtime irregularity. The method is excellent for loading large models with much lower memory, but the FP16 outlier path complicates kernels and does not guarantee latency improvement. That tradeoff explains why later methods either smooth the outliers away, as in SmoothQuant, or avoid activation quantization, as in GPTQ and AWQ.

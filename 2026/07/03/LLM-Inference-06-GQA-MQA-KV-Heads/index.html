Standard multi-head attention gives q, k, and v the same number of heads. Llama-style inference often uses grouped-query attention instead: many query heads, fewer key/value heads. This matters because decode speed is heavily shaped by KV-cache bandwidth.

Goal

The difference is:

Attention type Query heads KV heads
MHA H H
GQA H G, where 1 < G < H
MQA H 1

The repo uses H for query heads and G for KV heads.

The cache will still store only [B, G, T, Dh]. Repeating is a computation-time view of the KV heads, not the storage format we want to keep.

Minimal PyTorch

Why This Helps Inference

During decode, attention repeatedly reads old keys and values from the KV cache. If K/V have fewer heads, the cache is smaller:

Cache type K shape per layer V shape per layer
MHA [B, H, T_cache, Dh] [B, H, T_cache, Dh]
GQA [B, G, T_cache, Dh] [B, G, T_cache, Dh]
MQA [B, 1, T_cache, Dh] [B, 1, T_cache, Dh]

That is why GQA is not just a modeling trick. It is directly connected to serving memory traffic.

Common Pitfalls

First, do not change the q head count. GQA keeps H query heads.

Second, do not compute Dh = D / G. Dh still comes from D / H.

Third, do not store the repeated K/V in the cache. Store compact [B, G, T, Dh] and repeat only when computing attention.

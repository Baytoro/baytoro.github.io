The first time I tried to trace a decoder model, I mixed up two very different spaces: token-id space and hidden-vector space. Token ids are integers. Hidden states are vectors. The model only enters hidden-vector space after the embedding table, and it only returns to vocabulary space at the LM Head.

Goal

This post isolates the two boundaries:

flowchart LR
    ids["input_ids
[B, T]
integer ids"] --> emb["Embedding table
[V, D]"]
    emb --> x["hidden states
[B, T, D]"]
    x --> model["decoder blocks
[B, T, D]"]
    model --> head["LM Head
Linear(D, V)"]
    head --> logits["logits
[B, T, V]"]

The embedding table answers: “What vector should represent this token id?”
The LM Head answers: “Given this hidden vector, how much should each vocabulary token score?”

Token IDs Are Not Vectors

A tokenizer maps text to integer ids:

The tensor shape is [B, T], not [B, T, D]. The values are indices into a vocabulary. If V = 10, valid ids are in [0, 9].

In the teaching repo, GreedySubwordTokenizer is intentionally simple. It is not a production Llama tokenizer. It exists so the shape flow remains realistic:

Token Embedding

The embedding table has shape [V, D]. Looking up [B, T] ids returns [B, T, D] vectors.

Shape trace:

Tensor Shape Meaning
input_ids [B, T] integer token ids
embedding.weight [V, D] one row per vocab token
x [B, T, D] dense hidden states

This is a lookup, not a matrix multiplication over [B, T]. Each token id selects one row from the table.

LM Head

The LM Head maps hidden states back to vocabulary logits:

Mathematically, for one hidden vector :

$$
\text{logits}{b,t} = h{b,t} W^T
$$

where in PyTorch’s nn.Linear(D, V) storage convention.

Shape Trace

Step Operation Shape
prompt ids tokenizer output [B, T]
embedding lookup nn.Embedding(V, D) [B, T, D]
decoder body many blocks [B, T, D]
LM Head nn.Linear(D, V) [B, T, V]
next-token slice logits[:, -1, :] [B, V]

The decoder body is deliberately shown as a black box for now. It will be expanded in later posts.

Minimal PyTorch

The logits are scores, not probabilities. Softmax comes later during sampling.

A Useful Debug Check

When the model crashes before attention, I first check three things:

Check Why
input_ids.dtype == torch.long embedding lookup needs integer indices
input_ids.max() < V ids must be inside the vocab
x.shape[-1] == D every later module expects hidden size D

In a real inference stack, tokenizer bugs often look like model bugs. A wrong special token id, an out-of-range id, or a mismatched tokenizer/model vocabulary can break the path before attention even starts.

Common Pitfalls

First, do not flatten [B, T] unless you are explicitly preparing a training loss. In inference, we keep batch and time dimensions visible.

Second, do not call argmax over [B, T, V] directly. For next-token generation:

Third, remember that nn.Linear(D, V) stores weight as [V, D]. That storage shape is easy to confuse with the mathematical notation.

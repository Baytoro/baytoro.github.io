Paper: I-BERT: Integer-only BERT Quantization

I-BERT is the paper I read when I want to check whether a quantization method really covers the whole transformer graph. Quantizing linear layers is not enough. BERT still has GELU, Softmax, and LayerNorm, and those operators can force the runtime back into floating point.

Motivation

INT8 GEMM is the easy win. The harder question is what happens between GEMMs. A transformer block has nonlinearities and normalization operations that are not naturally integer arithmetic. If every block dequantizes for GELU or LayerNorm, the deployment graph is not cleanly integer-only.

The figure shows the integer-only transformer workflow. The value of the paper is not a new attention architecture; it is the operator coverage work around the attention and FFN matrix multiplications.

Methodology

I-BERT keeps the usual affine quantization idea for linear layers and then designs integer approximations for the remaining operators.

GELU

GELU involves the Gaussian CDF. I-BERT approximates it with polynomial/integer-friendly arithmetic so the activation can be evaluated without calling a floating-point exponential or erf implementation.

Softmax

Softmax requires exponentials and normalization:

I-BERT approximates the exponential and division using integer arithmetic. The goal is not exact mathematical equality; the approximation must preserve enough attention behavior while remaining hardware-friendly.

LayerNorm

LayerNorm needs mean, variance, and reciprocal square root. I-BERT implements these with integer/fixed-point approximations. This is usually the operator people forget when they say a transformer is “INT8”.

Results

The paper evaluates BERT-base and BERT-large on GLUE and SQuAD. The integer-only version keeps accuracy close to full precision at 8-bit. The useful systems result is that the entire block can avoid floating-point fallback, not only the matrix multiplications.

Takeaway

I-BERT is an operator-coverage paper. It makes the deployment question concrete: if a quantized model still calls FP kernels for GELU, Softmax, or LayerNorm every block, the speedup and portability are weaker than the bit-width suggests. This lesson matters again for ViT quantization and later full-stack LLM inference methods.

Integer-Only Is A Stronger Claim Than INT8 Weights

A model can have INT8 weights and still be operationally messy. If every block dequantizes for GELU and LayerNorm, the runtime needs mixed kernels and extra memory traffic. I-BERT’s stronger claim is that the transformer block can remain in integer/fixed-point arithmetic across these operators.

The important engineering question is not whether the approximation is mathematically exact. It is whether the approximation error is small enough compared with the quantization error already introduced by INT8.

What To Check In Implementations

For an integer-only transformer backend, I would check:

  • how Softmax range is stabilized before exponent approximation;
  • whether LayerNorm variance and reciprocal square root overflow in int32;
  • where requantization happens between attention and FFN;
  • whether residual adds require aligned scales;
  • whether the approximation constants are fixed or calibrated per model.

I-BERT is valuable because it forces these questions into the open.

Source-Level Notes

I-BERT is interesting because it targets the whole BERT inference graph, not just linear layers. Integer GEMM is only one part of the problem. GELU, Softmax, and LayerNorm contain nonlinear operations that are normally evaluated in floating point.

The paper replaces these with integer-friendly approximations. For GELU, the usual form

is approximated with polynomial pieces that can be evaluated under integer scaling. For LayerNorm, mean, variance, reciprocal square root, and affine transform all need integer approximations and careful rescaling.

Implementation Checklist

The hard part is scale propagation. Every tensor has an implicit scale; after residual adds, nonlinearities, and normalization, the next operator must know the correct scale. A reproduction should log scales at each BERT sublayer and verify that dequantization for debugging matches the intended floating reference.

This makes I-BERT a stronger claim than Q8BERT. Q8BERT demonstrates INT8-aware BERT training. I-BERT asks whether inference can avoid floating point arithmetic for the non-GEMM operators as well.

Experiment Reading

The strongest evidence for I-BERT is operator-by-operator replacement. A useful ablation is to quantize only GEMMs, then add integer GELU, then integer LayerNorm, then integer Softmax. That shows how much accuracy each approximation costs and whether the full integer graph is worth it.

LayerNorm is especially delicate because it normalizes by variance. Integer square-root or reciprocal-square-root approximation error can shift the scale of the next projection. In a residual network, those shifts can accumulate.

For deployment, I would inspect whether integer approximations reduce latency on the target CPU/accelerator or merely avoid floating point in theory. The paper’s value is high because it connects numerical approximation to a realistic integer inference path.

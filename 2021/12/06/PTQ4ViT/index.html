PTQ4ViT: Post-Training ViT Quantization

H.J. Chen
  2021-12-06 2021-12-06 Created  
  • Paper Reading 
 
  • Quantization 
  • | ViT 
  • | Vision 

Z. Yuan, C. Xue, Y. Chen, Q. Wu, and G. Sun, “PTQ4ViT: Post-Training Quantization for Vision Transformers with Twin Uniform Quantization.”

Paper: arXiv:2111.12293
Code: hahnyuan/PTQ4ViT

PTQ4ViT is an early and useful ViT quantization paper because it does not treat a Vision Transformer as “a CNN with larger matrix multiplications”. The paper starts from two concrete observations:

  1. post-softmax attention probabilities are extremely unbalanced;
  2. post-GELU activations are asymmetric, with long positive tails and a narrow negative range.

Those two tensors sit exactly on important paths in a transformer block. A single symmetric uniform grid can either waste many quantization levels near empty ranges or collapse the small but important values. PTQ4ViT addresses this with twin uniform quantization and a Hessian-guided metric for calibration.

One important boundary: PTQ4ViT is not a fully quantized ViT inference recipe in the later FQ-ViT sense. In the experiment setting, it quantizes weights and inputs of fully-connected layers and matrix multiplications in self-attention, but it does not quantize softmax and normalization layers. The paper is mainly about better post-training calibration for ViT MatMul/Linear operands and for the difficult activations around softmax/GELU.

The paper’s overview is compact but informative: twin uniform quantization is applied to the post-GELU and post-softmax activation patterns, while a Hessian-guided metric is used to search scaling factors layer by layer.

Post-Softmax And Post-GELU Are Special

The key empirical figure is the distribution plot below.

The post-softmax values are almost all close to zero, but a few values can be close to one. These large values correspond to strong token-patch relations. If the scaling factor is too small, those important large values get clipped or represented poorly. If the scaling factor is too large, most small probabilities collapse to zero.

The post-GELU tensor has a different failure mode. GELU keeps a small negative range but allows positive values to have a much longer tail. A symmetric quantizer has to cover both sides with one grid, so either the positive tail gets harmed or many levels are wasted on the negative side.

PTQ4ViT makes this concrete by comparing different scaling factors.

For post-softmax, a “large” protects large probabilities but destroys many small probabilities. A “small” keeps small probabilities visible but cannot represent large attention entries well. For post-GELU, the same tension appears across sign and magnitude: the negative side and positive side need different treatment.

This is the main reason PTQ4ViT is not just another layer-wise reconstruction paper. It identifies which transformer tensors violate the implicit distribution assumptions behind common PTQ recipes.

Twin Uniform Quantization

The proposed quantizer keeps the hardware-friendly idea of uniform grids, but it uses two ranges instead of one. For a -bit tensor, PTQ4ViT uses one bit as a range flag and the remaining bits for the quantized value inside that range.

For post-softmax activations:

  • uses a small scale to represent the dense near-zero region;
  • covers the whole range, so large attention probabilities remain representable.

For post-GELU activations:

  • the paper searches the positive scale while fixing the negative range to cover all negative values.

Hessian-Guided Calibration

The other problem is calibration. Earlier PTQ methods often choose scaling factors by minimizing MSE, cosine distance, or Pearson-style correlation between the original output and the reconstructed output. PTQ4ViT argues that these local metrics can pick the wrong scale for ViTs.

The paper plots common reconstruction metrics against the real task-loss change.

The curves show that MSE, cosine distance, and Pearson correlation can prefer scaling factors that do not match the cross-entropy loss curve. This is exactly the calibration trap: a tensor can be locally close under an easy metric while still moving the model output in a sensitive direction.

PTQ4ViT uses a second-order view. With a quantization perturbation , the expected loss change can be approximated by Taylor expansion:

$$
\mathbb{E}[L(\hat{W})] - \mathbb{E}[L(W)]
\approx
\epsilon^T \bar{g}^{(W)}

  • \frac{1}{2}\epsilon^T \bar{H}^{(W)}\epsilon.
    $$

The paper then uses a layer-output approximation. For layer output and quantized output , the calibration objective becomes a gradient-weighted reconstruction error:

In plain terms: do not weight every output coordinate equally. Coordinates with larger output gradients should matter more because perturbing them changes the loss more.

There is a subtle PTQ issue here: calibration data is unlabeled. The paper approximates the label with the full-precision model prediction, so the loss is computed against the FP32 model’s own output. This is a common PTQ trick: use the teacher model to define what “do not change the behavior” means.

This is also where the old shorthand “ranking-aware calibration” would be wrong for PTQ4ViT. Ranking loss appears in prior ViT PTQ work that PTQ4ViT compares against. PTQ4ViT’s own main metric is Hessian-guided, based on output gradients.

Framework

Algorithm 1 is simple but useful because it shows the actual calibration flow.

The framework has two phases:

  1. Run the full-precision model on calibration images and store each layer output .
  2. Run backward propagation to get .
  3. Search scaling factors layer by layer.
  4. For each layer, evaluate candidate scales with the Hessian-guided objective.
  5. Alternate the search over activation scale and weight scale for several rounds.

The paper stores outputs and gradients in CPU memory after generation, then moves them back to GPU memory layer by layer during search. Candidate outputs are evaluated in batches to make use of GPU parallelism. This is not just an implementation footnote. Without this memory movement, storing all layer outputs and gradients for ViT calibration can be expensive.

The reported experiment setting is:

  • ImageNet classification;
  • 32 randomly selected training images as unlabeled calibration data;
  • models from timm;
  • search range parameters alpha = 0, beta = 1.2, n = 100;
  • search round #Round = 3;
  • separate quantization parameters for different attention heads;
  • different scaling factors for , , and ;
  • no quantization for softmax and normalization layers.

The last point matters when comparing this paper to later fully quantized ViT work.

ImageNet Results

Table 1 is the central result.

At W8A8, PTQ4ViT keeps all tested models within roughly 0.5 percentage points of FP32. The drops are small across ViT, DeiT, and Swin.

At W6A6, the gap between base PTQ and PTQ4ViT becomes much larger. The paper reports that base PTQ has a 9.8 percent average drop, while PTQ4ViT reduces the average drop to 2.1 percent. A few numbers make the pattern clear:

Model FP32 Base PTQ W6A6 PTQ4ViT W6A6
ViT-S/224 81.39 70.24 78.63
ViT-B/224 84.54 75.66 81.65
DeiT-S/224 79.80 72.26 76.28
DeiT-B/384 83.11 68.44 81.55
Swin-B/384 86.44 85.22 85.38

Swin is less sensitive than plain ViT/DeiT in these results. The paper’s explanation is plausible: Swin computes self-attention within local windows, so the softmax distribution is less extreme because fewer patches participate in each attention operation.

There is also a model-size trend. Larger ViTs are less sensitive than smaller ones. For example, at 8-bit PTQ4ViT, the reported drops for ViT-S/224/32, ViT-S/224, ViT-B/224, and ViT-B/384 are 0.41, 0.38, 0.29, and 0.17. At 6-bit they are 4.08, 2.75, 2.89, and 2.65. This is a common compression pattern: larger models often have more redundancy, though that is not a guarantee.

Comparison With Prior PTQ

The method comparison table is useful because it separates calibration image count, mixed precision, model size, and top-1 accuracy.

PTQ4ViT uses only 32 calibration images, while EasyQuant and the Liu et al. baseline in the table use 1024. At W8A8 and W6A6, PTQ4ViT is stronger than the listed prior methods despite using fewer images.

The 4-bit result is more nuanced. On DeiT-B:

  • Liu et al. W4A4 mixed precision reaches 75.94;
  • PTQ4ViT W4A4 reaches 60.91;
  • PTQ4ViT with bias correction reaches 64.39.

So PTQ4ViT is a strong 8-bit and 6-bit PTQ method, but it is not a complete answer for 4-bit ViT quantization. Mixed precision still matters at lower bit-widths because sensitivity is not uniform across layers and tensors.

Ablation

The ablation table is the part I would check first when judging whether the two proposed components really matter.

The main reading:

  • Hessian-guided calibration alone helps, especially at 6-bit.
  • Twin uniform quantization helps only when the calibration metric is strong enough.
  • Combining Hessian-guided calibration with twin uniform quantization gives the best results.

For ViT-S/224 at W6A6:

  • base row: 70.24;
  • Hessian-guided only: 77.20;
  • Hessian + softmax twin: 78.57;
  • Hessian + GELU twin: 76.93;
  • Hessian + both twin quantizers: 78.63.

The warning is visible too. Twin uniform quantization without the Hessian-guided metric can degrade accuracy. On ViT-S/224 W8A8, using both twin quantizers without Hessian gives 79.25, which is worse than the 80.47 base row. That makes sense: a more flexible quantizer gives the search more ways to choose a bad scale if the objective is misaligned.

Calibration Cost

Table 4 gives a practical view of calibration time.

With 32 calibration images, most models are quantized in a few minutes on one Nvidia Tesla V100. Increasing calibration images to 128 raises time substantially, especially for larger high-resolution models. For example, Swin-B/384 goes from 25 minutes to 69 minutes.

Accuracy does not change much when moving from 32 to 128 images. That is important for PTQ deployment: if the method needed 1024 images and long calibration time, it would lose much of the appeal of post-training quantization.

Relation To FQ-ViT

PTQ4ViT and FQ-ViT solve related but different problems.

PTQ4ViT focuses on post-training calibration for the main matrix multiplications and difficult ViT activations. It explicitly leaves softmax and normalization layers unquantized in the reported setting. Its central ideas are twin uniform quantization and Hessian-guided scale selection.

FQ-ViT goes after fully quantized inference, including parts that PTQ4ViT leaves floating point. That requires different tricks, such as special handling for LayerNorm and Softmax. If the deployment target requires every operation to run in integer or low-bit arithmetic, PTQ4ViT is not enough by itself. If the target allows some FP operations and the main bottleneck is Linear/MatMul quantization, PTQ4ViT is a cleaner fit.

Relation To LLM Quantization

I read PTQ4ViT as an early transformer quantization warning:

  • architecture-specific activation distributions matter;
  • local reconstruction error is not always aligned with task loss;
  • calibration objectives should weight sensitive directions more heavily;
  • low-bit quantization needs tensor-specific treatment, not only a global bit-width.

Those themes later reappear in LLM quantization. LLMs have activation outliers, attention/KV-cache behavior, and strong layerwise sensitivity differences. The exact PTQ4ViT design does not directly transfer to language models, but the diagnostic mindset does: first inspect the tensor distribution and tensor role, then choose the quantizer and calibration metric.

Reproduction Notes

If I were reproducing this paper, I would not start with all models. I would use DeiT-S/224 or ViT-S/224 first and build the checks in this order:

  1. verify FP32 top-1 with the exact timm checkpoint;
  2. implement base PTQ with symmetric quantization for Linear/MatMul operands;
  3. confirm that W6A6 base PTQ loses a large amount of accuracy;
  4. add Hessian-guided calibration and check whether the selected scales move closer to the CE-preferred scales;
  5. add twin uniform quantization only for post-softmax and post-GELU;
  6. reproduce the ablation table before scaling to all ViT/DeiT/Swin models.

The most important debug artifacts would be:

  • activation histograms for post-softmax and post-GELU;
  • candidate scale curves for MSE, cosine, Pearson, Hessian, and CE;
  • layerwise chosen scales before and after Hessian weighting;
  • attention-head-specific quantization parameters;
  • top-1 results under W8A8 and W6A6 for a fixed 32-image calibration set.

I would also run several random calibration sets. The appendix says the paper observes slight accuracy variation with different calibration image counts, but PTQ methods can still have calibration-set variance. A single lucky 32-image set is not enough to understand robustness.

Limitations

PTQ4ViT has several clear boundaries:

  • It does not quantize softmax and normalization layers in the reported experiments.
  • It is much stronger at 8-bit and 6-bit than at 4-bit.
  • Twin uniform quantization adds format logic and range handling, even if it stays shift-friendly.
  • The Hessian-guided metric needs gradients and stored layer outputs, so calibration is heavier than pure min/max or MSE calibration.
  • The method is evaluated on ImageNet classification; downstream dense prediction tasks may expose different sensitivity.

None of these make the paper weak. They define what problem it solves: practical post-training quantization for ViT-family classifiers when 8-bit or 6-bit Linear/MatMul quantization is the target.

Takeaway

PTQ4ViT is valuable because it connects three things that should be considered together: tensor distribution, tensor semantics, and calibration objective. The twin uniform quantizer addresses the weird activation distributions around softmax and GELU. The Hessian-guided metric addresses the fact that local reconstruction error is not always the right proxy for task loss.

The broader lesson is simple: transformer PTQ is not solved by copying CNN PTQ. The difficult tensors are different, and the calibration metric has to know which errors the model actually cares about.

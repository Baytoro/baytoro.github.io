GDAS: Graph Differentiable Architecture Search

H.J. Chen
  2021-04-27 2021-04-27 Created  
  • Work hard 
  • >
  • PaperReading 
 
  • NAS 

Dong X, Yang Y. Searching for A Robust Neural Architecture in Four GPU Hours. CVPR 2019.

Paper / Code

GDAS is a differentiable NAS method that sits between DARTS and stochastic NAS. It keeps the NASNet/DARTS-style cell search space, but changes the search-time computation: instead of evaluating every candidate operation on an edge and mixing their outputs, GDAS samples one operation per edge and trains that sampled subgraph.

That makes the searched network closer to the final discrete architecture. It also reduces compute and memory, because one training step does not need to execute all candidate operations.

Motivation

DARTS made cell search cheap by relaxing each edge into a soft mixture of operations. The weak point is that the relaxed supernet is not the final model. During search, all operations on an edge are active; after discretization, only one operation remains. This can create a gap between search-time optimization and final architecture quality.

GDAS attacks that gap directly:

The search space is still a directed acyclic graph. Each node aggregates transformed features from previous nodes. The difference is that GDAS samples a subgraph in every iteration: on each edge, only one candidate operation is active in the forward pass.

This has two intended benefits:

  1. The search-time model is closer to the final discrete cell.
  2. The search step is cheaper because only sampled operations are computed.

The paper’s headline is the CIFAR-10 search cost: less than four hours on one V100 GPU for the fixed-reduction-cell variant, reported as 0.17 GPU days.

Search Space

GDAS follows the micro-search setup: search for a cell, then stack copies of that cell to build the final network.

For CNN search, a cell is a DAG with ordered nodes. The candidate function set contains 8 choices:

  • identity,
  • zeroize,
  • 3x3 depthwise separable convolution,
  • 3x3 dilated depthwise separable convolution,
  • 5x5 depthwise separable convolution,
  • 5x5 dilated depthwise separable convolution,
  • 3x3 average pooling,
  • 3x3 max pooling.

The searched cell can be reused in CIFAR-style and ImageNet-style networks. CIFAR uses a simple 3x3 convolution head, then stacks blocks of normal cells with reduction cells between blocks. ImageNet uses a stronger three-layer convolutional stem before the same block idea.

$$
\tilde{h}{i,j}^{k} =
\frac{
\exp((\log p{i,j}^{k} + o_k) / \tau)
}{
\sum_{r=1}^{K}
\exp((\log p_{i,j}^{r} + o_r) / \tau)
}.
$$

The temperature controls discreteness. When , the relaxed sample approaches one-hot. When is large, the distribution becomes smoother. In the CNN search setup, the paper initializes at 10 and linearly reduces it to 0.1.

The implementation trick is the key: use the argmax sample in the forward pass, but use the relaxed softmax value in the backward pass. In the paper’s words, this avoids evaluating all candidate functions and reduces memory roughly by the size of the candidate set.

Training Loop

GDAS uses the usual train/validation split for weight-sharing NAS. Network weights are updated on training data, and architecture parameters are updated on validation data.

The practical loop is:

  1. sample a batch from the training split;
  2. sample an architecture from the current distribution;
  3. update operation weights using training loss;
  4. sample a batch from the validation split;
  5. update architecture logits using validation loss;
  6. derive the final discrete architecture from and train it normally.

This is close to DARTS’ bilevel motivation, but the search-time computation is different. DARTS trains a soft multi-path graph. GDAS trains one sampled path per edge per iteration.

Reduction Cell Choice

One surprising part of GDAS is that the paper does not insist on searching everything. It argues that most reduction cells are simple and similar, so jointly searching a normal cell and a reduction cell enlarges the search space without much payoff.

The fixed reduction cell uses simple convolution, max pooling, concatenation, and stride-based downsampling. The ablation later supports this design choice: the fixed reduction cell variant is both smaller and slightly better on CIFAR-10.

CIFAR Results

The main CIFAR comparison is Table 1:

The compact GDAS rows:

Model Search cost Params CIFAR-10 error CIFAR-100 error
GDAS 0.21 GPU days 3.4M 3.87 19.68
GDAS + CutOut 0.21 GPU days 3.4M 2.93 18.38
GDAS (FRC) 0.17 GPU days 2.5M 3.75 19.09
GDAS (FRC) + CutOut 0.17 GPU days 2.5M 2.82 18.13

FRC means the reduction cell is fixed and GDAS only searches the normal cell. The best CIFAR-10 row reaches 2.82% error with 2.5M parameters and 0.17 GPU days of search. That matches DARTS second-order + CutOut on CIFAR-10 error in this table, while using a much lower reported search cost and fewer parameters.

There are two caveats:

  • The search costs are not normalized across GPU types. The paper explicitly says a Titan 1080Ti run would be about seven GPU hours instead of less than four V100 hours.
  • CIFAR-100 is not the strongest row. DARTS second-order has 17.54% in the table, while GDAS (FRC) + CutOut has 18.13%.

The result is still strong for the paper’s claim: sampled differentiable search can find a competitive CNN cell quickly.

ImageNet Transfer

The CIFAR-searched cell transfers to ImageNet mobile setting:

The important rows:

Model Search cost Params Multiply-adds Top-1 error Top-5 error
DARTS second-order 1 GPU day 4.9M 595M 26.9 9.0
GDAS 0.21 GPU days 5.3M 581M 26.0 8.5
GDAS (FRC) 0.17 GPU days 4.4M 497M 27.5 9.1

The full GDAS row is better than DARTS second-order on ImageNet top-1/top-5 in this table. The FRC row is smaller and cheaper but loses accuracy. This is a useful tradeoff: fixing the reduction cell helps CIFAR search efficiency and parameter count, but the searched reduction cell still seems useful for ImageNet transfer.

RNN Results

GDAS also searches recurrent cells on PTB and transfers to WikiText-2.

On PTB, GDAS reports 57.5 test perplexity with 23M parameters and 0.4 GPU days of search. DARTS second-order is better in the table, with 55.7 test perplexity and 0.25 GPU days. GDAS is still close to DARTS first-order and ENAS.

On WikiText-2, GDAS reports 69.4 test perplexity, slightly better than DARTS second-order at 69.6 and ENAS at 70.4. The language-modeling section is not the main reason I would cite GDAS, but it shows the differentiable sampler is not limited to CNN cells.

What Did It Find?

The final discovered cells are more complex than what I would want to design by hand:

The normal cell uses many skip connections and separable convolutions. The FRC normal cell is even more skip-heavy. The recurrent cell uses tanh, relu, and identity paths. This figure is also a reminder that cell search spaces are highly constrained: NAS is not inventing arbitrary networks, it is choosing edges and operations inside a hand-designed grammar.

The reduction-cell ablation is worth keeping:

Combination Params CIFAR-10 error
GDAS-N + GDAS-R 3.3M 2.93
GDAS-N + FIX-R 3.0M 2.87
FRC-N + GDAS-R 2.9M 2.84
FRC-N + FIX-R 2.5M 2.82

The fixed reduction cell is not just a shortcut; in this ablation it improves the result. That supports the paper’s practical argument: searching the normal cell may be enough, and searching the reduction cell can add complexity without improving the final model.

Relation To DARTS And SNAS

DARTS, SNAS, and GDAS are attacking the same bottleneck from slightly different angles.

Method Search-time edge behavior Main concern
DARTS soft weighted sum of all candidate operations cheap gradients but larger relaxation gap
SNAS stochastic architecture variables with Concrete/Gumbel-Softmax relaxation optimize a distribution over architectures
GDAS one sampled operation per edge in forward pass, relaxed gradient in backward pass closer discrete subgraph and lower compute

The important GDAS idea is not only “use Gumbel-Softmax”. It is the one-path forward computation. That is what makes the sampled search graph closer to the final architecture and avoids running all operations on every edge.

Limitations

  • The search space is still manually designed. GDAS searches inside a NASNet/DARTS-style cell grammar.
  • The method depends on the temperature schedule. Cooling too quickly can make the architecture distribution collapse early; cooling too slowly weakens the discrete signal.
  • The reported search cost is hardware-dependent. The paper gives V100 numbers and explicitly warns that costs are not normalized across GPUs.
  • Directly searching ImageNet with the same hyperparameters failed in their experiments, so the main CNN result still follows the CIFAR-search-then-transfer protocol.
  • The final discrete architecture is derived from learned probabilities using a selection heuristic, so the relaxation gap is reduced but not eliminated.

Takeaway

GDAS is best read as a correction to the DARTS relaxation. DARTS made NAS differentiable, but its search-time model executes a soft mixture that does not exist after discretization. GDAS keeps gradient-based optimization while training sampled subgraphs, so each step looks more like the final architecture.

For me, the reusable lesson is the forward/backward split: use a discrete one-path sample for computation, but use a differentiable relaxation for gradients. That idea shows up repeatedly in later efficient NAS work, especially when the supernet is too expensive or too biased if every candidate operation is active at once.

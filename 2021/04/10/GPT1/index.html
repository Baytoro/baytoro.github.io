Improving Language Understanding by Generative Pre-Training

Paper / Code

GPT-1 is small by modern LLM standards, but the paper is important because it makes the GPT recipe concrete: train a left-to-right Transformer language model on unlabeled text, reshape downstream tasks into token sequences, then fine-tune the same backbone with only a lightweight task head.

The paper is not about prompting yet. It still relies on supervised fine-tuning for each benchmark. The interesting part is that most of the modeling burden has already moved into one reusable decoder-only Transformer.

Motivation

Before GPT-1, pre-trained word vectors and contextual encoders were already useful, but a lot of NLP systems still had a task-specific architecture: one model for entailment, another for similarity, another for multiple choice QA. GPT-1 tries to remove that split. It asks whether a generative language model can become a general initialization for many natural language understanding tasks.

The bet is simple:

  • Unlabeled text is abundant, so the expensive part of representation learning should happen there.
  • A left-to-right language model is a dense self-supervised objective, because every token becomes a prediction target.
  • If downstream inputs can be converted into sequences, the same Transformer can be reused with minimal changes.

This is why the title says “generative pre-training” even though the benchmarks are mostly understanding tasks.

The Two-Stage Recipe

The training pipeline has two stages:

  1. Unsupervised pre-training on BooksCorpus with a standard next-token objective.
  2. Supervised fine-tuning on each target dataset with a task-specific input format and a linear prediction head.

The model is a 12-layer decoder-only Transformer with masked self-attention, 768-dimensional hidden states, 12 attention heads, and 3072-dimensional feed-forward layers. It uses a 40k BPE vocabulary and a context size of 512 tokens. These details look modest now, but they matter historically: the paper already has the core GPT shape, just at a smaller scale.

  • token embeddings plus positional embeddings,
  • a stack of causal Transformer blocks,
  • a vocabulary distribution at every position.

Input Transformations

Figure: GPT-1 converts different supervised tasks into token sequences that a decoder-only Transformer can process.

This figure is the paper’s interface design. Different NLP tasks have different structures, but GPT-1 reduces them to the same computation:

  • Classification: [start] text [extract]
  • Entailment: [start] premise [delim] hypothesis [extract]
  • Similarity: encode both possible orders, because the relation is symmetric.
  • Multiple choice: encode each candidate answer separately and score the candidates with a softmax.

The special tokens matter. [delim] tells the model where fields change, and [extract] marks the position whose hidden state will be used for prediction. This is an early version of the later “format the task as text” idea. GPT-1 still fine-tunes, but the task adapter is mostly a serialization scheme.

Datasets

Figure: The benchmark set covers natural language inference, question answering, similarity, and classification.

The dataset table is useful because it shows the intended scope. GPT-1 is not tuned for one benchmark family. It is evaluated on NLI datasets such as SNLI and MultiNLI, question answering datasets such as RACE, similarity/paraphrase datasets such as QQP and MRPC, and sentiment/classification datasets such as SST-2 and CoLA.

The important point is not that GPT-1 wins every row. The point is that the same pre-trained decoder backbone is reused across all rows with very small task-specific changes.

Results: NLI and QA

Figure: GPT-1 improves several natural language inference and question-answering benchmarks after generative pre-training.

The NLI results are where the method looks especially strong. Entailment tasks require the model to compare two text spans, and GPT-1 handles this by concatenating premise and hypothesis with a delimiter. That is not obviously enough; a decoder-only model reads left to right, so the hypothesis can attend to the premise, but the premise cannot attend back to the hypothesis.

The fact that this works is a useful lesson. For many transfer tasks, perfect architectural symmetry is less important than having a strong pre-trained text model and a stable input convention. The sequence format lets the final hidden state summarize both fields.

RACE is also interesting because it is a multiple choice reading comprehension dataset. GPT-1 scores each answer candidate independently, then normalizes over candidates. This is still supervised fine-tuning, but the candidate-scoring pattern is close to how later language models handle multiple-choice prompts.

Results: Similarity and Classification

Figure: GPT-1 also transfers to semantic similarity and single-sentence classification tasks.

The similarity setup is one of the more clever parts of the paper. For tasks like paraphrase detection, the relation between sentence A and sentence B should be symmetric. A left-to-right decoder is not symmetric by default, so GPT-1 runs both orders and combines the resulting representations before prediction.

This is a small engineering choice, but it shows the paper’s general approach: do not redesign the model unless necessary; reshape the input and output around the same decoder.

Analysis: Which Layers Transfer?

Figure: More transferred Transformer layers help downstream performance, and more LM pre-training updates improve normalized task scores.

The left plot asks how many pre-trained layers should be transferred. If only the embedding layer mattered, transferring deeper Transformer blocks would not help much. The paper shows the opposite: performance improves as more layers are transferred.

My interpretation is that the LM is not just learning word lookup tables. Middle and upper Transformer layers contain reusable composition behavior: entity tracking, phrase-level semantics, long-range dependency handling, and patterns that help compare text spans. This is why full-model fine-tuning became the standard recipe.

The right plot shows downstream task performance as pre-training continues. The trend is not yet a formal scaling law, but the direction is clear: more language-model pre-training improves multiple downstream tasks. GPT-2 and GPT-3 later turn this observation into a central scaling argument.

Ablations

Figure: The ablation table separates the effects of pre-training, auxiliary LM loss, and Transformer architecture.

The ablation table is the part I would check before trusting the paper’s story. Three lessons stand out:

  • Removing pre-training hurts badly. That confirms the result is not just a good supervised Transformer.
  • The auxiliary LM objective helps especially on larger datasets and NLI-style tasks. It is not magic, but it stabilizes fine-tuning.
  • Replacing the Transformer with an LSTM under the same framework is weaker. The gain is not only from the two-stage training recipe; the Transformer backbone matters.

The paper is careful here: it does not claim the auxiliary objective always helps. Smaller datasets can behave differently. That is a useful reminder that regularization interacts with data size.

What GPT-1 Did Not Solve

GPT-1 is still far from a modern instruction-following model.

It requires supervised fine-tuning for each task. It uses a 512-token context window. It does not show robust zero-shot or few-shot prompting. The pre-training data is BooksCorpus, not the broad web-scale mixture used later. It also has no RLHF, no instruction tuning, and no chat interface.

But those limitations make the contribution clearer. GPT-1 solved the transfer interface for decoder-only language models:

  • one generative pre-training objective,
  • one causal Transformer backbone,
  • task conversion through token formatting,
  • fine-tuning with a small prediction head.

Takeaway

GPT-1 is the bridge between pre-trained representations and the later GPT-style LLM interface. The formulas are simple, but they line up cleanly:

  • learns a general language model from raw text.
  • The Transformer equations define a reusable causal decoder.
  • adapts that decoder to labeled tasks.
  • keeps language modeling alive during fine-tuning.

The paper does not yet show that a language model can follow arbitrary prompts. It shows the earlier and necessary step: a generatively pre-trained decoder-only Transformer can be a general-purpose initialization for many NLP tasks.

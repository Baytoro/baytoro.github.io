HAWQ: Hessian-Aware Mixed Precision Quantization

H.J. Chen
  2021-04-23 2021-04-23 Created  
  • Paper Reading 
 
  • Quantization 
  • | Compression 

Paper: HAWQ: Hessian AWare Quantization of Neural Networks with Mixed-Precision

HAWQ is an early paper that made second-order information practical for mixed-precision neural network quantization. The problem is not simply “use 8 bits or 4 bits.” The problem is deciding which blocks deserve higher precision when the model is pushed into a small weight and activation budget.

The paper’s answer is to look at local loss curvature. If quantization perturbs a block in a sharp direction, the loss can increase quickly. If the same magnitude of perturbation lands in a flatter region, the model may tolerate it. HAWQ uses the top Hessian eigenvalue of each block as a sensitivity signal, then uses that signal for two decisions:

  1. which blocks should receive more or fewer bits;
  2. which blocks should be fine-tuned first after quantization.

This is a CNN-era paper, but the idea is still useful when reading AdaRound, BRECQ, GPTQ, SpQR, and other later quantization methods. They differ in scale and implementation, but they share the same intuition: rounding error should not be treated as equally harmful in every parameter direction.

Motivation

Figure cropped from the paper PDF: block-level Hessian spectra are highly non-uniform for ResNet20 and Inception-V3.

The first figure is the whole motivation. The top Hessian eigenvalue varies by orders of magnitude across blocks. This means a uniform precision rule is mathematically suspicious. Two blocks may have similar tensor shapes, but if one block has much larger local curvature, the same quantization error norm can cause much larger loss increase.

The paper frames this with a second-order Taylor approximation around a trained model:

Near convergence, the first-order gradient term is small. The Hessian term is what tells us whether a perturbation is cheap or expensive. For a block (i), a larger Hessian spectrum means a quantization perturbation in that block is more dangerous.

ResNet20 blocks respond differently when weights are perturbed along the dominant Hessian eigenvector.

The 1-D loss landscape makes the eigenvalue interpretation concrete. Blocks with larger top eigenvalues produce steeper curves. The 9th ResNet20 block, for example, is much more sensitive than the final block. This is why a depth-based rule such as “early layers need more bits” is too crude. HAWQ wants a measured sensitivity ranking.

That separation is important. The precision-ordering score asks, “Where should I spend bits?” The fine-tuning-order score asks, “After quantization, which block should be repaired first?”

Inception-V3 Curvature

Inception-V3 1-D loss landscapes show the same curvature imbalance at ImageNet scale.

The Inception-V3 plot supports the same claim on a larger model and dataset. Some blocks are steep in both directions around the optimum, while later blocks can be almost flat over the same perturbation interval.

This matters because mixed precision has a combinatorial search space. If there are (L) layers and several candidate bit-widths per layer, exhaustive search is not realistic. HAWQ does not solve a full discrete optimization problem. It reduces the search by computing a deterministic ordering from Hessian information, then assigning bits according to a target compression level.

That is both a strength and a limitation. It is much cheaper than AutoML-style search, but it only gives a relative ordering. It does not magically know the globally optimal bit configuration for every hardware target.

ResNet20 Results

ResNet20 on CIFAR-10: HAWQ keeps accuracy close to the baseline while using mixed precision and high activation compression.

Table I is the cleanest small-model result. The full-precision ResNet20 baseline is 92.37% accuracy. HAWQ reports 92.22% with mixed 2-bit weights and 4-bit activations, while reaching 13.11x weight compression and 8x activation compression.

The comparison with “Direct” is the key ablation in the table. Direct quantization uses the same general compression setting but does not use Hessian information. It drops to 90.34%. HAWQ recovers most of that gap.

Mobile-readable takeaway: the headline is not just that HAWQ beats uniform 2-bit or 3-bit baselines. The important comparison is HAWQ versus Direct under aggressive mixed precision. The Hessian ranking makes the same bit budget much less destructive.

ImageNet Results

Inception-V3 on ImageNet: HAWQ improves over direct mixed precision and keeps a much smaller model than the full-precision baseline.

For Inception-V3, the full-precision baseline is 77.45% top-1 with a 91.2 MB model. HAWQ reports 75.52% top-1, 12.04x weight compression, and a 7.57 MB model. Direct mixed precision under the same general setup drops to 69.76%, which shows how much the curvature-guided allocation matters.

The Inception result is useful because it is not a toy CIFAR-only case. The method still works when the model has more heterogeneous blocks and the dataset is ImageNet.

ResNet50 and SqueezeNext results: HAWQ is competitive with prior quantization and AutoML-style mixed-precision baselines.

The ResNet50 table compares HAWQ with Dorefa, PACT, LQ-Nets, Deep Compression, and HAQ. HAWQ reports 75.48% top-1 with a 7.96 MB model, compared with HAQ’s 75.30% at 9.22 MB. This is an interesting comparison because HAQ is hardware-aware and search-based, while HAWQ is sensitivity-based and deterministic.

For SqueezeNext, the paper shows two useful cases:

  • uniform 8-bit HAWQ gets 69.34% top-1, almost matching the 69.38% full-precision baseline;
  • mixed precision reaches a 1.09 MB model with 68.02% top-1, while Direct drops to 65.39%.

SqueezeNext is already compact, so the result is a stress test. HAWQ is not only compressing a redundant large model. It can also guide quantization when the architecture was designed to be small.

What Bit Allocation Looks Like

ResNet20 final block precision from the appendix: the first and last blocks stay higher precision, while many middle blocks use lower weight bits.

The appendix precision table makes the method more concrete. HAWQ does not assign one global bit-width. In ResNet20, some blocks use 6-bit or 8-bit weights, while several middle blocks use 2-bit or 3-bit weights. Activations are mostly 4-bit, with higher precision kept where needed.

This is the shape I expect from a useful mixed-precision method: it should produce a policy that can be inspected. If a paper only reports average bit-width, it hides the real deployment artifact.

Inception-V3 final block precision: larger later blocks can still receive low weight precision when the Hessian score allows it.

The Inception-V3 table is also a reminder that parameter size and sensitivity pull against each other. Some later blocks are large, so using high precision everywhere would be expensive. HAWQ’s (S_i = \lambda_i / n_i) score lets large, lower-sensitivity blocks absorb more compression while preserving bits for more sensitive regions.

Ablations

Reversing the Hessian-aware precision order hurts accuracy recovery under the same fine-tuning budget.

Figure 4 tests whether the precision ordering matters. HAWQ’s normal ordering recovers quickly and stabilizes around a much higher top-1 accuracy than the reverse-precision variant. This supports the first use of Hessian information: do not assign the low bits to blocks that the Hessian says are sensitive.

Reversing the block-wise fine-tuning order converges more slowly and to a worse final point.

Figure 5 tests the second use of Hessian information: fine-tuning order. The normal HAWQ order, based on (\Omega_i), converges faster and reaches higher top-1 accuracy than reverse tuning.

This part is easy to miss. HAWQ is not only a bit-allocation paper. It also says the sequence of local repair matters. If a heavily damaged high-curvature block is left unfixed, later fine-tuning may be less useful because the model is already operating through a bad internal representation.

Relation To HAQ

HAQ and HAWQ both produce mixed precision, but they answer different questions:

Method Main signal What it optimizes
HAQ hardware feedback plus validation reward device-specific latency, energy, or size constraints
HAWQ Hessian sensitivity and quantization perturbation loss-aware precision and fine-tuning order

HAQ is deployment-aware. HAWQ is curvature-aware. In practice, these are complementary. A good quantization system needs to know both where the model is sensitive and where the hardware actually benefits from lower precision.

For example, a block may be safe to quantize according to HAWQ but still not speed up on a target device if the kernel does not efficiently support that bit-width. Conversely, a hardware search may find a fast policy that damages accuracy if it ignores sensitivity. Modern systems often need both signals.

Relation To Later PTQ

HAWQ is useful background for several later methods:

  • AdaRound optimizes rounding decisions after the quantization grid is fixed. Its motivation also comes from a Hessian-weighted perturbation objective.
  • BRECQ moves from layer-wise reconstruction to block-wise reconstruction, using second-order or Fisher-style reasoning to preserve internal computation.
  • GPTQ scales second-order PTQ to very large Transformer weight matrices by using calibration activations and inverse-Hessian error compensation.
  • SpQR uses a Hessian view to identify sensitive weights that should become sparse high-precision outliers.

The granularity changes across these papers. HAWQ works at block-level mixed precision. AdaRound works at rounding decisions. GPTQ works inside linear layers. But the shared lesson is the same: quantization error should be weighted by how much the model cares about that direction.

Practical Reading Notes

If I were reproducing HAWQ or using it as a baseline, I would check the following:

  • Block definition. The Hessian score depends on how layers are grouped. A residual block, a convolution, and an Inception module can produce different sensitivity rankings.
  • Eigenvalue estimation cost. The paper avoids forming Hessians, but power iteration still requires Hessian-vector products and extra backpropagation.
  • Calibration and fine-tuning data. The method is not data-free. The Hessian and fine-tuning behavior depend on the examples used.
  • First and last layers. Many quantization papers treat them specially. Comparisons are only fair when this policy is stated.
  • Activation bit-width. HAWQ reports both weight and activation compression. Activation quantization can be harder than weight-only compression because it affects runtime tensors.
  • Kernel support. Mixed precision is only useful at deployment if the hardware/runtime can execute the chosen bit-widths efficiently.

Limitations

HAWQ’s main approximation is aggressive: each block’s Hessian is represented by its top eigenvalue, and sometimes scaled by block size. That captures the sharpest local direction, but it does not model the full spectrum or cross-block interactions.

The method also gives a relative ordering, not an exact bit-width solution. A user still needs a target compression ratio and a policy for mapping ranked blocks to concrete bit choices.

Finally, the paper is evaluated on CNN image classification. The idea transfers to modern transformer quantization, but the details do not transfer directly. Transformers have activation outliers, attention/KV-cache behavior, layer normalization, and much larger matrix structure. That is why later methods such as GPTQ and SmoothQuant look different even when they share the second-order motivation.

Takeaway

HAWQ should be remembered for making mixed precision less heuristic. It asks the right question: if two blocks receive the same quantization error, will the loss care equally? The answer is no, and the Hessian gives a usable way to estimate that difference.

The paper is not the final word on quantization. It does not solve hardware mapping, it approximates curvature heavily, and it targets CNNs. But it is an important bridge between simple uniform quantization and later reconstruction-based PTQ methods. It turns bit allocation into a sensitivity problem instead of a layer-count or parameter-count rule.

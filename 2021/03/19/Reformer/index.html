Reformer: The Efficient Transformer

  2021-03-19 2021-03-19 Created

Reference

  • Paper: Reformer: The Efficient Transformer
  • Code: google/trax Reformer

Reformer is one of the early long-context Transformer papers that is still useful to read carefully. It does not only say “attention is quadratic” and then replace attention with a sparse pattern. It separates the memory problem into several pieces:

  • attention scores scale as in sequence length;
  • activations have to be kept for every layer during training;
  • the feed-forward hidden dimension is often much larger than ;
  • long sequences make even “linear-looking” activation tensors enormous.

The paper’s answer is three-part:

  • use locality-sensitive hashing attention to avoid comparing every query with every key;
  • use reversible residual layers so intermediate activations can be reconstructed during backpropagation;
  • chunk feed-forward and output computations so large intermediate tensors do not have to be materialized at once.

This post is mainly a formula-by-formula reading. I care less about memorizing the exact Reformer implementation and more about understanding which tensor causes which cost.

One Sentence

Reformer is a Transformer variant for long sequences: LSH attention attacks the attention matrix, reversible layers attack the per-layer activation cache, and chunking attacks the large feed-forward intermediates.

This is a different route from FlashAttention. Reformer changes the attention pattern and therefore gives an approximate attention mechanism. FlashAttention keeps exact dense attention but changes the kernel schedule and memory traffic. That distinction matters when deciding whether a method is an algorithmic approximation or an implementation-level optimization.

The value projection remains separate. The reason is practical. Locality-sensitive hashing puts vectors into buckets. If query vectors and key vectors were produced by unrelated projections, “same bucket” would be less meaningful. With shared , a query and a key are comparable as points in one space.

The paper also normalizes key vectors and prevents a token from attending to itself except when it has no other valid context. This self-attention rule is easy to miss. In shared , a token’s dot product with itself is almost always very high, so without masking it can waste attention mass on copying itself.

Why this helps:

  • similar vectors tend to have similar projections;
  • after normalization, angular closeness corresponds to large dot product;
  • nearby vectors are likely to share at least one hash bucket;
  • vectors in different buckets are not compared, which saves attention work.

The hash is approximate. If two tokens should attend to each other but land in different buckets for a given hash round, that pair is missing. Reformer compensates by using multiple hashing rounds.

This is why Reformer is not just “group by hash and run tiny attentions”. It is a sorted dense batching trick around the hash grouping.

Synthetic Duplication Task

The task is deliberately simple: duplicate a sequence. A model has to retrieve information from far away, so local attention is not enough. This is a good sanity check for LSH attention because the method claims to preserve important non-local links through content similarity, not through fixed distance.

The table has two useful lessons:

  • A full-attention model evaluated with LSH loses accuracy as hashes decrease. This means the LSH approximation is real, not free.
  • Models trained with LSH attention become robust to LSH evaluation. A model trained with LSH-4 gets almost perfect accuracy when evaluated with LSH-4 or more hashes.

The most interesting row is not the full-attention row. It is the LSH-trained rows. They show that if the model learns under the approximate attention mechanism, it can adapt its representations so relevant tokens collide more reliably.

Experiments: Shared QK And Reversibility

Figure: Figure 3 compares shared query-key space and reversible layers on enwik8 and imagenet64.

This figure checks two risks:

  • Does sharing query and key projections hurt quality?
  • Does making the Transformer reversible hurt quality?

The plots say mostly no. Shared QK performs similarly to separate Q and K. Reversible layers also track the regular Transformer closely. This matters because both are structural changes. If either one caused a large accuracy drop, the memory savings would be less convincing.

One small detail I like: the paper tests these changes before combining them with LSH attention. That keeps the ablation clean. Shared QK and reversibility are not justified only by final Reformer performance; each component is separately checked.

The reversible Transformer reaches BLEU scores in the same range as the Vaswani et al. baselines. The big reversible model gets 29.1 BLEU in the paper’s table. My takeaway is that reversibility is not only a trick for character-level long-context tasks; it can be applied to regular sequence-to-sequence models without obviously destroying translation quality.

Experiments: Depth And Speed

Figure: Figure 5 compares depth scaling on enwik8 and attention speed as sequence length grows.

The left plot shows that deeper Reformers improve enwik8 performance up to around the tested 12-20 layer range. This is important because memory-efficient models sometimes save memory by becoming too constrained. Here the model can still benefit from depth.

The right plot is the speed argument. Full attention slows down as sequence length increases. LSH attention stays much flatter because it does not compare every pair. The plot keeps total token count fixed and varies sequence length versus batch size, so it isolates the attention-length effect.

This is one of the clearest figures in the paper: Reformer is not merely fitting into memory by recomputation. LSH attention changes the runtime trend with length.

What I Would Check In An Implementation

If I were implementing or debugging Reformer, I would focus on these failure points:

  • Hashing must be deterministic enough within a forward pass, but independent across hash rounds.
  • Shared QK self-attention needs the self-mask; otherwise tokens over-attend to themselves.
  • Sorting and unsorting must preserve token order for residual paths and output alignment.
  • Chunk boundaries need one chunk of overlap or look-back, otherwise same-bucket tokens split across chunks are lost.
  • Multi-round duplicates need careful handling; the same key can be found by more than one hash.
  • Reversible layers save activation memory only if the implementation actually avoids caching intermediate activations.
  • Chunked feed-forward is a scheduling optimization; it should not change numerical results except for small floating-point order differences.

These are the places where the paper’s math turns into engineering risk.

Limitations

Reformer is elegant, but it is not a universal replacement for dense attention.

First, LSH attention is approximate. The model may miss relevant pairs if they do not collide in a hash bucket. Multiple hash rounds reduce the risk but increase cost.

Second, the implementation is more complicated than dense attention. Hashing, sorting, chunking, duplicate removal, causal masking, and reversible recomputation all interact.

Third, later long-context methods took different paths. Some methods use fixed sparse patterns, some use retrieval, some use state-space or recurrent structure, and FlashAttention-style kernels preserve dense exact attention while improving memory traffic. Reformer is best understood as one important branch of the design space, not the final answer.

Takeaway

The part I want to remember is the decomposition:

  • causes the attention bottleneck.
  • LSH attention replaces all-pairs comparison with content-based bucketed comparison.
  • Multiple hash rounds trade compute for neighbor recall.
  • Reversible layers remove the need to store every layer’s activation.
  • Chunking keeps feed-forward and output intermediates from exploding.

The paper is valuable because each formula points to a concrete tensor. It does not just say “efficient Transformer”; it says which memory term is being removed, which approximation is being introduced, and which engineering schedule makes the method practical.

PC-DARTS: Partial Channel Connections for Memory-Efficient Architecture Search

H.J. Chen
  2021-01-23 2021-01-23 Created  
  • Paper Reading 
 
  • NAS 

Xu Y, Xie L, Zhang X, et al. PC-DARTS: Partial Channel Connections for Memory-Efficient Architecture Search. ICLR 2020.

  • Paper: https://arxiv.org/pdf/1907.05737.pdf
  • Code: https://github.com/yuhuixu1993/PC-DARTS

PC-DARTS is one of the most practical follow-ups to DARTS. The paper does not replace the differentiable NAS formulation. Instead, it attacks the part that makes DARTS awkward to scale: every candidate operation on every edge is kept alive during search, so the supernet has to store and backpropagate through many operation outputs that will mostly be discarded when the final discrete cell is derived.

The key idea is deliberately simple. On each edge, PC-DARTS sends only a fraction of the input channels through the expensive mixed operation and lets the remaining channels bypass that operation. This reduces search memory and computation roughly in proportion to the channel sampling factor. Since partial-channel sampling can make the edge ranking noisy, the paper adds edge normalization parameters to learn which incoming edges should dominate each node.

The result is a DARTS-family method that is much easier to run: 0.1 GPU-days on CIFAR10 and 3.8 GPU-days for direct ImageNet search in the reported experiments, while keeping competitive final accuracy.

Motivation

DARTS makes neural architecture search differentiable by relaxing a discrete operation choice into a weighted mixture. That relaxation is elegant, but its implementation is expensive. Suppose an edge has 8 candidate operations and an activation tensor with channels. During search, the supernet has to evaluate those 8 operations on the full -channel tensor and keep their intermediate activations for gradient computation. This is much heavier than training the final architecture, where each edge keeps only one operation.

This creates two practical problems:

  1. The search batch size is small because the supernet is memory-heavy.
  2. The over-parameterized supernet can overfit its own search dynamics, especially by preferring cheap or weight-free operations such as skip-connect.

PC-DARTS treats these two problems as coupled. If only channels are used for the operation mixture, the search stage can use a batch size about times larger. At the same time, the sampled-channel path acts as a regularizer because each operation is trained and evaluated through a partial view of the feature tensor instead of a full deterministic input.

The important caveat is that partial evaluation changes the signal used to rank edges. The paper therefore adds edge normalization so that the final topology decision does not depend only on the operation weights inside an edge.

Partial Channel Connection

The main operation-level change is partial channel connection. Instead of applying the mixed operation to the full tensor , PC-DARTS samples a channel mask and applies candidate operations only to . The unselected channels bypass the operation mixture and are concatenated or added back into the edge output.

There is also an implementation detail that matters. The conceptual formula samples channels, but the practical implementation does not need to randomly sample a different subset every time an operation is called. The paper uses the first channels for the operation mixture and then shuffles the output channels before the next computation, similar to ShuffleNet. This avoids costly dynamic indexing and makes the partial-channel path GPU-friendly.

Edge Normalization

Partial-channel search makes operation evaluation cheaper, but it introduces a new source of uncertainty. If each edge is evaluated through only part of the feature tensor, the relative strength of incoming edges may become noisier. DARTS already has a known instability problem where the relaxed supernet and the final discrete cell do not always agree. PC-DARTS tries to prevent partial-channel sampling from making that gap worse.

PC-DARTS learns both the within-edge operation distribution and the across-edge topology distribution, then multiplies them when deriving the final cell.

Results On CIFAR10

The CIFAR10 result is the headline demonstration that PC-DARTS keeps DARTS-level quality while reducing search cost.

CIFAR10 comparison. PC-DARTS reports 2.57 +/- 0.07% test error with 0.1 GPU-days search cost on a GTX 1080Ti.

The compact view:

Method CIFAR10 test error Params Search cost
DARTS first order + cutout 3.00 +/- 0.14% 3.3M 0.4 GPU-days
DARTS second order + cutout 2.76 +/- 0.09% 3.3M 1 GPU-day
P-DARTS + cutout 2.50% 3.4M 0.3 GPU-days
PC-DARTS + cutout 2.57 +/- 0.07% 3.6M 0.1 GPU-days

The important comparison is not only the final error. DARTS second order is already strong, but PC-DARTS reaches a better reported error while using one tenth of the listed search cost. The paper also notes that the 0.1 GPU-day number was measured on a single GTX 1080Ti and can be shortened to 0.06 GPU-days on a Tesla V100.

Ablation: Channel Sampling Rate

The channel sampling rate is controlled by . A larger means fewer channels go through the mixed operation, so search is cheaper but the operation-quality estimate is noisier.

The pattern is exactly what I would expect:

  • uses the full tensor and is expensive.
  • reduces cost and improves the final error.
  • gives the best tradeoff in the reported CIFAR10 setting.
  • is cheaper, but the final test error becomes much worse.

This is a good sign that partial channel connection is not just a hardware trick. Moderate sampling regularizes the supernet; too much sampling throws away too much information.

This ablation is probably the most convincing part of the paper. Partial channel connection is responsible for the big search-cost reduction, but it also improves accuracy. Edge normalization has almost no extra computation, but it consistently improves the final architecture. The combination is better than either piece alone.

Stability

DARTS-family methods are sensitive to seeds, search epochs, and search-space size. PC-DARTS evaluates this explicitly.

Stability comparison across independent runs, search epochs, and number of nodes.

Across five independent search runs, the reported standard deviations are:

Method Five-run behavior
DARTS-v1 +/- 0.15%
DARTS-v2 +/- 0.21%
PC-DARTS +/- 0.07%

The table also varies the number of search epochs and the number of nodes in the cell. PC-DARTS is not perfectly invariant, but it is visibly less erratic than the DARTS variants. This supports the paper’s interpretation that partial channel sampling works as a regularizer and edge normalization reduces the instability caused by sampling.

My reading is slightly more cautious: the stability result is strong within this DARTS search space, but it does not prove that the partial-channel estimator will rank operations well in every search space. If operations have very different cross-channel behavior, the subset may be a biased estimator. Still, for convolutional DARTS cells, the evidence is solid.

What PC-DARTS Actually Fixes

I see PC-DARTS as fixing three practical weaknesses of vanilla DARTS:

  1. Full-channel mixed operations make search memory-heavy.
  2. Small search batch sizes make the supernet optimization noisy.
  3. Operation softmax alone is not enough to rank incoming edges robustly.

Partial channel connection addresses the first two issues. Edge normalization addresses the third. The paper is effective because these changes are small and local. They do not require a new controller, a new reward, a new surrogate benchmark, or a complicated progressive search schedule.

The method also exposes a useful NAS lesson: the search supernet should not be optimized too well in a way that is disconnected from the final discrete architecture. PC-DARTS deliberately weakens each operation’s search-time view of the input tensor. That sounds like losing information, but the ablation suggests it can reduce overfitting to the supernet.

Limitations

There are still limitations worth keeping in mind.

  • Partial-channel evaluation is an estimator. It can misrank operations if the sampled channels are not representative.
  • The best is task-dependent. CIFAR10 uses , while ImageNet uses .
  • The final cell extraction rule is still heuristic, just like DARTS.
  • The method remains tied to a DARTS-style cell search space.
  • The reported stability is much better than DARTS, but the paper still evaluates a limited family of convolutional spaces.

I would not treat PC-DARTS as a universal NAS solution. I would treat it as a very strong engineering improvement to differentiable cell search.

My main note after reading the paper: PC-DARTS is valuable because it improves the estimator used during search, not the final architecture class. The final network is still an ordinary DARTS-style cell. The difference is that the search process is cheaper, uses larger batches, and is less likely to overfit the full supernet. That is exactly the kind of detail that decides whether a NAS method is merely elegant or actually usable.

Language Models are Unsupervised Multitask Learners

H.J. Chen
  2021-07-20 2021-07-20 Created  
  • Paper Reading 
 
  • LLM 
  • | AIGC 
  • | Transformer 

Paper / Code

GPT-2 is the paper where the GPT line stops looking like only “pre-train then fine-tune” and starts looking like a general text interface. The model is still a decoder-only Transformer trained with next-token prediction. The important change is how the paper treats downstream tasks: instead of adding a supervised head for every dataset, it asks whether the language model can infer the task from natural language context.

The answer is mixed but important. GPT-2 is not a reliable instruction follower, but it shows that scaling a generic language model on broad web text produces measurable zero-shot transfer across many tasks.

From Fine-Tuning to Zero-Shot Transfer

GPT-1 used supervised fine-tuning. GPT-2 tries to remove that dependency. The central idea is that many tasks already appear in text as demonstrations:

  • translation pairs,
  • question-answer formats,
  • article-summary patterns,
  • cloze questions,
  • multiple-choice patterns,
  • natural language instructions.

If a language model learns these formats during next-token prediction, then at test time the task can be specified as text rather than as a new output head.

Figure: Zero-shot task performance generally improves as GPT-2 scales from 117M to 1.5B parameters.

This figure is the paper’s main claim in one picture. The curves are noisy, and some tasks remain weak, but the trend is hard to ignore: larger WebText language models become better zero-shot task solvers. The paper is not claiming that zero-shot is always competitive with supervised SOTA. It is showing that task transfer emerges from the language-modeling objective itself.

In a supervised system, the task is often implicit in the architecture or the dataset. In GPT-2, the task is another part of the sequence. For example, “translate English to French” and a few translation-like examples can all be represented as text. The same next-token objective can learn to continue that pattern.

My reading:

  • The language model objective is unchanged.
  • The training distribution is widened so it contains many naturally occurring task demonstrations.
  • The model has to infer the latent task from context because that helps next-token prediction.
  • Zero-shot transfer is therefore not a new objective. It is a consequence of modeling a broad enough text distribution with enough capacity.

For evaluation, perplexity is still the basic language-model metric:

Lower perplexity means the model assigns higher probability to the observed tokens. The paper repeatedly uses perplexity to check whether scaling is still improving the base language model, not only downstream tasks.

WebText

GPT-2 builds WebText from outbound Reddit links that received enough user approval. The point is not that Reddit itself is the corpus; Reddit is used as a filter for linked web pages. The preliminary dataset contains over 8 million documents and about 40GB of text, with Wikipedia removed to reduce overlap with common benchmarks.

Figure: WebText contains naturally occurring task-like patterns, including translation examples.

This table is a good reminder that “unsupervised multitask learning” does not mean tasks are absent. It means task supervision is not manually labeled into separate datasets. The web contains many semi-structured examples. A sufficiently large LM can treat those examples as part of its language distribution.

This also explains why data quality matters. If the corpus contains clean examples of a task format, zero-shot transfer becomes easier. If a task format is rare, noisy, or adversarial, the model has less to imitate.

Input Representation: Byte-Level BPE

GPT-2 uses byte-level BPE. This is a practical compromise between character-level and word-level modeling.

Word-level tokenization is efficient but has out-of-vocabulary problems. Pure byte-level modeling can represent any string, but long byte sequences make optimization harder. Byte-level BPE starts from bytes and merges frequent byte sequences, so it can represent arbitrary Unicode text without an unknown-token failure mode.

The paper also discusses preventing bad BPE merges across character categories, with an exception for spaces. This sounds like a tokenizer detail, but it matters because GPT-2 is evaluated on many datasets with different preprocessing conventions. A robust tokenizer reduces the need for dataset-specific text cleaning.

Architecture and Scale

Figure: GPT-2 evaluates four model sizes from 117M to 1542M parameters.

GPT-2 is architecturally close to GPT-1: a decoder-only Transformer trained left to right. The changes are mostly scale and engineering:

  • Model sizes: 117M, 345M, 762M, and 1542M parameters.
  • Layers: 12, 24, 36, and 48.
  • Hidden sizes: 768, 1024, 1280, and 1600.
  • Context length: 1024 tokens.
  • Vocabulary size: 50,257 byte-level BPE tokens.
  • LayerNorm is moved to the input of each sub-block, similar to pre-activation residual networks.
  • An extra LayerNorm is added after the final self-attention block.
  • Residual weights are initialized with a factor of , where is the number of residual layers.

The scaling is worth pausing on. In a deep residual network, activations accumulate across many residual branches. If each branch starts too large, the sum can become unstable. Scaling by keeps the residual stream better behaved at initialization as depth grows.

GPT-2 therefore did not need a new conceptual architecture. It needed a larger and more stable version of the GPT-1 decoder.

Zero-Shot Language Modeling Results

Figure: GPT-2 achieves strong zero-shot results on several language-modeling datasets, while still failing badly on some domain-specific settings.

Table 3 is a useful sanity check. GPT-2 improves on 7 of 8 tested language-modeling datasets in the zero-shot setting. LAMBADA is the most striking row: the largest model greatly lowers perplexity and raises accuracy, showing better long-range dependency modeling.

The weak 1 Billion Word Benchmark result is also informative. That dataset uses sentence-level shuffling, so it removes the kind of long document context that GPT-2 is designed to use. The failure is not just “model too small”; it is a mismatch between evaluation format and training distribution.

Cloze and Commonsense Scaling

Figure: Children’s Book Test performance improves with scale.

CBT is a cloze-style benchmark. The model has to choose a missing word from candidates. The scale trend here supports the same pattern as Figure 1: a larger generic LM becomes better at a task without adding a task head.

Figure: Winograd Schema performance also improves as the WebText LM becomes larger.

Winograd-style tasks test pronoun resolution and commonsense. GPT-2 does not solve the problem in a robust way, but the scaling trend matters. It suggests that some commonsense-like behavior can be learned as statistical regularity in text, even without explicit symbolic supervision.

Summarization

Figure: GPT-2 can imitate summarization format, but ROUGE scores remain far behind supervised systems.

Summarization is one of the clearest “capability but not reliability” results. GPT-2 often recognizes that a prompt is asking for a summary. It can produce text with the right shape. But the measured ROUGE scores are weak compared with supervised systems.

My interpretation is that GPT-2 learned the genre of summarization before it learned robust content selection. It can generate plausible summary-like text, but it does not consistently preserve the exact information needed for benchmark scoring.

This is a pattern that continues in later LLMs: format imitation appears earlier than faithful task execution.

Data Overlap and Memorization

Figure: GPT-2 measures 8-gram overlap between evaluation datasets and training data.

The overlap analysis is one of the more responsible parts of the paper. A web-scale corpus can accidentally include benchmark examples. If a model performs well because it memorized test items, then the zero-shot claim is weaker.

The authors build Bloom filters over WebText token 8-grams and compare overlap rates. The result is nuanced:

  • Some benchmark test sets overlap with WebText.
  • Many benchmarks also overlap with their own training sets.
  • Removing LAMBADA examples with overlap changes the score only slightly.
  • The issue is real enough to measure, but it does not explain all GPT-2 gains.

This section also anticipates a much bigger problem for GPT-3 and later models. As pre-training corpora get larger, contamination is no longer a corner case; it becomes a standard evaluation concern.

Is GPT-2 Still Underfitting?

Figure: WebText train and test perplexity both improve with model size.

This figure is easy to overlook, but it is central to the scaling story. Both train and test perplexity decrease as model size increases. The test curve does not show the model overfitting WebText and getting worse. Instead, the largest model still appears underfit.

That means the paper has a clear next step: make the model bigger and train it with more compute. GPT-3 is almost the direct continuation of this plot.

Qualitative Generation

Figure: GPT-2 generations can preserve the requested format but still drift in factual content and task faithfulness.

The qualitative examples are useful because benchmark numbers do not fully describe the model. GPT-2 can write coherent paragraphs and maintain local style. It can also hallucinate, drift, repeat, and confidently produce unsupported details.

That distinction matters:

  • Coherence is not the same as factuality.
  • Recognizing a task format is not the same as following the user’s intent.
  • Good next-token prediction can produce impressive samples without guaranteeing controllability.

This is why later work moves toward instruction tuning and RLHF. GPT-2 proves that the base LM has broad latent capabilities, but it does not make those capabilities easy to steer.

What GPT-2 Contributes

The paper’s contribution is not a single new layer or loss function. It is a shift in how to view language modeling.

GPT-1 says: pre-train a decoder and fine-tune it for tasks.

GPT-2 says: if the pre-training distribution is broad enough, task behavior can be expressed and invoked as text.

The technical ingredients are ordinary but aligned:

  • a causal Transformer,
  • byte-level BPE,
  • a larger context window,
  • WebText as a broad training distribution,
  • larger model capacity,
  • zero-shot evaluation through natural-language formatting.

Limitations

GPT-2 has several clear limitations.

First, zero-shot performance is inconsistent. Some benchmarks improve smoothly with scale; others remain weak or depend heavily on prompt phrasing.

Second, the model is not instruction-tuned. It continues text. If the continuation happens to match a task, it looks like task solving. If the context is ambiguous, the model has no explicit preference for being helpful, concise, or truthful.

Third, web text introduces evaluation and safety problems. It gives broad coverage, but it also carries bias, duplication, low-quality text, and possible benchmark contamination.

Fourth, the paper’s strongest evidence is trend-based. Individual scores can be unimpressive, but the trend with scale points toward a new regime.

Takeaway

GPT-2 is the turning point where the GPT series starts to treat language modeling as an interface for many tasks. The key formula is still next-token prediction, but the interpretation changes:

The model is not yet a dependable few-shot learner. It is not aligned. It is not a robust assistant. But it shows that many tasks can be induced by context without gradient updates. GPT-3 takes that observation and scales it until few-shot prompting becomes the headline.
